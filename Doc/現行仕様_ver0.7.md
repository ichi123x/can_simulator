# CAN バスシミュレータ 現行仕様（ver.0.7）

- 時点: ver.0.7（main のマージコミット `a2eca6c`、2026-10-05）
- 位置付け: いま動いているアプリの仕様を 1 冊にまとめたもの。
  - 元になった文書: 全体仕様 [CANバスシミュレータ仕様.md](CANバスシミュレータ仕様.md)（Draft v1.11）と、各機能の仕様 `specs/001〜029/spec.md`（改訂の節を含む）
  - 各項目の末尾の（001）などは、その仕様を決めた機能の番号
  - 食い違うときは、後の機能の仕様が優先する
- 全体仕様 v1.11 から変わった点は、第 11 章にまとめた。

---

## 1. 概要

| 項目 | 内容 |
|------|------|
| 目的 | 最大 16 ECU が 1 本の CAN バスにつながったネットワークを、ソフトウェアだけで模擬する。送信・調停・受信の時刻をログに残し、性能（待ち時間・レイテンシ・ジッター・バス負荷）を評価する |
| プロトコル | CAN 2.0A 標準フォーマット（11 ビット ID、データ 0〜8 バイト）のデータフレームのみ |
| 方式 | フレーム単位のイベント駆動シミュレーション（DES） |
| 模擬しないもの | 物理層（電圧・終端・伝搬遅延・ビットタイミング・クロック誤差）、拡張フォーマット（29 ビット ID）、CAN FD、リモートフレーム、オーバーロードフレーム、エラー（第 4.7 節） |
| 動作環境 | Windows（MFC のダイアログアプリ）。Win32 / x64 × Debug / Release の 4 構成でビルドできる |

## 2. 画面

### 2.1 メインウィンドウ

上から次の 5 つが並ぶ。

1. **タイトルバー**: 「CAN Bus Simulator　　　　プロジェクト名：<プロジェクトファイルのフルパス>」。プロジェクトファイルが無いときは「プロジェクト名：」で終わる（024）。最小化・最大化のボタンがある（026）。
2. **メニューバー**: 第 2.2 節。
3. **ツールバー**: 暗い帯（高さ 64 px、96 dpi）。左から次の順に並ぶ（014・015・017・019・023）。
   - 「保存」「読込み」のボタン
   - 「開始」「中断」「終了」のボタン
   - 「フレーム表示」のチェックボックス
   - シミュレーション時間（3 けた区切り + μs）
   - 「スピード：」と、スピードスライダー
4. **CAN バス構成図**: 白い背景に「CAN BUS」の横線と ECU の箱を描く（003）。
   - ECU の箱は、奇数の ECU がバスの上、偶数の ECU が下に並ぶ。0〜16 個。
   - 箱には「ECU nn」と、あれば ECUラベル名を描く。ラベル名は 10 文字までで、超えたら「...」（022）。
   - 構成図の 4 px 内側に、グレーの 1 px の枠がある（011）。
5. **イベント＆ログ表示**: 構成図の下の薄いグレーの領域で、スクロールバーと枠が付く（009・011・020）。

- 最大化・大きさの変更をしても、中身は左上の固定位置のままで、余りは白くなる（026）。
- 閉じるのは ✖ だけ。Enter・Esc では閉じない（004）。

### 2.2 メニュー

| メニュー | 項目 | 内容 |
|----------|------|------|
| ファイル(F) | プロジェクト読込み(O)... | `.canprj` を選んで読み込む（004・024） |
| | プロジェクト保存(S)... | 毎回、保存先を尋ねて保存する（004） |
| 編集(E) | セッティング(T)... | ECU 数・通信速度・シミュレーション時間（第 3.2 節） |
| | データフレーム編集(F)... | ECU ごとの送信フレーム一覧の編集（第 3.3 節） |
| シミュレーション(S) | 開始(R) / 中断(P) / 終了(X) | 第 5 章 |
| 解析(A) | 送信待ち時間(W)... / 受信完了時間(R)... / 送信ジッター(J)... / ─ / CAN バス負荷(B)... | 第 8 章（028・029） |
| ログ表示(L) | シミュレーションログ(L)... / ログクリア(C)... | 第 7.1 節・第 7.2 節（025・027） |

- 実行中・中断中は、「シミュレーション」以外の 4 つのメニューがグレーで、開けない（007・025）。

### 2.3 ツールバー

| 部品 | 動き |
|------|------|
| 保存 | プロジェクトファイルがあれば、尋ねずに上書きする。無ければ保存先を尋ねる。保存先が読み取り専用で失敗したときは、そのことを知らせる（023） |
| 読込み | メニューの「プロジェクト読込み」と同じ（023） |
| 開始・中断・終了 | メニューと同じ。押して、同じボタンの上で離すと実行する。有効／無効はメニューと共通（014） |
| フレーム表示 | 構成図の強調と流れのエフェクトを描くかどうか。いつでも切り替えられ、実行中もその場で反映する。プロジェクトに保存する。既定は ON（017・021） |
| シミュレーション時間 | 今の再生時刻を表示する。新しい実行で 0、自然終了・即時完了で終端、「終了」で止めた時刻（017） |
| スピードスライダー | -10〜+10 の 21 目盛り。いつでも操作できる。数字は 5 刻みと今の値だけを表示し、今の値は太字・黄色（015・019・026） |

- 保存・読込みは、実行中・中断中はグレーになる。データフレームの編集中でも使える（023）。

## 3. プロジェクトと設定

### 3.1 プロジェクトファイル（`.canprj`）

UTF-8 の `key=value` 形式で、`;` 以降はコメント。保存するとコメントは消える（004）。

```ini
[Project]
EcuCount=16          ; 0〜16（省略時 2）
DurationSec=5        ; 1〜600 秒（省略時 10）
FrameDisplay=1       ; 0 / 1（省略時 1 = ON。021）
Speed=-3             ; -10〜+10（省略時 0。以前の -13〜-11 は -10 として読む。026）

[Network]
BitRateBps=500000    ; 125000 / 250000 / 500000 / 1000000（省略時 500000）

[Node1]
NodeId=1             ; 1〜16、一意
Name=ECM Engine Control Module   ; 起動記録の CSV に出る名前
Label=エンジン                    ; 構成図の ECUラベル名（32 文字まで、空なら書かない。022）
RxFilter=0x0A8,0x0E0 ; 受信する CAN ID（省略時は全 ID を受信）
ReceiveDelayUs=0     ; 受信処理遅延 µs（省略時 0）
PowerOnTimeUs=0      ; 電源投入時刻 µs（省略時 0）
InitDurationUs=0     ; 初期化時間 µs（省略時 0）

[Node1.Frame1]
Name=EngineRPM       ; フレーム名（32 文字まで。006）
CanId=0x0C0          ; 0x000〜0x7FF、全ノードで一意
Dlc=8                ; 0〜8
PeriodUs=10000       ; 送信周期 µs（1 ms〜3,600,000 ms）
InitialOffsetUs=5000 ; 初回オフセット µs（0 以上、周期未満）
```

- データは常に DLC 分の 0xFF で、`Data=` は読まない・書かない（006）。
- 1 ノード最大 100 フレーム（006）。
- 規則に合わないファイルは読み込まず、ファイル名・キー・理由を示す。読込みに失敗しても、今のプロジェクトは変わらない（004）。
- 実行に使うのは、ECU 番号 1〜`EcuCount` のノードだけ。それを超える番号の定義は、ファイルには残るが実行しない。定義の無い ECU は、フレームなしで加える（004）。
- 起動時の引数に `.canprj` を渡すと、起動後にそれを読み込む（関連付けによる起動。関連付けの登録はアプリでは行わない。024）。

### 3.2 セッティング（編集 → セッティング）

| 項目 | 範囲 |
|------|------|
| ECU 数 | 0〜16（ドロップダウン） |
| 通信速度 | 125 k / 250 k / 500 k / 1 Mbps（ドロップダウン） |
| シミュレーション時間 | 1〜600 秒の整数。範囲外は OK で拒否して閉じない |

- 起動時の既定は、ECU 数 2・500 kbps・10 秒・フレーム表示 ON・スピード 0（004・021）。
- スピードはここでは変えず、ツールバーのスライダーで変える（015）。

### 3.3 データフレーム編集（編集 → データフレーム編集）

- **ウィンドウ:** モードレス。開く位置は、ログ表示エリアの左端・構成図の下端の 8 px 下（006・010）。
- **上の段:** 「ノード:」で ECU を選び、「ECUラベル名:」（32 文字まで、入力のたびに構成図へ反映）を入力する（022）。
- **送信フレーム一覧:** 列は「No.・フレーム名・ID・DLC・初回オフセット・送信周期」。No. は追加・削除のたびに振り直す（006）。
- **ボタン:** 「追加」「編集」「削除」「閉じる」。
  - 追加・編集の入力画面では、フレーム名・ID（16 進）・DLC・送信周期 (ms)・初回オフセット (ms) を入力する。ビット長と伝送時間も表示する。
  - OK のときに次を検査し、NG なら「項目: 理由」を示して閉じない。
    - ID は 0x000〜0x7FF で、全ノードで一意
    - DLC は 0〜8
    - 周期は 1〜3,600,000 ms
    - オフセットは周期未満
    - 名前は 32 文字まで
    - 1 ノード 100 件まで
  - 削除は、確認してから行う。
- **ダブルクリック:** 一覧の見出し・行・空白のどこをダブルクリックしても「追加」になる（013）。
- **反映と保存:** 変更はその場でプロジェクトに反映し、ファイルへの保存はプロジェクト保存で行う。
- **編集中の制限:**
  - 実行中・中断中は開けない。
  - 開いている間（または ECU 切り替えの待ちの間）は「開始」がグレーになる（010）。
  - 「プロジェクト読込み」「セッティング」は、先に編集ウィンドウを閉じてから行う。
- **構成図の ECU をダブルクリックしたとき**（010・011）:
  - その ECU を選んだ編集ウィンドウを開く。すでに開いていれば前面に出す。
  - 別の ECU なら、一度閉じて 0.5 秒後に開き直す。
  - ダブルクリックした ECU は、0.5 秒グレーで描く。
  - 実行中・箱の外では何もしない。

## 4. シミュレーションの動き

### 4.1 時間と処理の順

- 時刻は内部では ns の整数で持ち、ログには µs で出す（001）。
- 同じ時刻のイベントは、次の順で処理する。種類が同じならノード番号の小さい順。そのため、同じ構成からは必ず同じ結果になる（001）。
  - 送信完了 → インターミッション終了 → 受信処理 → 電源投入・初期化完了 → 送信要求 → バスアイドル（送信開始）
- 計算は「開始」のときに、シミュレーション時間の最後まで一度に行う。画面ではそれを再生する（第 5 章）。

### 4.2 起動（スタートアップ）（002）

- 各ノードは次の順に状態を進める。
  - 電源オフ → 電源投入時刻に初期化 → 初期化時間の後にバス同期検出 → 11 ビット連続のレセシブを検出して通常動作
- 11 ビットの検出は、`max(検出開始, バスが空いた時刻) + 11 ビット時間` で成立する。他ノードの送信中に検出を始めた場合は、そのフレームのインターミッションの終わりで成立する。
- 既定値（電源投入 0・初期化 0）でも、バスが 11 ビット時間（500 kbps で 22 µs）空くのを待ってから通常動作に入る。
- 通常動作に入った時刻は、起動記録（第 6.3 節）に残る。

### 4.3 送信要求（006）

- 各フレームの最初の送信要求は「送信ノードが通常動作に入った時刻 + 初回オフセット」。以後は送信周期ごとに要求する。
- 通常動作の前に送信要求は発生しない。
- 送信待ちの間に同じフレームの次の周期が来たときは、データを更新したことにして `Update_Count` を数える。送信要求時刻は最初のまま残す（001）。

### 4.4 フレームと伝送時間（001）

- ビット列は CAN 2.0A 標準フォーマットどおり（SOF〜EOF）。CRC-15 を計算する。
- 伝送時間は、SOF〜CRC にビットスタッフィングを入れた実ビット数 × ビット時間。データは常に 0xFF なので、スタッフビットが多めになる。
  - 500 kbps・8 バイトで 248〜254 µs。規格の範囲は 216〜264 µs（`specs/029-tx-wait-jitter-analysis/verification.md`）。
- フレームの後に、インターミッション 3 ビットを置く。その間は新しい送信を始めない。

### 4.5 調停と再送信（001）

- バスが空いた時点で、送信待ちの先頭フレームを持つ通常動作のノードのうち、ID の最も小さいものが勝つ。ビットごとの比較はしない。
- 負けたノードは `Retry_Count` を 1 増やし、勝ったフレームとインターミッションの後に、自動で再送信する。
- 1 ノードに送信待ちが複数あるときは、ID の小さい順に調停へ出す。
- 送信は必ず成功する（ACK は必ず返る）。

### 4.6 受信とバッファ（001・008）

- **受信するノード:** 送信が成功したフレームは、送信ノード以外の通常動作中のノードのうち、受信フィルタに合うものがすべて受信する。
- **受信の時刻:**
  - 受信開始 = 送信開始、受信完了 = 送信完了
  - 受信処理時刻 = 受信完了 + 受信処理遅延
- **送信バッファ（16 本）:** 送信待ち（送信中の 1 本を含む）の数の上限。
  - 満杯のときに来た新しい送信要求は捨て、OVERWRITE の行を出す。受信ノードと送受信の時刻は空欄。
  - 同じ時刻・同じノードの送信要求は、CAN ID の小さい順に処理する。そのため、ID の大きいものが捨てられる。
- **受信バッファ（8 本、FIFO）:**
  - 受信完了で入り、受信処理時刻に取り出されて空く。
  - 満杯なら新しいフレームを捨て、OVERWRITE の行を出す。受信処理時刻は空欄。
  - 受信処理遅延が 0（既定）なら、受信側の満杯は起きない。

### 4.7 エラー

- エラーは模擬しない。全体仕様にある「エラー状態制御の枠（エラーアクティブ／パッシブ／バスオフ、TEC／REC）」は、ver.0.7 では実装していない（第 11 章）。

## 5. 実行と再生

### 5.1 操作と状態

状態は「待機」「実行中」「中断中」の 3 つ（014）。

| 操作 | 待機 | 実行中 | 中断中 |
|------|------|--------|--------|
| 開始 | 新しい実行（編集中はグレー） | — | 再開 |
| 中断 | — | 表示を今の時刻まで進めて止める | — |
| 終了 | — | その時刻までの結果を出して止める | 中断した時刻までの結果を出す |

- **新しい実行の「開始」:**
  1. プロジェクトファイルが無ければ、先に保存先を尋ねる（004）。
  2. 開いている結果のウィンドウ（シミュレーションログ・解析の 4 つ）を閉じる（025・028・029）。
  3. ログ表示・グレー表示・強調を空にして、その場で描き直す（012）。
  4. 最後まで計算する（待機カーソル）。
  5. 再生を始める。
- **「終了」:** その時刻までをもう一度計算し、送信を完了したフレームだけの結果を出す（005）。
- **中断:** 強調・ログ表示はそのまま残る。中断しても CSV は変わらない（014）。

### 5.2 再生の速さ（005・015・026）

- シミュレーション時刻 = 実際の経過時間 × 2^スピード。
  - 0 は実時間、-10 は 1/1024 倍。
  - +10 は待たずに即時完了する。
- 時刻は画面の書き換えの回数ではなく、実際の経過時間で決まる。
- 実行中にスピードを変えると、その瞬間の時刻から新しい速さで続く。時刻は飛ばず、戻らない。
- 中断中に変えたスピードは、再開から効く。
- 実行中・中断中に +10 にすると、その場で完了する。
- 再生が終わると、CSV を書き出してから完了のメッセージを出す。
  - 書き出しの前に、終わった状態（シミュレーション時間・ログ・ボタン）を描く（ver.0.7 の不具合修正）。

### 5.3 フレーム表示（強調と流れのエフェクト）（005・016・017・018）

- 約 16 ms ごとに画面を書き換える（実測 約 40 回/秒）。
- 直前の書き換えから今回までに送信中だったフレームについて、次のように強調する。
  - 送信 ECU は赤、受信 ECU は青。
  - 接続線とバスは青の太線。
- その上に、流れのエフェクトを重ねる（018）。
  - 送信 ECU から受信 ECU へ流れるオレンジの粒（16 px おき、150 px/秒、実時間）。
  - ECU の箱の外側の、オレンジの光の枠（0.8 秒周期、受信は半周期遅れ）。
  - 道筋は、最後に見えてから 0.3 秒残す。
- フレーム表示が OFF なら、強調もエフェクトも描かない。時間の進み方は ON/OFF に関係しない。

### 5.4 イベント＆ログ表示（009）

- 「開始」で前回の行を消す。
- 再生の時刻が各行の時刻に達したものから、順に表示する。
  - 行は、起動の状態遷移（初期化中／バス同期検出中／通常動作）と、フレームの各行（1 フレーム × 受信ノード）。
  - 並びは、時刻 → 状態遷移が先 → ノード番号の順。
- フレームの状態は「正常」「再送」「破棄」で表示する。
- 一番下を見ている間は、最新の行に追従する。スクロールバー・ホイール（3 行）で遡っている間は、表示を動かさない。
- 行は次の「開始」まで残る。読込み・セッティングでは消えない。ログクリアでは消える（027）。

## 6. 出力ファイル

実行すると、プロジェクトファイルの隣に 3 つの CSV（UTF-8）を書く。

| ファイル | 内容 |
|----------|------|
| `<プロジェクトファイル名>.log.csv` | フレームログ |
| `<プロジェクトファイル名>.summary.csv` | 性能指標の集計 |
| `<プロジェクトファイル名>.startup.csv` | 起動記録 |

### 6.1 フレームログ（`.log.csv`）（001・008）

1 フレーム × 受信ノードで 1 行。受信ノードの無いフレームも 1 行出す。時刻はすべて、シミュレーション開始からの µs。

| 列 | 内容 |
|----|------|
| Timestamp_us | 受信処理時刻（受信ノードの無い行は送信完了時刻） |
| CAN_ID | 0x000〜0x7FF（16 進、小文字） |
| DLC | 0〜8 |
| Tx_Node / Rx_Node | 送信ノード / 受信ノード（無ければ空欄） |
| Tx_Request | 送信要求時刻 |
| Tx_Start / Tx_End | 送信開始（調停に勝った試行の SOF）/ 送信完了（EOF の終わり） |
| Rx_Start / Rx_End / Rx_Process | 受信開始 / 受信完了 / 受信処理時刻 |
| Bus_Load_Pct | Tx_End までの直前 100 ms のバス負荷率（小数第 1 位） |
| Status | SUCCESS / ARBITRATION_LOST_RETRY（1 回以上調停に負けた）/ OVERWRITE（バッファ満杯で捨てた） |
| Retry_Count | 調停負けによる再送信の回数 |
| Update_Count | 送信待ちの間にデータを更新した回数 |

- OVERWRITE の行では、意味の無い時刻を空欄にする。

### 6.2 集計（`.summary.csv`）（001・008）

- 行の種類: CAN ID ごと（`ID`）・ノードごと（`Node`）・全体（`ALL`）。
- 列:

  | 列 | 内容 |
  |----|------|
  | Count | 件数 |
  | TotalLatency_Min/Max/Avg_us | 総送信レイテンシ = Rx_Process − Tx_Request |
  | QueueingDelay_Min/Max/Avg_us | 送信待ち遅延 = Tx_Start − Tx_Request |
  | TxDuration_Min/Max/Avg_us | フレーム伝送時間 = Tx_End − Tx_Start |
  | BusLoad_Avg_Pct | 送信ごとの直近 100 ms の負荷の平均 |
  | Jitter_Max/Min/StdDev_us | 連続する Tx_Start の間隔 − 周期 |
  | TxDiscard_Count / RxDiscard_Count | ノード行の末尾に出す。満杯で捨てた回数 |

- OVERWRITE の行は、統計から除く。

### 6.3 起動記録（`.startup.csv`）（002）

- 列: `Node_Id, Node_Name, Power_On_us, Init_Done_us, Normal_Entry_us, Reached_Normal`。
- シミュレーション時間内に通常動作へ達しなかったノードは、`Reached_Normal` が偽になる。

## 8. 解析（028・029）

### 8.1 共通

- どれも、今のプロジェクトのフレームログ（`.log.csv`）から計算する。ログ・プロジェクトは変更しない。
- **ウィンドウ:** モードレスで、もう一度選ぶと前面に出るだけ。大きさを変えられる（最初 900 × 640、最小 520 × 400 px、96 dpi）。
  - 上に表、中に説明の 1 行、下にグラフ。表の行を選ぶとグラフが切り替わる。
- **使えないとき:** 実行中・中断中はグレー。
- **ウィンドウが閉じる契機:** シミュレーションログと同じ（第 7.1 節）。
- **開けないときの通知:** プロジェクトファイルが無い・ログが無い・読めない、の 3 つ（025 と同じ）。
- **「解析中」ウィンドウ**（029 改訂 1）:
  - 読み込みと計算は裏で行い、0.5 秒を超えたら「解析中」を出す。中身は文字・進み具合のバー・「中断」ボタン。
  - 出ている間、メインウィンドウは操作できない。
  - 「中断」・Esc・✖ で止めると、何も開かず、メッセージも出さない。集計の途中なら、終わるのを待ってから閉じる。
  - 0.5 秒以内に終わったときは、出さずに結果を開く。
- **速さ:** 600 秒・16 ECU（約 193 万行）のログで、読み込みは Release 約 0.7 秒・Debug 約 3.5 秒。

### 8.2 各項目

| 項目 | 表 | グラフ |
|------|----|--------|
| 送信待ち時間(W) | `Tx_Start − Tx_Request`。送信 1 回を 1 件とし、受信ノードの数だけある行は 1 件にまとめる。調停負けで再送されたフレームは、最終的に送れた 1 回を 1 件とする。全体と CAN ID ごと（CAN ID・送信 ECU・件数・最小・平均・最大・95%）。破棄（OVERWRITE）の件数は説明の行に出す | 選んだ行のヒストグラム |
| 受信完了時間(R) | `Rx_End − Tx_Request`。受信 1 件ごと。全体と、送信 ECU × 受信 ECU ごと（件数・最小・平均・最大・95%） | 選んだ行のヒストグラム |
| 送信ジッター(J) | CAN ID ごとに「連続する送信開始の間隔 − 送信要求の間隔」（正は遅れ、負は早まり）。列は CAN ID・送信 ECU・周期 (ms)・件数・最小・最大・標準偏差。周期は送信要求の間隔の最頻値。送信が 1 回だけの CAN ID は件数 0 で、ほかは空欄 | 選んだ CAN ID のずれを、時刻に沿って描く。点を折れ線でつなぎ、0 の線も描く。点が幅より多いときは、列ごとの最小〜最大を縦線で描く |
| CAN バス負荷(B) | 送信 1 回の `[Tx_Start, Tx_End)` を使用時間とする。要約（平均・最大とその区間・範囲）と、ECU ごとの送信フレーム数・使用率 | 10 ms ごとの負荷の折れ線と、平均の線 |

- **数値の決まり:**
  - 95% は最近順位法（並べて ⌈0.95 n⌉ 番目）。
  - 標準偏差は母標準偏差（件数で割る）。
  - 平均・標準偏差は小数第 1 位、ほかは整数で表示する。
- **ヒストグラム:** ビンの数はおよそ `clamp(⌈√n⌉, 10, 50)`、幅は 1・2・5 × 10^m µs。
- **集計 CSV との関係:**
  - 送信ジッターは、破棄の無い構成では集計 CSV の `Jitter_*` と一致する。破棄で送信が抜けたときは、抜けた周期をずれに数えないため、集計 CSV と違ってよい。
  - 受信完了時間は `Rx_End` まで、集計 CSV の総送信レイテンシは `Rx_Process` までで、終点が違う。
  - CAN バス負荷の平均は「使用時間 ÷ 範囲」で、集計 CSV の `BusLoad_Avg_Pct`（直近 100 ms の負荷の平均）とは別の指標。
- **検証の記録:** `specs/029-tx-wait-jitter-analysis/verification.md`

## 9. 制限と目安

| 項目 | 値 |
|------|----|
| ECU 数 | 0〜16（NodeId 1〜16） |
| 1 ノードの送信フレーム | 100 まで |
| 送信バッファ / 受信バッファ | 16 本 / 8 本 |
| シミュレーション時間 | 1〜600 秒 |
| スピード | -10〜+10 |
| 通信速度 | 125 k / 250 k / 500 k / 1 Mbps |
| フレーム名 / ECUラベル名 | 32 文字まで（構成図のラベルは 10 文字まで表示） |
| 送信周期 | 1〜3,600,000 ms |

- **メモリと時間の目安**（2026-10-05 の計測、Release）:
  - 16 ECU の車両サンプル 600 秒（約 193 万行）: x64 で約 0.7 GB・計算約 3 秒。
  - 混んだ構成（sample_16ecu）の 600 秒（720 万行）: x64 で約 2.2 GB・約 114 秒。32 bit 版はメモリ不足で失敗する（行数が 400 万前後を超えると失敗）。

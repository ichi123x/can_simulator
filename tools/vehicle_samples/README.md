# 車両イメージのサンプルプロジェクトと動作テスト記録

`MFCApplication1/CanSim/SampleConfigs/sample_vehicle_{2,4,8,16}ecu.canprj` は、実車の CAN をイメージしたデモ用のサンプルプロジェクトです。
このフォルダーには、サンプルを作るスクリプト・ログを確かめるスクリプトと、動作テストの記録を置いています。

## ファイル

| ファイル | 内容 |
|---|---|
| `gen_vehicle_samples.ps1` | 4 つのサンプルを 1 つの車両モデル（ECU の一覧・フレーム・受信フィルター）から作る |
| `verify_log.ps1` | シミュレーションのログ（`.log.csv`）をプロジェクトの設定と照らし合わせて確かめる |

どちらも Windows PowerShell 5.1 で動きます（日本語の ECU ラベル名を含むため、BOM 付き UTF-8 で保存しています）。

## サンプルの内容

| サンプル | ECU（ラベル名） | フレーム数 |
|---|---|---|
| 2 ECU | エンジン・メーター | 4 |
| 4 ECU | エンジン・ブレーキ/ESC・ボデー・メーター | 9 |
| 8 ECU | 上記 ＋ トランスミッション・ステアリング・エアバッグ・ゲートウェイ | 19 |
| 16 ECU | 上記 ＋ エアコン・前方カメラ・レーダー・左前ドア・右前ドア・バッテリー・タイヤ空気圧・ナビ/オーディオ | 31 |

- 500 kbps。CAN ID は実車と同じ考え方で、エアバッグ（0x050）→ シャシー（0x0A0〜）→ パワートレイン（0x0C0〜）→ ボデー・快適系（0x300〜）→ インフォテインメント（0x400〜）の順に優先度が高い。
  同じ ECU はどのサンプルでも同じ CAN ID。
- 周期は 10 ms（車輪速・エンジン回転・舵角など）〜 1000 ms（タイヤ空気圧など）。フレーム名は DBC の信号名風の英語（例: `WheelSpeed_FL_FR_RL_RR`）。
- 各 ECU の `RxFilter` には、実際に使うフレームだけを入れる。ゲートウェイはフィルターなし（全受信）。
  そのサンプルの中に受信する ECU が無いフレームは入れない（ログに受信先の無い行を出さないため）。
- 初回オフセットは ECU・フレームごとにずらす（`(ECU番号 × 3 + フレーム番号 × 2) mod 周期` ms）。それでも一部のフレームはぶつかり、調停負けの再送が起きる。
- シミュレーション時間 5 秒、スピード -3（実時間の 1/8）、フレーム表示 ON。

## 作り直す・確かめる手順

リポジトリのルートで、PowerShell から実行します。`runner.exe` のビルドは [../cansim_runner/README.md](../cansim_runner/README.md) を参照してください。

```powershell
# サンプルを作り直す（SampleConfigs に上書きする）
.\tools\vehicle_samples\gen_vehicle_samples.ps1 -OutDir (Resolve-Path MFCApplication1\CanSim\SampleConfigs).Path

# 5 秒シミュレーションして、ログを確かめる（例: 16 ECU）
$out = "$env:TEMP\cansim_tools"
& "$out\runner.exe" MFCApplication1\CanSim\SampleConfigs\sample_vehicle_16ecu.canprj "$env:TEMP\v16" 5
.\tools\vehicle_samples\verify_log.ps1 -Project (Resolve-Path MFCApplication1\CanSim\SampleConfigs\sample_vehicle_16ecu.canprj).Path -Prefix "$env:TEMP\v16" -DurationUs 5000000
```

`verify_log.ps1` は最後に `RESULT: no problems found` または見つかった問題を表示します。
通信速度 500 kbps（通常動作に入る時刻 22 μs）・受信処理遅延 0 を前提にしています。

### verify_log.ps1 が確かめること

1. ログの状態が `SUCCESS` か `ARBITRATION_LOST_RETRY` だけであること（`OVERWRITE` などが無い）。
2. 各送信の送信元 ECU と DLC が、プロジェクトの設定どおりであること。
3. 各送信の受信先が、送信元以外で受信フィルターがその ID を含む ECU（フィルターなしは全受信）と一致すること。
4. 受信の時刻（受信完了 = 送信完了、受信処理 = 受信完了）。
5. フレームごとの送信回数が、周期と最初の送信要求の時刻（22 μs + 初回オフセット）から計算した回数と一致し、送信要求の間隔が周期どおりであること。
6. バス上でフレームが重ならず、フレームの間に 3 ビット（6 μs）のインターミッションがあること。
7. 調停: あるフレームが送信を始めたとき、それより前から待っていたフレームの CAN ID がすべてそれより大きい（優先度が低い）こと。

## 動作テストの記録（2026-10-02）

- 対象: ブランチ `ver.0.5`（コミット `eab6b42` の上に、サンプル 4 つを追加した状態）。CanSim のソースから `cl` でビルドした `runner.exe` と、Release x64 のアプリ。
- 方法: 各サンプルを 5 秒シミュレーションし、`verify_log.ps1` でログを確かめた。集計（`.summary.csv`）と起動記録（`.startup.csv`）も確認した。

### 結果

| サンプル | 送信フレーム | ログの行 | 調停負けの再送 | 最長の待ち | バス負荷 | 破棄 | verify_log.ps1 |
|---|---|---|---|---|---|---|---|
| 2 ECU | 600 | 600 | 0 | 0 μs | 2.89% | 0 | 問題なし |
| 4 ECU | 1,700 | 2,700 | 25 | 174 μs | 8.17% | 0 | 問題なし |
| 8 ECU | 3,240 | 10,040 | 625 | 514 μs | 15.10% | 0 | 問題なし |
| 16 ECU | 4,015 | 16,080 | 990 | 514 μs | 18.74% | 0 | 問題なし |

16 ECU の詳細:

- 起動: 16 台とも電源投入 0 μs、通常動作に入った時刻 22 μs（500 kbps でバスの空きを 11 ビット分観測する時間）。
- 送信回数: 31 フレームすべてが計算どおり（10 ms のフレームは 500 回、20 ms は 250 回、50 ms は 100 回、100 ms は 50 回、200 ms は 25 回、500 ms は 10 回、1000 ms は 5 回）。
- 受信先: すべての送信で受信フィルターどおり。ゲートウェイは全フレームを受信。
- バス: 重なりなし。インターミッションあり。
- 調停: 待っているフレームの CAN ID が勝ったフレームより小さい例は 0 件。
- 状態: `SUCCESS` 12,735 行、`ARBITRATION_LOST_RETRY` 3,345 行（990 送信分の受信先の行）。送信・受信バッファの破棄は 0。

### アプリでの確認（16 ECU）

- 16 ECU のサンプルの複製（スピードだけ +10 にしてすぐ完了させたもの）を Release x64 のアプリで開いて「開始」した。
  アプリが書き出した `.log.csv`・`.summary.csv`・`.startup.csv` は、`runner.exe` の出力と完全に一致した。
- 同じサンプルをスピード -3 で実行した画面で、構成図の日本語のラベル名（最長の「トランスミッション」「ナビ/オーディオ」を含む）が ECU の箱に収まり、
  フレーム表示（送信 ECU の赤・受信 ECU の青・流れのエフェクト）とログ表示エリアの行が出ることを画面写しで確かめた。

### テストで見つかって直したこと（サンプルの作り）

シミュレーションの動作には問題は無かった。サンプルの作りについて、次の 2 点を直してから上の結果を取り直した。

1. 16・8 ECU: ゲートウェイの `Diag_SessionStatus`（0x208）を受信する ECU が無く、ログに受信先の無い行（Rx_Node 0）が出ていた。
   メーターの受信フィルターに 0x208 を足した（サービス表示のイメージ）。
2. 2・4 ECU: 本来の受信先（トランスミッション・ナビなど）がいない小さな構成で、誰も受信しないフレームが送信されていた。
   そのサンプルの中に受信する ECU があるフレームだけを入れるようにした。

また、サンプルを作るスクリプトで、フレームが 1 つだけの ECU が正しく書き出されない不具合（PowerShell が 1 要素の配列を平らにする）を、フレームの定義を文字列にして直した。

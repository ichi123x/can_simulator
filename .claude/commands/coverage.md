# カバレッジのループ

目的は、テストで実行されていない行（赤い行）を減らすこと。ただし**赤い行を消すためだけのテストは書かない**。
期待値の根拠が仕様にある行だけをテストにし、根拠が無い行は人が決める。

入力: $ARGUMENTS（無ければ全ファイルを、率の低い順に見る）

## 手順（A が無くなるまで繰り返す）

1. **測る**: `powershell -NoProfile -ExecutionPolicy Bypass -File .claude/scripts/coverage.ps1` を実行し、`build/coverage/uncovered.txt` を読む。
   - ビルドかテストが失敗したら、まずそれを直す（テストと期待値は変えない）。
   - OpenCppCoverage が無いと言われたら、ユーザーに `winget install --id OpenCppCoverage.OpenCppCoverage -e` を頼んで止まる。
   - 「保留の行」は人が決めた行なので、調べ直さない。
   - 「測れる行が 0 行」（終了コード 3）なら、率は 100% ではなく「まだ測れていない」と報告する。テストが対象のコードを呼んでいないのが原因なので、どの機能の仕様からテストを書き始めるかをユーザーに聞いて止まる（勝手に全機能のテストを書き始めない）。
2. **根拠を探す**: 「未カバーの行」ごとに、ソースの前後を読み、次の順で根拠を探す。
   1. その機能の `specs/<NNN>-<機能名>/spec.md`（FR、受け入れシナリオ、Edge Cases、境界値の表）
   2. 同じフォルダーの `data-model.md`・`contracts/`
   3. 関数を宣言しているヘッダーのコメント（関数の約束）
3. **分ける**:
   - **A 根拠がある**: 期待値が上の資料から決まる → テストを書く
   - **B 守りのコード**: 呼び出し側の約束で来ない入力、OS やファイルの故障など、テストで起こせない・起こす意味が無い → 保留の候補
   - **C 動きは決まっているが、仕様に書かれていない** → 人に確認する
4. **A のテストを書く**:
   - 置き場所: その機能のテストのファイル、または `tests/unit/<機能>_edge_tests.cpp`。新しいファイルは `tests/CMakeLists.txt` の `add_gtest` に `unit` で登録する。
   - テスト名とコメントは CLAUDE.md の決まりに従う（`F<機能番号>_<ID>_<条件>_<結果>`、`RecordProperty`、日本語のコメントとメッセージ）。
   - 各テストの直前のコメントに、根拠（ファイル名と節や ID）を書く。
   - 期待値は仕様から書く。今の実装を動かして出た値を、そのまま期待値にしない。
5. **測り直す**（1 に戻る）。
   - A のテストが失敗したら、仕様と実装が食い違っている。テストを実装に合わせて書き換えず、そこで止めて報告する。
6. A が無くなったら終える。B・C は書かずに、下の報告で人に渡す。

## 終わりの報告

短く、次の順で書く。
1. 結果: 全体とファイル別の率（前 → 後）、足したテストの数、ctest の結果
2. 足したテスト: `テスト名 | 通した行 | 根拠` の表
3. B（保留の候補）: `ファイル:行 | コード | 守りと判断した理由` の表
4. C（確認したいこと）: `ファイル:行 | コード | 今の動き | 質問（仕様に足すか、保留にするか）` の表

人が B や C を「テストしない」と決めたら、`tests/coverage-hold.md` の表に 1 行ずつ追記する（ファイル、コード、理由、決めた日）。
「仕様に足す」と決めたら、spec.md か data-model.md に書き足してから、A としてテストを書く。

## してはいけないこと

- 根拠の無い行（B・C）のテストを、人が決める前に書くこと
- 製品のコードを変えること（不具合を見つけたら報告だけする）
- テストを消す・無効にする・期待値を緩めること
- 100% を目標にすること（理由のある保留は正しい結果）
- `tests/coverage-hold.md` に、人が決めていない行を足すこと

# Research: 011 ECU のグレー表示と表示エリアの枠

## 決定1: グレー表示は 1 つの番号と 500 ms のワンショットタイマー

- **Decision**: メインダイアログに `int m_grayEcu = 0`。`OnLButtonDblClk` で ECU の操作を受け付けたとき（機能 010 の「開く」「前面に出す」「閉じて待ちに入る」「待ちの間に置き換える」のすべて）に、`m_grayEcu = ecu`、`SetTimer(kGrayTimerId = 3, kGrayMs = 500)`（同じ ID で張り直すと 500 ms を数え直す）、構成図を無効化して `UpdateWindow()` で即座に描き直してから、機能 010 の処理を行う。`OnTimer` で ID 3 なら`KillTimer`、`m_grayEcu = 0`、構成図を無効化。
- **Rationale**: 最後のダブルクリックの ECU だけがグレーになり（FR-004）、同じ ECU の連続も最後から 0.5 秒（Edge Cases）。`UpdateWindow` を編集ウィンドウを開く前に呼ぶので、グレーは編集ウィンドウの生成を待たずに出る（SC-001）。機能 010 の処理の順序と時間は変わらない（FR-005）。切り替えの場合は切替タイマー（ID 2）と同時に張るので、グレーが戻るのと新しい編集ウィンドウが開くのがほぼ同時になる（US1 シナリオ 3）。
- **Alternatives considered**: 終了時刻を持ち再生タイマーで見る（実行中でないときは再生タイマーが動いていない）。ECU ごとに状態を持つ（同時に 1 つなので不要）。

## 決定2: 受け付けないダブルクリックはグレーにしない

- **Decision**: `OnLButtonDblClk` の「実行中なら戻る」「`FindEcuAt` が 0 なら戻る」の後でだけグレーにする。入力画面・確認画面の間はメインウィンドウが無効なのでダブルクリックが届かない（機能 010 決定8）。1 回クリックは処理しない。
- **Rationale**: FR-006。グレー表示を「受け付けた」合図に限る。

## 決定3: 取り消し

- **Decision**: `ClearGray()` = `KillTimer(3)`、`m_grayEcu = 0`、構成図を無効化。`SetEcuCount` で `m_grayEcu > 新しい ECU 数` なら呼ぶ、`OnSimStart` の計算の前に呼ぶ、`OnDestroy` でタイマーを止める。
- **Rationale**: FR-007、Edge Cases。「開始」は編集中は選べない（機能 010）が、編集ウィンドウを閉じた直後の 0.5 秒以内には開始できるため。

## 決定4: グレーの配色

- **Decision**: 塗り `RGB(205, 205, 205)`、枠 `RGB(128, 128, 128)`（太さ 1 px を換算）、文字 `RGB(96, 96, 96)`。実行中の強調（送信: 赤、受信: 緑）より優先するが、実行中はグレーにならないので実際に重なることはない。
- **Rationale**: 上段（薄紫）・下段（薄橙）の通常色、送信（赤）・受信（緑）と色相で区別できる無彩色（FR-003）。白い背景とも区別できる明るさ。
- **Alternatives considered**: 半透明の重ね塗り（GDI では `AlphaBlend` が要り、元の色が透けて区別しにくい）。

## 決定5: 構成図の枠は構成図の領域の 4 px 内側

- **Decision**: `CanSim::kDiagramFrameInset = 4`。`BusDiagramLayout::Frame` = `(4, 4) - (1136, 212)`（96 dpi、ECU 数によらない）。描画は`DrawBusDiagram` のメモリ DC で、中身より先に 1 px（換算、最小 1）の `RGB(160, 160, 160)` の矩形の線を描く（塗らない）。
- **Rationale**: 構成図の領域はクライアントの左上 (0, 0) にぴったり置かれているので、外側には枠を描く余白がない。中身の範囲は x 10〜1130（バス線）、y 34〜186（ECU の箱）、「CAN BUS」の文字は x 14〜、y 106 付近まで。4 px 内側なら中身と 6 px 以上離れる（FR-010）。領域そのものは変えないので、クリックの判定・ウィンドウの大きさに影響しない（FR-012）。
- **Alternatives considered**: 構成図全体を右下にずらして外側に枠（機能 003 の位置と、機能 010 の判定・位置の計算がすべて変わる）。

## 決定6: ログ表示エリアの枠は 3 px 外側

- **Decision**: ログ表示エリア（灰色の領域 + スクロールバー、96 dpi で (150, 260) - (1000, 520)）の 3 px 外側 (147, 257) - (1003, 523) に、構成図と同じ色・太さの矩形の線を `OnPaint` で描く。定数はダイアログ側（ログ表示エリアの定数の隣）に置く。
- **Rationale**: 灰色の領域とスクロールバー（子ウィンドウ）に重ならず、ログの書き換え（`GetLogTextRect` の無効化）で消えない。構成図の下端216 とも 41 px 離れ、クライアントの高さ（約 560）に収まる（FR-009、FR-010）。
- **Alternatives considered**: スクロールバーを `WS_BORDER` にする（ログの領域の枠にならない）。灰色の領域の内側に描く（ログの文字と重なる）。

## 決定7: 枠の太さと換算

- **Decision**: 太さ `max(1, ScaleToDpi(1, dpi))`、位置は `ScaleToDpi` で換算（機能 010 と同じ関数）。
- **Rationale**: FR-011。100%・125%・150% で 1〜2 px の細い線になり、位置の余白も同じ比率で保たれる。
- **補足（動作に影響なし）**: ログ表示エリアの枠は、ログ表示エリアと同じ換算（`CanSim::ScaleLogViewRect` / `ScaleLogFrameRect`、T014 で移設）を使う。ダイアログ内の `ScaleForDialog`（`MulDiv`）と `ScaleToDpi` は非負の値で同じ結果になるため、tasks.md の記述（T010 の `ScaleForDialog`）と本決定（`ScaleToDpi`）の関数名の違いは値に影響しない。

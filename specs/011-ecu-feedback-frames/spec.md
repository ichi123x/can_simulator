# Feature Specification: ECU ダブルクリック時のグレー表示と、表示エリアの枠

**Feature Branch**: `011-ecu-feedback-frames`

**Created**: 2026-09-30

**Status**: Draft

**Input**: User description: "CANバス図のＥＣＵをダブルクリックしたときは、わかりやすいようにそのＥＣＵを0.5秒、グレーアウトしてアクションをわかり易くする。イベント表示、ログ表示ウィンドウに枠をお設けて見栄えをよくしてください。"

**前提となる機能**: 機能 003（CAN バス構成図）、機能 009（ログ表示エリア）、機能 010（ECU のダブルクリックでデータフレーム編集を開く）。本機能は見た目の追加だけで、ダブルクリックで何が起きるか（開く・前面に出す・切り替える）は機能 010 のまま変えない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ダブルクリックした ECU が 0.5 秒グレーになる (Priority: P1)

ユーザーが構成図の ECU をダブルクリックすると、その ECU のブロックが約 0.5 秒グレーで表示され、その後もとの色に戻る。どの ECU の操作を受け付けたかが一目で分かる。特に、編集ウィンドウを開いたまま別の ECU に切り替える場合（機能 010 の「閉じて約 0.5 秒後に開く」）は、待ちの間その ECU がグレーになるので、操作が受け付けられたことが分かる。

**Why this priority**: ユーザー要望の中心。操作の手応えがなく、受け付けられたか分かりにくい問題を解決する。

**Independent Test**: `sample_appendix_a` を読み込み「ECU 03」をダブルクリックして、ECU 03 のブロックだけがグレーになり、約 0.5 秒後にもとの色に戻ることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** シミュレーションを実行していない状態で構成図に ECU が表示されている、**When** ECU 03 をダブルクリックする、**Then** ECU 03 のブロック（枠・塗り・文字）がグレー表示になり、約 0.5 秒後にもとの表示に戻る。ほかの ECU は変わらない。
2. **Given** 同上、**When** ECU 03 をダブルクリックする、**Then** 編集ウィンドウは機能 010 どおりすぐに開く（グレー表示の0.5 秒を待たない）。
3. **Given** ECU 03 の編集ウィンドウが開いている、**When** ECU 05 をダブルクリックする、**Then** ECU 05 がグレーになり、編集ウィンドウが閉じ、約 0.5 秒後に ECU 05 の編集ウィンドウが開くのとほぼ同時に ECU 05 がもとの色に戻る。
4. **Given** ECU 03 の編集ウィンドウが開いている、**When** ECU 03 をもう一度ダブルクリックする（前面に出すだけ）、**Then** ECU 03 が約 0.5 秒グレーになる。
5. **Given** ECU 03 がグレー表示中、**When** 0.5 秒以内に ECU 05 をダブルクリックする、**Then** ECU 03 はすぐにもとの色に戻り、ECU 05 がその時点から約 0.5 秒グレーになる（グレーになるのは常に最後にダブルクリックした 1 つだけ）。

---

### User Story 2 - 受け付けないダブルクリックではグレーにならない (Priority: P2)

操作が受け付けられないときにグレーになると、受け付けられたと誤解する。グレー表示は、ダブルクリックが ECU の操作として受け付けられたときだけ行う。

**Why this priority**: グレー表示の意味（受け付けた）を保つため。

**Independent Test**: 実行中に ECU をダブルクリックして、グレーにならないことを確認する。

**Acceptance Scenarios**:

1. **Given** シミュレーション実行中、**When** ECU をダブルクリックする、**Then** グレーにならない（実行中の送信・受信の強調表示もそのまま）。
2. **Given** 編集ウィンドウの「追加」の入力画面を開いている（メインウィンドウは操作できない）、**When** 構成図の ECU をダブルクリックする、**Then** グレーにならない。
3. **Given** 構成図のバス線・余白・ログ表示エリア、**When** ダブルクリックする、**Then** どの ECU もグレーにならない。ECU の 1 回クリックでもグレーにならない。

---

### User Story 3 - 構成図とログ表示エリアに枠が付く (Priority: P2)

構成図（フレームの送受信を表示するイベント表示の領域）とログ表示エリアの周りに枠が付き、画面の区切りがはっきりして見栄えがよくなる。

**Why this priority**: 見た目の改善。機能には影響しないが、ユーザーの要望。

**Independent Test**: アプリを起動し、構成図とログ表示エリアのそれぞれを囲む枠が表示されていることを確認する。

**Acceptance Scenarios**:

1. **Given** アプリを起動した、**When** メインウィンドウを見る、**Then** 構成図の領域の周囲と、ログ表示エリア（スクロールバーを含む）の周囲に、それぞれ枠が表示されている。
2. **Given** 枠が表示されている、**When** ECU 数を 0〜16 に変える、シミュレーションを実行する、ログを表示・スクロールする、**Then** 枠は常に同じ位置・同じ見た目で表示され、ECU・バス線・「CAN BUS」の文字・ログの文字・スクロールバーに重ならず、欠けない。
3. **Given** 画面の拡大率が 100%・125%・150%、**When** メインウィンドウを見る、**Then** 枠は拡大率に合わせた位置・太さで表示され、中身と重ならない。

---

### Edge Cases

- グレー表示中にシミュレーションを開始することはできない（編集ウィンドウが開いている、または切り替えの待ちの間は「開始」が選べない、機能 010）。編集ウィンドウを閉じた直後に「開始」した場合は、グレー表示を取り消してから実行の表示に移る。
- グレー表示中に「プロジェクト読込み」「セッティング」で ECU 数が変わり、その ECU が表示されなくなった場合は、グレー表示を取り消す。
- グレー表示中にメインウィンドウを閉じた場合は、そのまま終了する。
- 同じ ECU を 0.5 秒以内に続けてダブルクリックした場合は、最後のダブルクリックから約 0.5 秒グレーにする。
- 枠は画面の表示だけで、ダブルクリックの判定範囲（ECU の箱）やログのスクロール操作の範囲は変えない。
- （補足、動作に影響なし）切り替えの待ちの間に別の ECU をダブルクリックした場合、編集ウィンドウは最初の切り替えの操作から約 0.5 秒で開く（機能 010: 待ちは延ばさない）が、グレー表示は最後のダブルクリックから約 0.5 秒続く。そのため、新しい編集ウィンドウが開いた後も最長で約 0.5 秒グレーが残ることがある（FR-004 どおりの動き）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 構成図の ECU のダブルクリックが受け付けられたとき（機能 010 で編集ウィンドウを開く・前面に出す・切り替える、のいずれかが行われるとき）、その ECU のブロックをグレー表示にしなければならない。
- **FR-002**: グレー表示は約 0.5 秒（0.4〜0.7 秒）続き、その後もとの表示に戻らなければならない。
- **FR-003**: グレー表示は ECU のブロック全体（枠・塗り・ECU 名の文字）を、通常の ECU とも実行中の強調表示（送信・受信）とも区別できるグレーの配色で表示しなければならない。ほかの ECU・バス線・接続線は変えない。
- **FR-004**: グレー表示になるのは同時に 1 つの ECU だけとし、グレー表示中に別の ECU のダブルクリックが受け付けられた場合は、前の ECU をすぐにもとに戻し、新しい ECU を約 0.5 秒グレー表示にしなければならない。
- **FR-005**: グレー表示は機能 010 の動作（編集ウィンドウを開く時期、切り替えの待ち時間、前面に出す）を遅らせたり変えたりしてはならない。グレー表示の間も画面は固まらず、メインウィンドウ・編集ウィンドウを操作できる。
- **FR-006**: 実行中のダブルクリック、ECU の外のダブルクリック、1 回クリック、メインウィンドウが操作できない間（入力画面・確認画面の表示中）の操作では、グレー表示にしてはならない。
- **FR-007**: グレー表示中に ECU 数の変更でその ECU が表示されなくなった場合、またはシミュレーションを開始した場合は、グレー表示を取り消さなければならない。
- **FR-008**: 構成図の領域（ECU 数 16 のときのすべての ECU・バス線・「CAN BUS」の文字を含む範囲）の周囲に枠を表示しなければならない。
- **FR-009**: ログ表示エリア（灰色の領域とスクロールバー）の周囲に枠を表示しなければならない。
- **FR-010**: 枠は、ECU 数・実行状態・フレーム表示の ON/OFF・ログのスクロール位置にかかわらず常に同じ位置・見た目で表示され、中身（ECU・バス線・文字・ログの行・スクロールバー）に重ならず、欠けてはならない。
- **FR-011**: 枠は画面の拡大率に合わせて位置と太さを換算し、100%・125%・150% で FR-010 を満たさなければならない。
- **FR-012**: 構成図の中身の位置・大きさ・色（機能 003）、ログ表示エリアの内容と操作（機能 009）、ダブルクリックの判定範囲（機能 010）は変えてはならない。メインウィンドウの大きさは、枠がすべて収まる範囲で必要なら広げてよい。

### Key Entities

- **グレー表示中の ECU**: 最後に受け付けたダブルクリックの ECU 番号と、グレー表示を終える時刻。無ければ「なし」。
- **表示エリアの枠**: 構成図の枠とログ表示エリアの枠。位置は各エリアの外側で、画面の拡大率に合わせて換算する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ECU のダブルクリックの受け付けから、その ECU がグレー表示になるまでが 0.1 秒以内で、グレー表示は 0.4〜0.7 秒でもとに戻る（ECU 数 1〜16 のどの ECU でも）。
- **SC-002**: グレー表示の間、ほかの ECU の表示は 1 つも変わらない。
- **SC-003**: 実行中・ECU の外・1 回クリック・入力画面の表示中の操作で、グレー表示になる ECU が 0 件。
- **SC-004**: 機能 010 の切り替え（閉じてから開くまで 0.4〜0.7 秒）、すぐに開く、前面に出す、の各動作の時間が本機能の前と変わらない。
- **SC-005**: 拡大率 100%・125%・150%、ECU 数 0・6・16 のすべての組み合わせで、2 つの枠が表示され、中身と重ならない。
- **SC-006**: 既存の検証（機能 001〜010）がすべて通り、シミュレーション結果（CSV）は変わらない。

## Assumptions

- 「イベント表示」は、フレームの送受信を ECU とバスの強調で表示する CAN バス構成図の領域を指すものとする（メインウィンドウにほかのイベント表示の領域はない）。
- 「ログ表示ウィンドウ」は機能 009 のログ表示エリア（別ウィンドウではなくメインウィンドウ内の領域）を指す。
- グレー表示の時間は固定値（0.5 秒）で、ユーザーが変更する設定は設けない。
- グレー表示は機能 010 で「受け付けた」ダブルクリックが対象で、切り替えの待ちの間に開く ECU を置き換えた場合も含む。
- 枠は細い線（96 dpi 基準で 1〜2 px 程度）で、背景（白）とログ表示エリア（薄いグレー）の両方と区別できる色とする。具体的な色・太さは計画で決める。
- 編集ウィンドウ側の表示は変えない。

# Feature Specification: フレームが流れる様子のアニメーション

**Feature Branch**: `ver.0.3`（spec ディレクトリ: `018-frame-flow-animation`）

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "フレーム表示で、送信ECUから受信ECUにフレームが流れている様子のアニメーションをいれてください。アニメーションはスピード=0の時で考慮して、一定パターンのアニメーションでいいです。アニメーションのポイントは、ECUとCANバス上に上書きでエフェクト表示をするイメージです。送信元のECUは赤色強調表示、受信ECUは青色協調表示はそのままで。"

**前提となる機能**: 機能 005（フレーム表示: 画面の書き換え 1 回分に送信中だったフレームの送信 ECU・受信 ECU・バスをまとめて強調）、機能 014（中断）、機能 015（スピード）、機能 016（受信 ECU の青・接続線の青）、機能 017（フレーム表示のチェックボックス）。

## 現状（背景）

- フレーム表示 ON の実行中、送信 ECU は赤、受信 ECU は青、それぞれの接続線とバスは青の太線で強調される。ただし止まった色の変化だけで、
  「送信 ECU から受信 ECU へフレームが流れている」ことが絵として伝わりにくい。
- スピード 0（実時間）では、1 フレームは数百 μs で、画面の書き換え（約 1/40 秒）より短い。そのため、1 フレームのビットの進みに合わせた動きは
  目に見えない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 送信 ECU から受信 ECU へ流れる動きを見る (Priority: P1)

ユーザーはフレーム表示 ON・スピード 0 で実行し、構成図の上で、送信 ECU（赤）から接続線を下り（または上り）、バスを伝わって、受信 ECU（青）の
接続線を通って受信 ECU に届く「流れ」の動き（エフェクト）を見る。動きは決まったパターンのくり返しで、ECU とバスの上に重ねて描かれる。
送信 ECU の赤・受信 ECU の青・青い線の強調は今のまま。

**Why this priority**: 要望のすべて。CAN バス上の通信の向きがひと目で分かる。

**Independent Test**: `sample_collision`（ECU 1・3 が送信、ECU 2 は受信しない）をフレーム表示 ON・スピード 0 で実行し、送信中の ECU から
受信 ECU へ向かう動きが見え、受信しない ECU 2 には届かないことを、続けて撮った数枚の画面写しで確認する。

**Acceptance Scenarios**:

1. **Given** フレーム表示 ON・スピード 0 で実行中、**When** 送信 ECU と受信 ECU が強調されている、**Then** 送信 ECU の位置から、その接続線・
   バスを通って、各受信 ECU の接続線・受信 ECU へ向かって進む光の粒（流れのエフェクト）が描かれる。粒は時間とともに進み、受信 ECU に届いたら
   送信 ECU の位置から次の粒が出る（一定の周期のくり返し）。
2. **Given** 同じとき、**When** 粒が受信 ECU に届く、**Then** 受信 ECU の箱の上に、届いたことを示す短い光（縁の輝き）が重ねて描かれる。
3. **Given** 同じとき、**When** 送信 ECU を見る、**Then** 送信 ECU の箱の上に、送り出していることを示す周期的な光（縁の輝き）が重ねて描かれる。
4. **Given** 同じとき、**When** 赤・青の強調を見る、**Then** 送信 ECU の赤、受信 ECU の青、青い接続線・バスは今までどおり描かれ、エフェクトは
   その上に重なる（ECU 名の文字は読める）。
5. **Given** 受信しない ECU（`sample_collision` の ECU 2）、**When** 見る、**Then** その ECU とその接続線には粒は行かない。
6. **Given** バスが空いている（強調の対象のフレームが無い）書き換え、**When** 見る、**Then** エフェクトは描かれない。
7. **Given** フレーム表示 OFF（チェックなし）、**When** 実行する、**Then** エフェクトも強調も描かれない（チェックを入れたら、その場で描かれ始める）。

---

### Edge Cases

- 画面の書き換え 1 回分に複数のフレームがある場合は、その間に送られた各フレームの「送信 ECU → 受信 ECU」の組ごとに粒を流す（同じ組は 1 本に
  まとめる）。同じ書き換えの間に送信も受信もした ECU は赤で強調されるが、受信した組の行き先として粒は届く（実装中の見直し: スピード 0 では
  `sample_collision` の ECU 1・3 が同じ書き換えの間に互いに送り合い、強調の「受信 ECU」（赤を除いた集まり）が空になるため、強調の集まりから
  道筋を作ると粒が出なかった）。
- スピード 0 ではフレームが短く、書き換えのたびに強調の対象が入れ替わることがある。エフェクトの動き（粒の位置）は書き換えのたびに最初から
  やり直さず、実時間で連続して進むようにする（そうしないと粒が進まずに見える）。
- 動きの速さ（周期）は、スピードに関係なく実時間で一定とする（スピード 0 で見やすい速さ。要望の「スピード=0 の時で考慮」「一定パターン」）。
  遅いスピード（例: -10）でも同じ速さで流れる。
- 中断中は、エフェクトも中断した時点の形で止まる（機能 014 の「表示はその時点のまま止まる」に合わせる）。再開で動き出す。
- 待機中・完了後は、エフェクトは描かない。
- 送信と受信の両方に当たる ECU は送信（赤）として扱う（今のまま）。
- エフェクトは構成図の領域の中だけに描き、枠（機能 011）・ツールバー・ログ表示エリアにはみ出さない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: フレーム表示 ON の実行中、強調されている送信 ECU と受信 ECU があるとき、送信 ECU → その接続線 → バス → 各受信 ECU の接続線 →
  受信 ECU の道筋を、光の粒が進むエフェクトを、構成図の ECU・線・バスの上に重ねて描かなければならない。
- **FR-002**: エフェクトは一定の周期（実時間）でくり返さなければならない。1 周期の中で、粒は送信 ECU から受信 ECU まで進む。周期・粒の数・
  大きさ・色はスピードに関係なく一定とする。
- **FR-003**: 送信 ECU の箱には送り出しを示す周期的な光を、受信 ECU の箱には粒が届いたことを示す光を、重ねて描かなければならない。
- **FR-004**: 送信 ECU の赤、受信 ECU の青、青い接続線・バスの強調（機能 005・016）は変えてはならない。エフェクトはその上に重ね、ECU 名が
  読めなければならない。
- **FR-005**: 強調の対象（送信・受信の ECU の集まり）は今までどおりとし、強調されていない ECU・線・バスの部分にはエフェクトを描いてはならない。
  バスが空いている書き換えではエフェクトを描いてはならない。
- **FR-006**: エフェクトの進み（粒の位置）は、書き換えのたびにやり直さず、実時間で連続して進めなければならない。
- **FR-007**: 中断中はエフェクトを止め（中断した時点の形のまま）、再開で動きを続けなければならない。待機中・フレーム表示 OFF では描いてはならない。
- **FR-008**: シミュレーションの計算・CSV・ログ表示、構成図・ログ表示エリアの位置と大きさは変えてはならない。

### Key Entities

- **流れのエフェクト**: 強調されている送信 ECU から各受信 ECU への道筋（接続線とバスの区間）と、その上を進む粒の位置（周期の中の割合）。
- **エフェクトの時計**: 実時間で進む周期の位相。中断中は止まる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: フレーム表示 ON・スピード 0 の実行中、0.1 秒おきに撮った 5 枚の画面写しで、粒の位置が送信 ECU から受信 ECU の向きへ進んでいる。
- **SC-002**: 受信しない ECU とその接続線には、粒が 1 度も描かれない（`sample_collision` の ECU 2 で、10 秒の実行の間）。
- **SC-003**: エフェクトがあっても、送信 ECU の赤・受信 ECU の青の箱の塗りの色と、ECU 名の文字が判別できる。
- **SC-004**: 中断中に 5 秒待っても、構成図の画像が変わらない。
- **SC-005**: 画面の書き換えの回数（約 40 回/秒）が、エフェクトを入れる前と比べて目に見えて落ちない（16 ECU の構成で 30 回/秒以上）。
- **SC-006**: 既存の検証（機能 001〜017）がすべて通り、シミュレーション結果（CSV）は変わらない。

## Assumptions

- 「一定パターンのアニメーション」は、実際のビットの進み（フレームの長さ）に合わせない、決まった周期のくり返しの動きとする（ユーザーの
  「スピード=0 の時で考慮して、一定パターンでいい」）。周期は 0.6 秒程度、粒は道筋 1 本につき 3 個程度とし、具体的な値は計画で決める。
- 粒の色は、強調の赤・青と区別できる明るい色（白〜黄色系）とする。
- 送信 ECU が上段で受信 ECU が下段（またはその逆）のとき、粒は送信 ECU の接続線を下り、バスを横に進み、受信 ECU の接続線を下る（上る）。
  バスの上では、送信 ECU の接続点から受信 ECU の接続点へ向かって進む（左右どちらへも）。
- エフェクトは、フレーム表示の強調と同じく、実行中（中断中を含む）のフレーム表示 ON のときだけ描く。
- 凡例・設定（エフェクトの ON/OFF）は追加しない。

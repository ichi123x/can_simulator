# Quickstart: 018 の検証

## 1. コアの検証（自動、checks.exe）

- 018 の新しい項目:
  - `FlowPhase`: 0 → 0、300,000 → 0.5、600,000 → 0、-1 → 0。値は常に 0 以上 1 未満。
  - `FlowPointAt`（6 ECU のレイアウトで、上段 → 下段・下段 → 上段・同じ段・左向き・右向きの組み合わせ）:
    - f = 0 は送信 ECU の `(LineX, LineY1)`、f = 1 は受信 ECU の `(LineX, LineY1)`。
    - f の増加で、道筋上の距離が単調に増える。
    - どの点も、送信・受信の接続線の上（x = LineX）か、バスの上（y = kBusY）にある。
  - `ComputeFlowEffect`:
    - 粒の数 = 送信の数 × 受信の数 × 3。
    - 送信・受信のどちらかが空、または `BusBusy` が偽なら、空。
    - 受信していない ECU の接続線（その x で、バスと箱の間）に粒が無い。
    - 光の強さは (0, 1]。
    - phase = 0 では、送信の光が 1 になる（粒 0 が出たところ）。
  - 性能: 16 ECU（送信 8 × 受信 8）の `ComputeFlowEffect` を 1,000 回計算して、1 秒未満。
- 既存の 001〜017 の項目がすべて PASS し、サンプルの CSV が基準と一致する。

## 2. GUI の確認（Debug|x64、サンプルは一時フォルダにコピー）

詳しい見た目は [contracts/ui-flow-effect.md](./contracts/ui-flow-effect.md) を参照。

1. `sample_collision`（フレーム表示 ON、スピード 0）を実行し、0.1 秒おきに構成図の画面写しを 5 枚撮る。
   - 粒（黄 `FFEB5A` の画素）があり、その位置が枚ごとに変わる（粒が動いている）。
   - 画面写しを並べて、送信 ECU から受信 ECU へ向かって進んでいることを目で確認する。
2. 同じ実行の 10 秒の間、0.2 秒おきに、ECU 2 の箱の外側の帯とその接続線の画素を調べる → 黄の粒・光が 1 度も無い。
3. 粒があるときの画面写しで、送信 ECU の箱の中の点が `F06E6E`、受信 ECU の箱の中の点が `A0C3F5` のまま。ECU 名が読める（目で確認）。
4. 実行中に中断し、5 秒待つ → 構成図の画像が変わらない。再開すると、粒が動き出す。
5. フレーム表示を外す → 粒・光が消える。入れる → 戻る（017 のチェックボックス）。
6. 性能: `sample_16ecu`（フレーム表示 ON・OFF、スピード 0）で、1 秒間に撮った画面写しのうち、構成図が前の 1 枚と異なる枚数を比べる → ON が OFF と同程度。
7. スピード -10 でも、粒は同じ速さ（0.6 秒で 1 周）で流れる（画面写しの粒の位置の進みが、スピード 0 と同程度）。

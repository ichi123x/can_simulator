# Research: 009

## 決定1: 表示用の行の作り方 (`CanSim/LogLines`)
- **Decision**: `BuildLogLines(rows, endNetwork, durationUs)` が `std::vector<LogLine>` を返す。`LogLine` は `{ long long TimeUs; LogLineKind Kind; int NodeId; int Index; }`。
  - 状態遷移（Kind = State）: 各ノードについて、電源投入（時刻 = `PowerOnTimeUs`、遷移後 = 初期化）、初期化完了（`InitDoneUs` が 0 以上のとき、遷移後 =
    バス同期検出）、通常動作（`NormalEntryUs` が 0 以上のとき）。`Index` に遷移後の状態（`StartupState`）。シミュレーション時間を超える時刻は含めない。
  - フレーム（Kind = Frame）: `rows` の各行。`TimeUs` = 行の `TimestampUs`、`Index` = `rows` の添字。
- **並び順**: 時刻の昇順 → 同時刻は「状態遷移が先、フレームが後」→ ノード番号の小さい順 → 元の順（安定ソート）。
- **Rationale**: 文字列を持たず 24 バイト程度なので 12 万行でも約 3 MB。時刻順にそろえておけば、再生時計に合わせて先頭から順に供給するだけで済む。
- **Alternatives**: エンジンからログ出力時に行を積む — エンジンの変更が要る。実行後の結果から作る方が影響が小さい。

## 決定2: 供給（時刻に合わせた追加）
- **Decision**: ダイアログは `m_logLines`（全行）と `m_logShown`（表示済みの本数）を持つ。機能 005 の `OnTimer` で `m_curSimUs` を求めたあと、`TimeUs ≤ m_curSimUs`
  の行までを `m_logShown` に含める（二分探索または前進）。スピード +10 と実行の完了時は、全行を表示済みにする。「終了」で止めた場合は、止めた時点までに表示済みの
  行を残す。「開始」で `m_logLines`・`m_logShown` を消して作り直す（spec FR-010）。
- **フレーム表示 OFF でも同じ**（spec FR-006）。表示エリアの再描画は、行が増えたときだけ、表示エリアの矩形だけを無効化する。

## 決定3: 描画（仮想リスト）
- **Decision**: `OnPaint`（既存の構成図描画と同じメモリ DC の流れ）に、灰色の矩形と、先頭行 `m_logTop` から `visibleRows` 行ぶんの文字を描く。文字列は
  そのときだけ組み立てる（`FormatLogLine(const LogLine&)`）。等幅フォント（`MS Gothic`）、行の高さ = フォント高 + 余白（DPI/96 でスケール）。
- **行の書式**（日本語の文字列は `.rc`）:
  - 状態: `  22 us  ECU 01  通常動作` のように「時刻 µs、ECU 番号、遷移後の状態名」。
  - フレーム: `  274 us  ECU 03 -> ECU 01  0x080  DLC 8  正常`、受信ノードなしは `ECU 03 -> -`、破棄は状態が「破棄(OVERWRITE)」で受信の記載は行のとおり。
- **Rationale**: 行の描画を見えている行だけにすれば、行数に依存しない。専用コントロールクラスや `CListCtrl` の仮想リストにするより部品が少ない。

## 決定4: スクロールバーと追従
- **Decision**: 領域の右端に `CScrollBar`（`SBS_VERT`）を置き、`SetScrollInfo`（範囲 = 全行数、ページ = 表示行数、位置 = `m_logTop`）で同期する。`OnVScroll` で
  `m_logTop` を更新して再描画。ホイール（`OnMouseWheel`、表示エリア上）は 3 行ずつ。
- **追従の判定**: 行を追加する直前に「一番下を見ているか」（`m_logTop + visibleRows ≥ 追加前の行数`）を記録し、そうなら追加後に一番下へ移す（1 行追加で 1 行スクロール、
  spec FR-007）。そうでなければ `m_logTop` を動かさない（FR-009）。スライドバーを一番下へ戻せば次の追加から追従に戻る（FR-009）。
- 行数が表示行数以下ならスクロールバーは無効（`EnableScrollBar`）。

## 決定5: 配置とダイアログ寸法
- 参考画像（125% スケールで 1440 px 幅）を 96 dpi に換算: ログ表示エリアの矩形 = 左 150、上 = 構成図の高さ（216）+ 44 = 260、幅 850、高さ 260。スクロールバーは
  矩形の右端の内側（幅 17 px）に置く。ダイアログのクライアント高さ = 260 + 260 + 下余白 40 = 560 px（約 345 DLU）。幅は変えない。
- 構成図の位置は変更しない。灰色は `RGB(230, 230, 230)`、文字は黒。
- **Alternatives**: 構成図とログ表示エリアの間にスプリッターを置く — 不要（スコープ外）。

## 決定6: 実行状態との関係
- ログ表示エリアは機能 007 のメニューの制限の対象外（実行中もスライドバーとホイールを操作できる）。実行中は「ファイル」「編集」の制限はそのまま。
- ✖ で実行中に閉じたときは何も出力しない（機能 004 と同じ）。

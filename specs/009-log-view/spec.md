# Feature Specification: ログ表示エリア

**Feature Branch**: `009-log-view`

**Created**: 2026-09-30

**Status**: Draft

**Input**: User description: "Doc\ログ表示エリアイメージ図.jpgを追加しました。CANバス構成図の下に、薄いグレーエリアを追加してください。このエリアはイベント、出力したログを表示します。イベントは、スタートアップや通常状態、エラー状態などの状態が遷移したタイミングで表示します。表示は上から下に向かって表示し、一番下の行にいったら上方向に１行スクロールします。また、表示エリアの右側にスライドバーを設置して、先頭を確認できるようにしてください。"

**参考画像**: `Doc/ログ表示エリアイメージ図.jpg`。CAN バス構成図（機能 003）の下に、構成図より少し内側の幅の薄いグレーの矩形があり、その周囲は白い。画像のクライアント領域は幅 約 1440 px（125% スケール）で、グレーの領域は左端から約 190 px、幅 約 1060 px、高さ約 320 px、構成図の最下段の ECU の箱から約 55 px 下にある。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - シミュレーション中のイベントとログを、時間の流れに沿って読む (Priority: P1)

利用者は、シミュレーションの実行中、CAN バス構成図の下のログ表示エリアに、ノードの状態が遷移したタイミング（電源投入、初期化、バス同期検出、通常動作、将来のエラー状態など）と、送信されたフレームのログが、時刻順に1行ずつ追加されていくのを読める。

**Why this priority**: 構成図の強調だけでは、どの ECU がいつ何をしたかを後から読み返せない。文字で残るログが、動作を確かめる基本の手段になる。

**Independent Test**: `sample_startup`（電源投入時刻をずらした 6 ECU）をスピード 0 で実行し、各 ECU の状態遷移とフレームの送信が、時刻順にログ表示エリアへ 1 行ずつ現れることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 起動直後（未実行）、**When** 画面を見る、**Then** CAN バス構成図の下に薄いグレーのログ表示エリアがあり、中身は空である。
2. **Given** シミュレーションを開始した、**When** ノードの状態が遷移する（電源投入、初期化完了、バス同期完了による通常動作の開始）、**Then** そのシミュレーション時刻に、ノード番号・遷移後の状態を示す行が追加される。
3. **Given** 実行中、**When** フレームの送信が完了する、**Then** そのシミュレーション時刻に、送信元 ECU・ID・DLC・状態（正常／調停負け後の再送／バッファ満杯による破棄）がわかる行が追加される。
4. **Given** 実行中、**When** 行が追加される、**Then** 追加は上から下の順（新しい行が下）で、時刻の昇順に並ぶ。
5. **Given** スピード 0、**When** 実行する、**Then** 行は、シミュレーション時刻の進みに合わせて実時間で追加されていく。スピード +10（待ちなし）では、実行が終わった時点で全行が表示されている。
6. **Given** フレーム表示が OFF、**When** 実行する、**Then** ログ表示エリアには、ON のときと同じ行が表示される（フレーム表示の設定に影響されない）。

---

### User Story 2 - 一番下まで来たら1行ずつスクロールし、スライドバーで先頭を確認する (Priority: P1)

利用者は、行数が表示エリアの高さを超えても、最新の行が常に見えるように、1 行追加されるごとに表示が 1 行ぶん上へスクロールするのを確認できる。また、表示エリアの右側のスライドバーを動かして、先頭（最初の行）まで遡って読める。

**Why this priority**: ログは数千行になるため、自動追従とさかのぼりの両方がないと、読み返せない。

**Independent Test**: 表示エリアの行数を超える量のログを出して実行し、最新の行が常に一番下に見えていること、スライドバーを一番上へ動かすと最初の行が見えることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 表示エリアがまだいっぱいでない、**When** 行が追加される、**Then** 空いている行に上から順に表示される。
2. **Given** 表示エリアの一番下の行まで埋まった、**When** 次の行が追加される、**Then** 全体が 1 行ぶん上へスクロールし、新しい行が一番下に表示される。
3. **Given** 行数が表示エリアの高さを超えている、**When** 画面を見る、**Then** 表示エリアの右側にスライドバー（縦のスクロールバー）があり、つまみの位置と大きさで全体に対する表示位置がわかる。
4. **Given** 追従表示中、**When** スライドバーのつまみを上へ動かす、**Then** 過去の行が表示され、先頭まで動かすと最初の行が一番上に見える。
5. **Given** 過去の行を見ている（つまみが一番下ではない）、**When** 新しい行が追加される、**Then** 表示位置は動かない（読んでいる行が流れない）。
6. **Given** 過去の行を見ていた、**When** つまみを一番下まで戻す（またはスライドバーの一番下へ移動する）、**Then** 以後は再び、新しい行が一番下に追従して表示される。
7. **Given** 行数が表示エリアに収まっている、**When** 画面を見る、**Then** スライドバーはつまみが動かせない状態（無効）である。

---

### User Story 3 - 新しい実行を始めるとログが入れ替わる (Priority: P2)

利用者は、実行が終わったあともログ表示エリアの内容を読み返せる。次に「開始」を選ぶと、前の実行のログは消え、新しい実行のログが最初から表示される。

**Why this priority**: 結果をあとで確認する用途と、複数回の実行の混在を防ぐ用途の両方に必要だが、US1・US2 が前提。

**Independent Test**: 実行を終えてからスライドバーで先頭まで読み返せること、もう一度「開始」すると表示が空から始まることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 実行が完了した、**When** ログ表示エリアを見る、**Then** 実行の全行が残っており、スライドバーで先頭まで読み返せる。
2. **Given** 実行が完了した、**When** 「終了」でなく完了した場合と「終了」で止めた場合、**Then** どちらも、その時点までの行が残る。
3. **Given** ログが残っている、**When** 「開始」を選ぶ、**Then** ログ表示エリアが空になり、新しい実行の行が最初から表示される。
4. **Given** プロジェクトを読み込む、またはセッティングを変更する、**When** 画面を見る、**Then** ログ表示エリアの内容はそのまま残る（次に「開始」するまで消えない）。

---

### Edge Cases

- ログの行数は実行によって数万行になり得る（例: 16 ECU のサンプルを 10 秒実行で約 12 万行。CSV と同じ単位で表示するため）。すべての行をスライドバーで読み返せるようにし、表示エリアの動作が重くならないこと。
- 行が同じ時刻に複数ある場合（例: 電源投入が同時の複数ノード）は、ノード番号の小さい順に並べる（ログの並び順の既存規則: 同時刻はノード番号順）。
- ログ表示エリアの文字は、ECU 数（0〜16）や構成図の表示には影響されない。ECU 数 0 でも表示エリアは同じ位置・大きさで存在し、状態遷移がなければ空のままである。
- シミュレーション時間が短く、電源投入前に終わる ECU がある場合は、電源投入前の行は出ない。
- 表示エリアの文字が幅を超える場合は、行の途中で折り返さず、表示エリアの幅で切る（1 行は 1 行のまま）。
- エラー状態（エラーアクティブ／パッシブ／バスオフ）は、現状のシミュレーションでは発生しないため、その行が出ることはない（将来エラー状態制御が入ったときに同じ規則で表示される）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、メインダイアログの CAN バス構成図（機能 003）の下に、薄いグレー（参考画像のグレー）の矩形のログ表示エリアを常に表示しなければならない。構成図とログ表示エリアの位置・大きさは、ECU 数によらず一定とする。
- **FR-002**: ダイアログの初期サイズは、構成図に加えてログ表示エリアが収まる大きさとしなければならない（参考画像の配置に従う）。
- **FR-003**: ログ表示エリアには、シミュレーション中のノードの状態遷移（電源投入、初期化完了、通常動作の開始、および将来のエラー状態への遷移）を、遷移したシミュレーション時刻に 1 行として表示しなければならない。行には、時刻、ノード番号、遷移後の状態が含まれること。
- **FR-004**: ログ表示エリアには、シミュレーション中に送信が完了した（または送信要求・受信がバッファ満杯で捨てられた）フレームを、出力する CSV のログと同じ単位、すなわち「1 フレーム × 受信ノード」につき 1 行（受信ノードがないフレームは送信側の情報だけで 1 行）として、その時刻に表示しなければならない。行には、時刻、送信元 ECU、受信 ECU、ID、DLC、状態（正常／調停負け後の再送／バッファ満杯による破棄）が含まれること。（2026-09-30 利用者決定）
- **FR-005**: 行は時刻の昇順（同時刻はノード番号の小さい順）に、上から下へ追加しなければならない。行の追加は、シミュレーション時刻の進みに合わせて行い（機能 005 のスピードに従う）、スピード +10 では実行の完了時にすべての行が表示されていること。
- **FR-006**: 表示は、フレーム表示（機能 004・005）の ON / OFF に影響されてはならない。
- **FR-007**: 表示エリアの一番下の行まで埋まったあとに行が追加されたら、全体を 1 行ぶん上へスクロールし、新しい行を一番下に表示しなければならない。
- **FR-008**: 表示エリアの右側に縦のスライドバーを設け、全行を先頭までさかのぼって表示できなければならない。行が表示エリアに収まっているときは、スライドバーは操作できない状態とする。
- **FR-009**: 利用者が過去の行を表示している（スライドバーが一番下にない）間は、新しい行が追加されても表示位置を動かしてはならない。スライドバーが一番下に戻ったら、以後は新しい行に追従しなければならない。
- **FR-010**: 実行が終わって（完了または「終了」）も、その時点までの行を残さなければならない。次に「開始」を選んだとき、前の実行の行をすべて消して空にしてから、新しい実行の行を表示しなければならない。プロジェクトの読込み・セッティングの変更では消してはならない。
- **FR-011**: ログ表示エリアの内容（シミュレーションのログ・イベント）は、出力される CSV（ログ・集計・起動記録）に影響してはならない。
- **FR-012**: 1 つの実行で行数が数万行になっても、追加・スクロール・スライドバー操作が実用的な速さで動作しなければならない。

### Key Entities *(include if feature involves data)*

- **ログ行**: 時刻（シミュレーション開始からの µs）、種類（状態遷移／フレーム）、ノード番号、内容（遷移後の状態、または ID・DLC・状態など）。
- **ログ表示エリア**: ログ行の一覧を、上から下へ表示する領域。表示開始位置（スライドバーの位置）と、追従中かどうかの状態を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 起動直後の画面で、構成図の下に薄いグレーのログ表示エリアが、参考画像と同じ位置関係（構成図の下、左右に余白）で見える。
- **SC-002**: `sample_startup`（6 ECU）を実行すると、各 ECU の「電源投入」「初期化完了」「通常動作」の 3 つの状態遷移（計 18 行）が、ノードの起動記録の時刻と一致する時刻で表示される。
- **SC-003**: 実行中に追加された行数がログ表示エリアの高さを超えても、追従表示のとき、最新の行が常に一番下に見える。
- **SC-004**: 実行後にスライドバーを一番上に動かすと、最初の行（最初の状態遷移）が見える。
- **SC-005**: 過去の行を表示している間に 10 行以上が追加されても、表示位置は動かない。
- **SC-006**: 2 回目の「開始」で、1 回目の行が残らず、2 回目の実行の最初の行が表示エリアの一番上に表示される。
- **SC-007**: 約 12 万行のログがある状態で、スライドバーの操作の反応が体感で遅れない（1 操作あたり 0.2 秒未満）。
- **SC-008**: ログ表示エリアの有無・内容にかかわらず、同一構成の実行結果（3 種の CSV）が完全に一致する。

## Assumptions

- ログ表示エリアは、実行のたびに新しいログで入れ替わる、閲覧専用の領域とする。利用者が文字を選択・コピー・編集する機能、行の絞り込み・検索は本機能のスコープ外。
- 状態遷移として表示する状態は、機能 002 の起動制御の 3 つの遷移（電源投入＝初期化状態へ、初期化完了＝バス同期検出へ、通常動作の開始）と、将来のエラー状態への遷移とする。通常動作から他の状態へ戻る遷移は、現状のシミュレーションにはない。
- 行の表示文字列（状態名、ラベル）は日本語とし、リソース側で管理する。時刻は µs で表示する。
- 実行中は、ダイアログの再描画のたびに全行を描き直さず、見えている範囲だけを描く（行数が多くても軽く動かすための実装方針は plan で決める）。
- ログ表示エリアは機能 007 の「実行中にファイル・編集メニューが使えない」の対象外で、実行中も（スライドバーの操作を含めて）操作できる。
- ログ表示エリアの位置と大きさは参考画像に合わせる: ダイアログのクライアント幅に対して、左右に均等な余白を持つ矩形（幅は構成図の約 75%）。

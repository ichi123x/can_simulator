# Quickstart: 005 の検証

## 1. コアの検証（自動）
CLAUDE.md の手順で `checks.exe` をビルド・実行する。追加項目:
- `Speed` の読込み（省略時 0、`+3`/`-3`/`10`/`-13` の受理、`11`/`-14`/`1.5`/`abc` の拒否）と保存→再読込み
- `SimTimeAtUs`（0 → 等倍、+1 → 2 倍、-1 → 1/2、-10 → 1/1024、-13 → 1/8192、+9 → 512 倍）
- `ActiveFrameCursor`（区間内の複数フレームの送信元・受信者の集約、送信優先、空き区間で強調なし、区間を細かく刻んでも粗く刻んでも全フレームが少なくとも 1 回は対象になる）
- 既存の 001〜004 の項目がすべて PASS のまま

## 2. GUI の確認（Debug|x64、サンプルは一時フォルダにコピーして使う）
1. セッティングにスピード欄があり、+10〜-13 の 24 項目・初期値 0（US1 AS3、US2 AS1）。
2. `sample_appendix_a.canprj`、スピード 0、10 秒、フレーム表示 OFF で開始 → 完了通知まで 9〜11 秒（SC-001）。実行中は「セッティング」「開始」「読込み」がグレー、「終了」が選べる（SC-007）。
3. 同じ構成でスピード +1 / -1 / +3 / +10 の所要時間を測る（SC-002, SC-003）。
4. スピード 0・フレーム表示 ON・`sample_appendix_a` → 強調が途切れずに見える（SC-009）。空き時間に強調が消えること（US1 AS2）は、フレームがまばらな `sample_16ecu.canprj`（各 ECU 20 ms 周期）で確認する。所要時間が OFF と 1 秒以内の差（SC-006）。
5. スピード -13・フレーム表示 ON・`sample_16ecu.canprj` → 1 フレームの強調が 0.2 秒以上（8 バイト・500 kbps で約 2 秒）続く（SC-004）。通信速度 1 Mbps でも 0.2 秒以上続くことを確認する。途中で「終了」→ その時点までの結果が出る（SC-008）。
6. 手順 2〜4 の CSV を、スピード +10 の CSV と比較して完全一致（SC-005）。

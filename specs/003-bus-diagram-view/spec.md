# Feature Specification: CAN バス構成図の表示（ダイアログ表示部）

**Feature Branch**: `003-bus-diagram-view`

**Created**: 2026-09-29

**Status**: Draft

**Input**: User description: "ダイアログの表示部は白とする。ダイアログボックスの初期表示サイズは、Doc フォルダの『CANバスイメージ(最大時 ECU=16).jpg』を参考に、全ECU 16個がすべて表示されるサイズにする。ECU が0個の場合は ECU を表示せず CAN バスだけを表示する（『CANバスイメージ(最小時 ECU=0).jpg』を参考）。"

**Scope note**: 本機能は「現在の ECU 数を CAN バス構成図として描く表示部品」に絞る。ECU 数の入力手段（セッティング画面・プロジェクト読込み）、メニュー、既存コントロールの削除、ダイアログ全体の白化、起動直後の ECU 数の初期値は機能 004（`specs/004-menu-project-settings/`）が定める。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 現在の ECU 数どおりに CAN バス構成図を見る (Priority: P1)

利用者は、メインダイアログの表示部で、CAN バスを表す太い水平線と、バスにぶら下がる ECU を図として確認できる。表示される ECU の数は、現在の ECU 数（機能 004 のセッティングまたはプロジェクトで決まる値）と一致する。

**Why this priority**: 構成図の表示そのものが本機能の中核であり、初期サイズと0個時の表示はこの図の描画が存在して初めて意味を持つ。

**Independent Test**: ECU 数を変えながら（3、6、16 など）、表示される ECU の個数・ラベル・配置がECU 数と一致することを目視で確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** ECU 数が 16 の状態、**When** ダイアログを表示する、**Then** 「CAN BUS」の見出しと水平のバス線が表示され、「ECU 01」〜「ECU 16」の16個すべてがバス線に接続された形で表示される。
2. **Given** 参考画像（最大時）と同じ並び、**When** 表示を確認する、**Then** 奇数番号の ECU はバス線の上側、偶数番号の ECU は下側に交互に並び、番号順に左から右へ進む。
3. **Given** ECU 数が 6 の状態、**When** 表示を確認する、**Then** 「ECU 01」〜「ECU 06」の6個だけが表示され、存在しない ECU は表示されない。
4. **Given** 表示を確認する、**When** 「CAN BUS」の見出しと ECU 01 を見る、**Then** 見出しの文字はECU からバス線に向かう接続線と重ならず、バス線の左右両端には ECU を置かない余裕がある。

---

### User Story 2 - 初期表示で全16 ECU が見切れずに収まる (Priority: P1)

利用者は、アプリケーションを起動した直後の大きさのままで、最大数（16個）の ECU がすべて欠けずに見える。ウィンドウの大きさを変える操作や、スクロールは不要である。

**Why this priority**: 最大構成が初期サイズで収まらないと、図の確認のために毎回サイズ変更が必要となり、表示機能の価値が損なわれる。

**Independent Test**: ECU 数を 16 にし、ダイアログを起動直後のサイズのまま表示して、16個すべてのECU ラベルが欠けず・重ならずに見えることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** アプリケーションを起動した直後の初期サイズ、**When** ECU 数が 16 である、**Then** 16個すべての ECU が表示領域内に収まり、ラベル文字が切れたり隣の ECU と重なったりしない。
2. **Given** 初期サイズ、**When** 表示を確認する、**Then** 横に長い参考画像と同様に、バス線が表示領域の左右ほぼ全幅に渡って引かれる。

---

### User Story 3 - ECU が0個のときはバスだけを表示する (Priority: P2)

利用者は、ECU 数が 0 のとき、ECU が一切なく CAN バスだけが表示された図を見る。

**Why this priority**: ECU がない状態を空白や異常表示にしないために必要。図の描画（US1）が前提。

**Independent Test**: ECU 数を 0 にして、「CAN BUS」の見出しとバス線のみが表示され、ECU が1つも表示されていないことを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** ECU 数が 0 の状態、**When** ダイアログを表示する、**Then** 「CAN BUS」の見出しとバス線のみが表示され、ECU および ECU への接続線は1つも表示されない。
2. **Given** ECU 数が 0 から 1 以上に変わった、**When** 表示を確認する、**Then** 変わった数の ECU が表示される。逆に 1 以上から 0 に変わったときは、ECU がすべて消えバスだけになる。

---

### Edge Cases

- ECU 数が 1〜15 のとき、ECU は番号順に左から詰めて配置され、16 ECU 時と同じ間隔・大きさで表示される（ECU 数に応じて拡大縮小しない）。
- ECU 数の変更がキャンセルされた、または失敗した場合は、直前に表示していた構成図を維持する（図を壊さない）。
- ECU 数が 17 以上になることは機能 004 のセッティングで防がれるため、17個目以降の表示は考慮しない。
- ダイアログの大きさをユーザーが変更した場合の再配置は本機能では規定しない（Assumptions 参照）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、メインダイアログの構成図の表示部の背景を白で表示しなければならない。
- **FR-002**: システムは、表示部に「CAN BUS」の見出しと、CAN バスを表す太い水平線を常に表示しなければならない。
- **FR-003**: システムは、現在の ECU 数と同数の ECU を、「ECU NN」（NN は2桁の番号）のラベル付きで表示しなければならない。
- **FR-004**: システムは、各 ECU をバス線と接続線で結んで表示しなければならない。
- **FR-005**: システムは、奇数番号の ECU をバス線の上側、偶数番号の ECU を下側に配置し、番号の順に左から右へ並べなければならない。
- **FR-006**: システムは、上側の ECU と下側の ECU を、参考画像と同様に区別できる見た目（異なる色合い）で表示しなければならない。
- **FR-007**: システムは、ECU の数が0個のとき ECU と接続線を一切表示せず、見出しとバス線のみを表示しなければならない。
- **FR-008**: システムは、アプリケーション起動直後（ダイアログの初期表示サイズ）の状態で、最大数16個のすべての ECU をラベルの欠けや重なりなく表示できる大きさでダイアログを表示しなければならない。
- **FR-009**: システムは、ECU の表示位置・大きさ・間隔を ECU 数によらず一定とし、ECU 数が変わっても既に表示されている ECU の位置を変えてはならない。
- **FR-010**: システムは、ECU 数が変更された時点で、表示をその ECU 数に更新しなければならない。変更がキャンセルまたは失敗した場合は、表示を変更してはならない。
- **FR-011**: システムは、バス線の左右両端に余裕を空けて ECU を配置し、見出し「CAN BUS」の文字がECU からバス線に向かう接続線と重ならないようにしなければならない。

### Key Entities *(include if feature involves data)*

- **構成図**: バス見出し・バス線・ECU 群からなる表示内容。ECU の個数は現在の ECU 数で決まる。
- **ECU 表示要素**: 番号ラベル、バス線との接続線、バス線に対する配置側（上／下）を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 起動直後の初期サイズで、ECU 数が 16 のとき、16個すべての ECU ラベルが欠けず・重ならずに目視で確認できる（スクロール・サイズ変更の操作は0回）。
- **SC-002**: 1〜16 の任意の ECU 数で、表示される ECU の個数が常に ECU 数と一致する（全ケースで一致）。
- **SC-003**: ECU 数が 0 のとき、ECU が1つも表示されない。
- **SC-004**: 表示部の背景色が、ECU の有無・個数にかかわらず常に白である。
- **SC-005**: 参考画像（最大時）と見比べたとき、上下の交互配置、番号順、バス線への接続という構成が一致していると利用者が判断できる。
- **SC-006**: 見出し「CAN BUS」の文字と、ECU からバス線に向かう接続線が、ECU 数が 1〜16 のいずれのときも重ならない。

## Assumptions

- 本機能は表示部品のみを扱う。ECU 数の値は、ダイアログが保持する「現在の ECU 数」として与えられ、その設定・変更・初期値（機能 004 では 2）・読み込みは機能 004 が担う。
- ECU のラベルは番号のみ（「ECU 01」形式）とする。ノードの名称や送信状況・起動状態の表示は本機能のスコープ外（送受信の強調表示は機能 004）。
- 参考画像は横長（約5:1）であるため、初期表示サイズも横長とする。具体的なピクセル寸法はresearch.md で確定する。
- ダイアログの大きさを利用者が変更した際の拡大縮小・再配置は行わない（初期サイズの固定を前提とする）。
- 表示部の白は、システムのテーマ（ダークモード等）に依存せず常に白とする。ダイアログ全体の白化は機能 004 が定める。
- 画面表示に関する文字列（「CAN BUS」「ECU NN」）は英字とし、UI 側のリソース化はしない。

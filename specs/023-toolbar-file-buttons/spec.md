# Feature Specification: ツールバーへのプロジェクト読込み・保存ボタンの追加

**Feature Branch**: `ver.0.4`（spec ディレクトリ: `023-toolbar-file-buttons`）

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "シミュレーションアイコンの前に、プロジェクト保存とプロジェクト読込みアイコンを追加する。保存ボタンを押下したときにプロジェクトファイルがない場合、保存処理を行う。読込みボタンを押下したときは、読込み処理を行う。"（確認の回答: Q1 = プロジェクトファイルがあれば尋ねずに上書き、無ければ保存先を尋ねる。Q2 = B（保存 → 読込み）、ただし保存・読込みと開始・中断・終了の間にアイコン 1 つ分の空きを置く）

**前提となる機能**: 機能 004（プロジェクト読込み・保存）、007（実行中のメニューのロック）、010（編集ウィンドウとの関係）、014（ツールバーのボタン）、019（ツールバーの並びと大きさ）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ツールバーからプロジェクトを保存する (Priority: P1)

ユーザーはツールバーの「保存」ボタンを押して、今のプロジェクト（設定・ECU ラベル名・データフレーム一覧・フレーム表示・スピード）を
ファイルに保存する。まだプロジェクトファイルが無い（一度も読込み・保存していない）ときは、保存先を尋ねてから保存する。

**Why this priority**: 編集した内容を失わないための操作で、メニューを開く手間を省く効果が最も大きい。

**Independent Test**: 起動直後に「保存」ボタンを押し、保存先を指定して保存されたファイルを読み込み直し、内容が一致することを確かめる。

**Acceptance Scenarios**:

1. **Given** プロジェクトファイルが無い（起動直後）、**When** 「保存」ボタンを押す、**Then** 保存先を尋ねる画面が開き、指定したファイルに今のプロジェクトが保存される。
   以後、そのファイルが現在のプロジェクトファイルになる。
2. **Given** 1 で保存先を尋ねる画面、**When** キャンセルする、**Then** 何も保存されず、プロジェクトファイルは無いままになる。
3. **Given** プロジェクトファイルがある（読込み・保存済み）、**When** 「保存」ボタンを押す、**Then** 保存先を尋ねず、確認も出さずに、そのファイルへ今のプロジェクトを上書き保存する（Q1）。
4. **Given** 保存先に書き込めない、**When** 保存する、**Then** メニューからの保存と同じエラーメッセージを表示し、現在のプロジェクトファイルは変わらない。

---

### User Story 2 - ツールバーからプロジェクトを読み込む (Priority: P1)

ユーザーはツールバーの「読込み」ボタンを押して、メニューの「プロジェクト読込み」と同じ手順でプロジェクトファイルを読み込む。

**Why this priority**: 保存と対になる基本操作で、要望に明記されている。

**Independent Test**: 「読込み」ボタンからサンプルプロジェクトを読み込み、構成図の ECU 数・ラベル名、フレーム表示のチェック、スピードのつまみが
ファイルの内容に変わることを確かめる。

**Acceptance Scenarios**:

1. **Given** 待機中、**When** 「読込み」ボタンを押す、**Then** ファイルを選ぶ画面が開き、選んだプロジェクトがメニューからの読込みと同じように反映される。
2. **Given** ファイルを選ぶ画面、**When** キャンセルする、**Then** 今のプロジェクトは何も変わらない。
3. **Given** 不正な内容・拡張子のファイル、**When** 読み込む、**Then** メニューからの読込みと同じエラーメッセージを表示し、今のプロジェクトは変わらない。
4. **Given** データフレーム編集ウィンドウが開いている（または切り替えの待ち）、**When** 「読込み」ボタンを押す、**Then** メニューからの読込みと同じく、
   先に編集ウィンドウを閉じて（待ちも取り消して）から読込みを行う。

---

### User Story 3 - 実行中は押せない (Priority: P2)

シミュレーションの実行中・中断中は、メニューの「ファイル」と同じく、「読込み」「保存」ボタンは無効（グレー）で、押しても何も起きない。

**Why this priority**: 実行中にプロジェクトが差し替わると再生と結果が食い違うため。既存の規則（機能 007・014）をボタンにも揃える。

**Independent Test**: 実行中・中断中にボタンがグレーで、押しても画面が開かないこと、待機に戻ると押せることを確かめる。

**Acceptance Scenarios**:

1. **Given** 実行中または中断中、**When** ツールバーを見る、**Then** 「読込み」「保存」はグレーで表示される。
2. **Given** 同じとき、**When** ボタンを押す、**Then** 何も起きない。
3. **Given** 自然終了・「終了」・即時完了で待機に戻った、**When** ツールバーを見る、**Then** 「読込み」「保存」は押せる表示に戻る。

### Edge Cases

- 編集ウィンドウを開いたまま「保存」ボタンを押したときは、閉じずにそのまま保存できる（メニューからの保存と同じ）。
- 追加・編集の入力画面や削除確認を表示している間は、メインウィンドウが無効なのでボタンも押せない（既存の動作のまま）。
- ボタンを押したまま別のボタンの上で離したときは、どちらの操作も行わない（機能 014 のボタンと同じ）。
- 読込み・保存を行っても、ログ表示エリアの行は消さない（機能 009 のまま）。
- ツールバーの帯の高さ、構成図・ログ表示エリアの位置、ウィンドウの大きさは変えない。すでにある部品はすべて右へずらし、どの DPI（96/120/144）でも
  重ならずにウィンドウの幅に収まる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ツールバーの左端、開始ボタンの前に「保存」「読込み」の 2 つのボタンを追加しなければならない。並びは左から
  保存 → 読込み →（ボタン 1 つ分の空き）→ 開始 → 中断 → 終了 とする（Q2）。
- **FR-002**: 2 つのボタンは、開始・中断・終了のボタンと同じ大きさ・形（箱と記号、下に名前）でなければならない。読込みと開始の間の空きは、
  ボタン 1 つ分の間隔（隣り合うボタンどうしの左端の間隔と同じ幅）とする。
- **FR-003**: 「読込み」ボタンは、メニューの「ファイル → プロジェクト読込み」と同じ処理（編集ウィンドウを閉じる・ファイル選択・検査・エラー表示・反映）を行わなければならない。
- **FR-004**: 「保存」ボタンは、プロジェクトファイルが無いときは保存先を尋ねてから保存し、成功したらそのファイルを現在のプロジェクトファイルにしなければならない。
- **FR-005**: 「保存」ボタンは、プロジェクトファイルがあるときは保存先を尋ねず、確認も出さずに、そのファイルへ上書き保存しなければならない。
  上書きに失敗したときはエラーメッセージを表示し、現在のプロジェクトファイルは変えない。
- **FR-006**: 2 つのボタンは、実行中・中断中は無効（グレー）にし、押しても何もしてはならない。待機中は（編集ウィンドウが開いていても）有効にする。
- **FR-007**: ボタンの押し方（押して同じボタンの上で離したときだけ動く）・押下中の見た目は、機能 014 のボタンと同じでなければならない。
- **FR-008**: メニューの「ファイル」の項目と動作、シミュレーションのボタン・チェックボックス・シミュレーション時間・スピードスライダーの動作、
  プロジェクトファイルの形式、計算・CSV は変えてはならない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: プロジェクトファイルが無い状態から、「保存」ボタンを 1 回押して保存先を指定するだけで保存でき、読み込み直した内容が保存前と一致する。
- **SC-002**: 「読込み」ボタンで読み込んだ結果（ECU 数・ラベル名・フレーム一覧・フレーム表示・スピード・シミュレーション時間・通信速度）が、メニューから読み込んだ結果と一致する。
- **SC-003**: 実行中・中断中の 100% の押下で、読込み・保存の画面が開かない。
- **SC-004**: ツールバーの部品がすべて重ならずに帯とウィンドウの幅に収まる（DPI 96/120/144）。
- **SC-005**: 既存の検証（機能 001〜011・014・015・017〜020・022）がすべて通り、シミュレーション結果（CSV）は変わらない。

## Assumptions

- 「プロジェクトファイルがない」は、起動後に一度も読込み・保存に成功していない状態（現在のプロジェクトファイルが決まっていない状態）を指す。
  決まっていたファイルが後から外部で消された場合は、決まっている状態として扱う（上書き保存なら作り直す）。
- ボタンの名前は「読込み」「保存」とし、日本語の文字列として `.rc` の文字列テーブルに置く。記号はフォルダー（読込み）・フロッピー風の四角（保存）程度の簡単な図形で、
  色はシミュレーションのボタンと区別できるものにする。
- 「シミュレーションアイコン」は、ツールバーの開始・中断・終了のボタンを指す。
- メニューの「ファイル → プロジェクト保存」は今までどおり毎回保存先を尋ねる（名前を付けて保存の役割として残す）。上書き保存はツールバーの「保存」ボタンだけの動作とする。
- 「開始」でプロジェクトファイルが無いときに保存先を尋ねる動作（機能 004）は変えない。
- キーボードのショートカット（Ctrl+S など）は今回の範囲に含めない。

## 改訂 1（2026-10-02、実装後の確認を受けて）

ユーザーが quickstart の手動確認を行い、2 点の改善を求めた（この節が上の記述に優先する）。

- **A. チェックボックスの高さ**（FR-002 に追加）: フレーム表示のチェックボックス（箱と「フレーム表示」の文字）の縦の位置を、
  左の終了ボタンの箱と揃える。箱の縦の中心を終了ボタンの箱の縦の中心（96 dpi で y 23）に合わせ、文字も同じ中心に置く。
  横の位置・押せる範囲・動作は変えない。
- **B. 読み取り専用の保存の失敗**（US1-4・FR-004/005 に追加）: 保存先のファイルが読み取り専用のために保存できなかったときは、
  プロジェクトファイル名を示し、読み取り専用のため保存できなかったこと（と、読み取り専用を外せば保存できること）を伝えるメッセージを出す。
  それ以外の理由の失敗は、今までどおりの保存エラーのメッセージ。どちらの場合も現在のプロジェクトファイルは変えない。
  メニューの「プロジェクト保存」と「開始」の保存先確認でも、同じメッセージにする（保存の処理は共通）。
- 変えないもの: ボタンの並び・大きさ、保存・読込みの動作、シミュレーション結果（CSV）。

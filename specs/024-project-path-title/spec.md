# Feature Specification: プロジェクトファイル名の表示と関連付けからの起動

**Feature Branch**: `ver.0.5`（spec ディレクトリ: `024-project-path-title`）

**Created**: 2026-10-02

**Status**: Draft

**Input**: User description: "現在、読み込んでいるプロジェクトファイル名をユーザーに通知する仕様を追加します。アプリのタイトルであるCAN Bus Simulatorと同じラインの”プロジェクトファイル名：”のラベルを付けて、ラベルの右に現在、読み込んでいる又は、保存したプロジェクト名をフルパスで表示して、ユーザーがわかるようにする。アプリ単体で起動時した場合は、.canprjプロジェクトファイルがリードされた状態ではないので、当然、プロジェクトファイルのフルパスは空白となる。.canprjプロジェクトファイルを関連付けで起動した場合、アプリ起動時に引数パラメータとして、.canprjプロジェクトファイルが添付されているはずなので、そのプロジェクトを読み込んで、プルパスで表示する。"（確認の回答: Q1 = A（関連付けの登録はユーザーが Windows で行い、アプリは引数を読むだけ））

**前提となる機能**: 機能 004（プロジェクト読込み・保存、「開始」時の保存先確認）、010（編集ウィンドウ）、023（ツールバーの保存・読込み、`SaveProjectTo` による現在のプロジェクトファイルの更新）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 今どのプロジェクトファイルを使っているかがわかる (Priority: P1)

ユーザーは、アプリのタイトル「CAN Bus Simulator」と同じ行（ウィンドウのタイトルバー）を見るだけで、今使っているプロジェクトファイルをフルパスで知ることができる。
タイトルの後ろに「プロジェクト名：」のラベルがあり、その右にフルパスが出る。読込み・保存でプロジェクトファイルが変わると、表示もすぐに変わる。

**Why this priority**: 機能 023 でツールバーの「保存」が尋ねずに上書きするようになったため、どのファイルに上書きされるのかが見えることが要望の中心である。

**Independent Test**: アプリを単体で起動してタイトルバーを見る → プロジェクトを読み込む → 別名で保存する、の各時点でタイトルバーの表示を確かめる。

**Acceptance Scenarios**:

1. **Given** アプリを単体で（引数なしで）起動した直後、**When** タイトルバーを見る、**Then** 「CAN Bus Simulator」の右に「プロジェクト名：」のラベルがあり、その右は空白である。
2. **Given** 起動直後、**When** 「読込み」（ツールバー・メニューのどちらでも）で `C:\work\a.canprj` を読み込む、**Then** ラベルの右に `C:\work\a.canprj` と表示される。
3. **Given** `a.canprj` を読み込んだ状態、**When** メニューの「プロジェクト保存」で `C:\work\b.canprj` に保存する、**Then** 表示は `C:\work\b.canprj` に変わる。
4. **Given** 起動直後（プロジェクトファイルなし）、**When** ツールバーの「保存」または「開始」で保存先を尋ねられ、`C:\work\c.canprj` に保存する、**Then** 表示は `C:\work\c.canprj` になる。
5. **Given** `a.canprj` を表示している状態、**When** 読込みをキャンセルする・読込みが失敗する・保存をキャンセルする・保存が失敗する、**Then** 表示は `a.canprj` のまま変わらない。

---

### User Story 2 - .canprj ファイルから直接アプリを開く (Priority: P1)

ユーザーがエクスプローラーで .canprj ファイルを開く（ダブルクリック・関連付けによる起動）と、アプリはそのファイルを起動時に読み込み、構成図などを読み込んだ内容で表示し、タイトルバーにそのファイルのフルパスを表示する。

**Why this priority**: 要望に明記された動作であり、読み込みの手間を省く。表示（US1）と合わせて、どのファイルを開いたのかがすぐにわかる。

**Independent Test**: コマンドラインからアプリの exe に .canprj ファイルのパスを渡して起動し、読み込まれた内容とタイトルバーの表示を確かめる（関連付けによる起動と同じ形の起動）。

**Acceptance Scenarios**:

1. **Given** `sample_16ecu.canprj` を引数にしてアプリを起動する、**When** 起動が終わる、**Then** 構成図は 16 ECU で、セッティング・スピード・フレーム表示もファイルの内容になっており、タイトルバーにそのファイルのフルパスが出る。メニューから同じファイルを読み込んだ場合と同じ状態である。
2. **Given** 引数のファイルが相対パス・短いパス（8.3 形式）・引用符付きのパスで渡された、**When** 起動する、**Then** 読み込みは成功し、表示は絶対パスのフルパスになる。
3. **Given** 引数のファイルを読み込んで起動した、**When** ツールバーの「保存」を押す、**Then** 尋ねずにそのファイルへ上書き保存される（機能 023 の「プロジェクトファイルがある」状態）。
4. **Given** 引数のファイルが存在しない・拡張子が .canprj でない・内容が不正、**When** 起動する、**Then** メニューからの読込みと同じエラーメッセージが出たうえで、アプリは単体起動と同じ状態（既定のプロジェクト、表示は空白）で使える。

---

### Edge Cases

- パスが長くタイトルバーに収まらない場合: 表示しきれない部分が省略されてもよいが、記録しているパスは省略しない（ウィンドウの幅を広げれば見える）。
- 実行中・中断中: プロジェクトファイルは変わらないので表示も変わらない（読込み・保存は実行中は行えない）。
- 外部でファイルが削除・移動された場合: 表示は最後に読み込んだ・保存したパスのまま（機能 023 の Assumptions と同じく、「プロジェクトファイルがある」状態として扱う）。
- 引数が 2 つ以上ある場合（複数の .canprj を選んで開いた等）: 最初の 1 つだけを読み込む。
- タスクバーのボタンや Alt+Tab の一覧にもタイトルと同じ文字列が出てよい。
- アプリがすでに起動しているときに別の .canprj を開いた場合: 新しいウィンドウ（別のアプリ）として起動し、そのファイルを読み込む。起動済みのウィンドウには影響しない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ウィンドウのタイトルは「CAN Bus Simulator」の後ろに区切りを置き、「プロジェクト名：」のラベル、続けて現在のプロジェクトファイルのフルパスを表示しなければならない。
- **FR-002**: プロジェクトファイルが決まっていないとき（単体起動の直後、引数の読込みに失敗したとき）は、ラベルを表示し、パスの部分は空白にしなければならない。
- **FR-003**: プロジェクトの読込み（メニュー・ツールバー・起動時の引数）、保存（メニューの「プロジェクト保存」・ツールバーの「保存」・「開始」時の保存先確認）が成功したときは、そのたびに表示を新しいフルパスへ更新しなければならない。
- **FR-004**: 読込み・保存のキャンセル・失敗では、表示を変えてはならない（現在のプロジェクトファイルは変わらないため）。
- **FR-005**: アプリは起動時のコマンドライン引数に .canprj ファイルのパスがあれば、そのファイルを読み込まなければならない。読込みの検査（拡張子・内容）・エラー表示・読み込み後の状態は、メニューの「プロジェクト読込み」と同じでなければならない。
- **FR-006**: 起動時の引数の読込みに失敗した場合は、エラーメッセージを出したうえで、単体起動と同じ状態で起動を続けなければならない（アプリを終了してはならない）。
- **FR-007**: 表示するパスは、引数・ファイル選択のどちらで指定された場合も、絶対パスのフルパスでなければならない。
- **FR-008**: アプリは .canprj の関連付けを登録してはならない（レジストリに書き込まない）。関連付けは、ユーザーが Windows の「プログラムから開く」→「常にこのアプリを使う」などで設定し、アプリは起動時の引数を受け取って読み込むだけとする（確認の回答 Q1 = A）。
- **FR-009**: 既存の動作（読込み・保存・ツールバー・シミュレーション・CSV の出力先）は変えてはならない。

### Key Entities

- **現在のプロジェクトファイル**: 最後に読込み・保存に成功したプロジェクトファイルの絶対パス。無い（空）こともある。機能 023 の上書き保存の保存先・「開始」時の CSV の出力先の基準と同じもの。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 読込み・保存の成功の 100% で、操作の直後にタイトルバーの表示がそのファイルのフルパスになっている。
- **SC-002**: 読込み・保存のキャンセル・失敗の 100% で、タイトルバーの表示が変わらない。
- **SC-003**: .canprj ファイルを開いて起動したとき、追加の操作なしに、メニューから同じファイルを読み込んだ場合と同じ内容（ECU 数・ラベル名・フレーム一覧・セッティング・スピード・フレーム表示）とフルパスの表示になる。
- **SC-004**: 単体起動の直後は、タイトルバーにラベルだけが出て、パスは空白である。
- **SC-005**: 既存の検証（機能 001〜011・014・015・017〜020・022・023）がすべて通り、シミュレーション結果（CSV）は変わらない。

## Assumptions

- 「アプリのタイトルである CAN Bus Simulator と同じライン」は、ウィンドウのタイトルバー（今は「CAN Bus Simulator」とだけ表示している行）を指す。タイトルバーの中にラベルとパスを続けて表示する。
- 表示の形は「CAN Bus Simulator　　プロジェクト名：C:\…\x.canprj」とする（タイトルとラベルの間は空白で区切る）。ラベルの文字列は `.rc` の文字列テーブルに置く。
- 「保存したプロジェクト名」は、保存に成功して現在のプロジェクトファイルになったファイルを指す（機能 023 の `SaveProjectTo` で現在のプロジェクトファイルが変わる操作と同じ）。
- 起動時の引数で読み込む場合も、拡張子 .canprj の検査はメニューからの読込みと同じに行う。
- 編集中の未保存の変更の有無（「*」などの印）は、今回の範囲に含めない。
- 起動時の引数の処理は、関連付けによる起動とコマンドラインからの起動（`MFCApplication1.exe <パス>`）で同じとする。
- 関連付けの登録・解除（アプリ自身によるもの、インストーラー）は今回の範囲に含めない。

## 改訂 1（2026-10-02、実装後の確認を受けて）

ユーザーの指示により、ラベルを「プロジェクトファイル名：」から「プロジェクト名：」に短くする（上の記述は改訂後の文字列に揃えた。Input はユーザーの原文のまま）。
表示するパス（フルパス）・更新の条件・起動時の引数の動作は変えない。

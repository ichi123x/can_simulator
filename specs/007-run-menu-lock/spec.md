# Feature Specification: 実行中のメニュー制限と、インターミッション後のバスアイドル

**Feature Branch**: `007-run-menu-lock`

**Created**: 2026-09-30

**Status**: Draft

**Input**: User description: "・シミュレーション実行中はファイル・編集メニューは非アクティブとして編集できないようにする。シミュレーションを実施していない場合は、ファイル・編集メニューをアクティブにして選択可能とする。・データフレームは、SOF～EOFだが、データフレームとは関係ないがCANのシステムとしてEOF後のITM=3ビットのレセシブを考慮した時間を踏まえて、バスアイドル状態となる。"

**Relation to earlier features**: 機能 004・005 では、実行中も「プロジェクト保存」と「フレーム表示」の切替ができた。本機能では、実行中は「ファイル」「編集」のメニュー全体を選べなくする（005 FR-007・US3 AS3 の「実行中のフレーム表示の切替」を廃止）。2 点目（EOF 後のインターミッション 3 ビットを経てバスアイドル）は、機能 001 で既に実装されている（Doc FR-022）ため、本機能では仕様として明文化し、検証を加える。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 実行中はファイル・編集メニューを操作できない (Priority: P1)

利用者がシミュレーションを開始すると、メニューバーの「ファイル」「編集」は選べない状態（グレー表示）になり、プロジェクトの読込み・保存、セッティング、データフレーム編集、フレーム表示の切替のいずれもできない。シミュレーションが終わる（完了または「終了」）と、「ファイル」「編集」は再び選べるようになる。

**Why this priority**: 実行中に構成や表示が変わると、得られる結果と画面の意味が曖昧になる。実行中に触れる操作を「シミュレーション → 終了」だけに絞ることで、誤操作を防ぐ。

**Independent Test**: スピード 0 で 10 秒のシミュレーションを開始し、実行中に「ファイル」「編集」がグレーで開けないこと、完了後に開けることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** シミュレーションを実行していない、**When** メニューバーを見る、**Then** 「ファイル」「編集」「シミュレーション」の3 つとも選べる。
2. **Given** シミュレーションの実行中、**When** メニューバーを見る、**Then** 「ファイル」「編集」はグレー表示で、クリックしてもAlt+F / Alt+E を押しても開かない。「シミュレーション」は開けて、「開始」はグレー、「終了」は選べる。
3. **Given** 実行中、**When** シミュレーションが完了する、または「終了」を選ぶ、**Then** 「ファイル」「編集」は選べる状態に戻る。
4. **Given** フレーム表示 ON で実行中、**When** 画面を見る、**Then** 強調表示は続く（フレーム表示の設定は開始時の値のまま変わらない）。

---

### User Story 2 - フレームの後に必ずインターミッションを置いてからバスアイドルになる (Priority: P2)

利用者は、1 つのデータフレーム（SOF〜EOF）の送信が終わったあと、CAN のシステムとして EOF の後にインターミッション（ITM、3 ビットのレセシブ）の時間が経過してから、バスがアイドル状態になり、次のフレームの送信（SOF）が始まることを、ログで確認できる。

**Why this priority**: CAN の実挙動に沿ったバスの時間配分であり、送信待ち遅延やバス負荷の評価の前提になる。機能 001 で実装済みのため、明文化と検証が中心で P2。

**Independent Test**: 2 つのノードが同時に送信要求する構成（`sample_collision`）を実行し、連続する 2 フレームについて、後のフレームの送信開始時刻 − 前のフレームの送信終了時刻 = 3 ビット時間（500 kbps で 6 µs）であることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 送信待ちのフレームがある状態でフレームの送信が終わった、**When** 次のフレームの送信開始時刻を見る、**Then**前のフレームの EOF の終わりから、ちょうど 3 ビット時間後である（125 kbps で 24 µs、250 kbps で 12 µs、500 kbps で 6 µs、1 Mbps で 3 µs）。
2. **Given** 送信待ちのフレームがない状態でフレームの送信が終わった、**When** 3 ビット時間が経過する前に新しい送信要求が発生した、**Then** そのフレームはインターミッションの終わりを待ってから送信を開始する。
3. **Given** ログ、**When** 各フレームの伝送時間（Tx_Start〜Tx_End）を見る、**Then** インターミッションは含まれない（SOF〜EOF のみで、Doc FR-021 のビット数 × ビット時間に一致する）。

---

### Edge Cases

- スピード +10（待ちなし）で開始した場合、実行中の状態は一瞬で終わるため、メニューの制限は利用者からは見えない。
- 実行中に ✖ でダイアログを閉じることはできる（機能 004 と同じ。結果は出力しない）。
- 実行中にメニューのショートカット（Alt+F / Alt+E）を押しても、メニューは開かない。
- 1 Mbps の 3 ビット時間は 3 µs で、µs の整数になる。すべての通信速度で 3 ビット時間は µs の整数である。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、シミュレーションの実行中、メニューバーの「ファイル」「編集」をトップレベルごと選べない状態（グレー表示）にし、マウスでもキーボードでも開けないようにしなければならない。
- **FR-002**: システムは、シミュレーションを実行していないとき、「ファイル」「編集」を選べる状態にしなければならない。実行の完了・「終了」による停止の直後に、選べる状態に戻さなければならない。
- **FR-003**: 「シミュレーション」メニューは実行中も選べ、「開始」は実行中は選べず、「終了」は実行中だけ選べる（機能 004と同じ）。
- **FR-004**: 実行中はフレーム表示の ON / OFF を切り替えられない。実行中の強調表示の有無は、開始時のフレーム表示の設定で決まる。（005 の「実行中の切替」を廃止）
- **FR-005**: システムは、データフレームの送信終了（EOF の終わり）から 3 ビット時間（インターミッション）が経過した時点でバスをアイドル状態とし、それより前に次のフレームの送信を開始してはならない。（Doc FR-022、機能 001 で実装済み）
- **FR-006**: ログのフレームの伝送時間（Tx_Start〜Tx_End）には、インターミッションを含めてはならない（SOF〜EOF のみ）。（Doc FR-021、機能 001 で実装済み）
- **FR-007**: フレーム表示の強調では、バスを「使用中（青）」として表示するのは SOF〜EOF の間だけとし、インターミッション（EOF 後の 3 ビット）は表示しない。インターミッションは CAN コントローラ内部の処理であり、その後バスアイドルに遷移していればよい。（2026-09-30 利用者決定。機能 005 の表示のまま変更しない）

### Key Entities *(include if feature involves data)*

- **実行状態**: 停止中／実行中。メニューの「ファイル」「編集」の選択可否を決める。
- **インターミッション**: フレームの EOF の後に続く 3 ビットのレセシブ期間。この間はバスアイドルではない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 実行中に「ファイル」「編集」を開こうとする操作（クリック、Alt+F、Alt+E）は、すべて開かない（0 回）。
- **SC-002**: 実行の完了・停止の直後に、「ファイル」「編集」が開ける。
- **SC-003**: 送信待ちが続いている区間のすべての連続する 2 フレームで、後の送信開始 − 前の送信終了 = 3 ビット時間（全通信速度で一致）。
- **SC-004**: すべてのフレームの伝送時間が、そのフレームのビット数（スタッフビット込み）× ビット時間と一致し、インターミッションを含まない。

## Assumptions

- 「編集できないようにする」は、実行中に「ファイル」「編集」の配下の操作をすべて選べなくすることと解釈する。「シミュレーション」メニューと ✖ は対象外。
- インターミッション中は、CAN のシステムとしてバスはアイドルではないが、ログの Tx_End やバス負荷率の計算は従来どおりSOF〜EOF を対象とする（Doc FR-071 はインターミッションを含めない）。
- 本機能は、Doc v1.11 の 3.7a（送信・受信バッファ）とは独立している。

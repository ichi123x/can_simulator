# Feature Specification: ログ表示メニューへのログクリア（ログファイルの削除）の追加

**Feature Branch**: `ver.0.6`（spec ディレクトリ: `027-log-clear`）

**Created**: 2026-10-03

**Status**: Draft

**Input**: User description: "ログ表示 (L)に、サブメニューにログクリア（ログファイル消去）を追加。ログクリアはログファイルを削除します。"（確認の回答: Q1 = A（削除の前に確認を出す）、Q2 = A（3 つのファイルすべて）、Q3 = A（ログ表示エリアの行も消す））

**前提となる機能**: 機能 004（プロジェクトファイルの隣への CSV の出力）、009（ログ表示エリア）、024（現在のプロジェクトファイル）、025（ログ表示メニューとシミュレーションログのウィンドウ）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 現在のプロジェクトのログファイルを削除する (Priority: P1)

ユーザーはメニューの「ログ表示 → ログクリア」で、現在のプロジェクトのシミュレーションで出力されたログファイルを削除する。
古い結果を残さずに、まっさらな状態から実行し直したいときや、不要になった大きなログを片付けたいときに使う。

**Why this priority**: 要望のすべて。

**Independent Test**: サンプルプロジェクトを読み込んで実行し、ログファイルができたことを確かめてから「ログクリア」を選び、ファイルが無くなったこと、
続けて「シミュレーションログ」を選ぶと「ログが無い」と通知されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 現在のプロジェクトのログファイルがある、**When** 「ログ表示 → ログクリア」を選ぶ、**Then** 削除する前に、削除するファイルと「元に戻せない」ことを示す確認を出す（Q1）。
   「はい」で削除し、削除したことを通知する。「いいえ」なら何もしない（ファイルも表示も変わらない）。
2. **Given** 削除の後、**When** 「ログ表示 → シミュレーションログ」を選ぶ、**Then** ログが無いことが通知される（機能 025 のまま）。
3. **Given** 削除するファイル、**When** ログクリアを行う、**Then** シミュレーションで出力される 3 つのファイル（フレームログ・集計・起動記録）のうち、あるものをすべて削除する（Q2）。プロジェクトファイル（`.canprj`）は削除しない。
4. **Given** シミュレーションログのウィンドウが開いている、**When** ログクリアを行う、**Then** 先にそのウィンドウを閉じてから削除する。
5. **Given** メインウィンドウのログ表示エリアに前回の実行の行が表示されている、**When** ログクリアを行う、**Then** ログ表示エリアの行も消え、空の表示になる（Q3）。
   構成図の強調・シミュレーション時間の表示は変えない。

---

### User Story 2 - 削除できないときに理由がわかる (Priority: P2)

ログファイルが無いとき、プロジェクトファイルが無いとき、ほかのアプリがファイルを開いていて削除できないときは、ユーザーはその理由を通知で知る。

**Why this priority**: 削除できたかどうかがわからないと、古い結果を新しい結果と取り違えるおそれがある。

**Independent Test**: 起動直後（プロジェクトファイルなし）、ログの無いプロジェクト、ログを表計算ソフトで開いたままのプロジェクト、の 3 つでログクリアを選び、
それぞれの通知を確かめる。

**Acceptance Scenarios**:

1. **Given** プロジェクトファイルが無い（起動直後など）、**When** ログクリアを選ぶ、**Then** プロジェクトファイルが無いことを通知し、何も削除しない（機能 025 のシミュレーションログと同じ通知）。
2. **Given** 削除の対象のファイルが 1 つも無い、**When** ログクリアを選ぶ、**Then** ログが無いことを通知する（確認は出さない）。
3. **Given** 対象のファイルをほかのアプリが開いていて削除できない、**When** 削除する、**Then** 削除できなかったファイル名を通知する。削除できたファイルは削除されたままになる。

### Edge Cases

- 実行中・中断中は、「ログ表示」メニューはグレーで開けない（機能 025 のまま）。そのためログクリアも選べない。
- データフレーム編集ウィンドウが開いていても、ログクリアはそのまま行える（プロジェクトの内容は変わらない）。
- ログクリアはプロジェクトの内容（設定・ECU・フレーム）と、現在のプロジェクトファイルを変えない。
- ファイルを削除した後に「開始」すると、今までどおり新しいログファイルが作られる。
- ログファイルが読み取り専用のときは、削除できなかったものとして通知する（属性を変えてまで削除しない）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 「ログ表示」メニューに「ログクリア」の項目を、「シミュレーションログ」の下に追加しなければならない。
- **FR-002**: ログクリアは、現在のプロジェクトファイルの隣にある、シミュレーションで出力された 3 つのファイル（フレームログ・集計・起動記録）のうち、あるものをすべて削除しなければならない。
- **FR-003**: ログクリアは、削除の前に、削除するファイルと元に戻せないことを示す確認を出し、「はい」のときだけ削除しなければならない。
- **FR-004**: 削除した後は、削除したことを通知しなければならない。
- **FR-005**: プロジェクトファイルが無いとき・対象のファイルが 1 つも無いときは、その旨を通知し、何も削除してはならない。
- **FR-006**: 削除できないファイルがあったときは、そのファイル名を通知しなければならない。
- **FR-007**: シミュレーションログのウィンドウが開いていれば、削除の前に閉じなければならない。
- **FR-008**: 削除を行ったとき（1 つでも削除できたとき）は、メインウィンドウのログ表示エリアの行を消さなければならない。確認で「いいえ」のとき・何も削除しなかったときは消してはならない。
- **FR-009**: プロジェクトファイル（`.canprj`）・プロジェクトの内容・ほかのフォルダーのファイルを削除・変更してはならない。

### Key Entities

- **ログファイル**: シミュレーションの実行時に、現在のプロジェクトファイルの隣に `<プロジェクトファイル名>.log.csv`（フレームログ）・`.summary.csv`（集計）・`.startup.csv`（起動記録）の名前で作られるファイル。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ログのあるプロジェクトで、メニューの操作 1 回と確認への応答 1 回で 3 つのファイルが削除され、ログ表示エリアも空になる。
- **SC-002**: プロジェクトファイル・ほかのファイルは、どの場合でも削除・変更されない（100%）。
- **SC-003**: 削除できなかった場合・削除するものが無い場合に、通知が出ない操作が無い（100%）。
- **SC-004**: 既存の検証（機能 001〜026 の自動検証）がすべて通り、シミュレーション結果（CSV の中身）は変わらない。

## Assumptions

- 「ログファイル」は、現在のプロジェクトのシミュレーションが出力するファイルを指し、ほかのプロジェクトのログや、別の場所に手で移したファイルは対象にしない。
- 削除はごみ箱を経由しない通常の削除とする（元に戻せない。そのため確認の文面に「元に戻せない」ことを含める）。
- メニューの項目名は「ログクリア」とし、日本語の文字列は `.rc` に置く。
- 通知の文言は既存の通知（機能 025）に合わせ、メッセージボックスで表示する。

# Feature Specification: シミュレーション開始時に表示をクリアして先頭から表示する

**Feature Branch**: `ver.0.3`（spec ディレクトリ: `012-start-clear-display`）

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "シミュレーション開始で、必ず、イベント＆ログ表示画面をクリアし、先頭から表示開始できるようにする。"

**前提となる機能**: 機能 004（開始・終了）、機能 005（スピード、開始時の計算）、機能 009（ログ表示エリア）、機能 011（グレー表示と枠）。

## 現状の問題（背景）

- 「開始」は前回のログを消すが、画面の描き直しは開始直後の計算（シミュレーション時間が長いと数秒、待機カーソル表示）が終わってから
  行われる。そのため計算の間は、前回の実行のログ・構成図がそのまま見えていて、新しい実行が始まったのか分かりにくい。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 「開始」するとすぐに表示が空になる (Priority: P1)

ユーザーが「開始」を選ぶと、シミュレーションの計測に関わる初期化（計算・再生の時計・強調の準備など）より前に、イベント表示
（構成図の強調）とログ表示エリアが初期化され、その場で画面が空の状態になる。前回の結果と新しい実行の結果が混ざって見えることがない。

**Why this priority**: 要望の中心。新しい実行が始まったことがすぐに分かる。

**Independent Test**: シミュレーション時間 600 秒の構成で一度実行して完了させた後、もう一度「開始」して、待機カーソルが出ている間に
ログ表示エリアが空であることを確認する。

**Acceptance Scenarios**:

1. **Given** 前回の実行のログが表示されている、**When** 「開始」を選ぶ、**Then** 計算の完了を待たずに（待機カーソルの表示中に）
   ログ表示エリアが空になり、スクロールバーは無効（行が無い状態）になる。
2. **Given** 前回の実行のログを途中までスクロールして読んでいる、**When** 「開始」を選ぶ、**Then** スクロール位置は先頭に戻り、
   新しい実行の行は先頭（ログ表示エリアの一番上）から表示され始める。
3. **Given** 構成図に何らかの表示（ダブルクリック直後のグレー表示など）が残っている、**When** 「開始」を選ぶ、**Then** 計算の間、
   構成図はどの ECU・バスも強調のない通常の表示になる。

---

### User Story 2 - 新しい実行の行が先頭から順に表示される (Priority: P1)

実行が進むと、ログの行が時刻の順に、ログ表示エリアの一番上の行から順に表示される。行がエリアに収まらなくなった後は、機能 009 と
同じく最新の行が一番下に来るように追従する。

**Why this priority**: 「先頭から表示開始」の要望そのもの。

**Independent Test**: スピード 0 の実行を開始し、最初の行がログ表示エリアの一番上に表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 「開始」した直後、**When** 最初の行の時刻に達する、**Then** その行がログ表示エリアの一番上に表示される。
2. **Given** 行がエリアに収まっている間、**When** 行が増える、**Then** 上から順に並び、表示位置（先頭行）は動かない。
3. **Given** 行がエリアの行数を超えた、**When** 行が増える、**Then** 機能 009 と同じく最新の行が一番下に来るように追従する
   （ユーザーがスクロールで遡っている間は動かさない）。

---

### Edge Cases

- 「開始」の前にプロジェクトの保存先を尋ねられ、キャンセルした場合は、実行しないので表示は消さない（今のまま残す）。
- 保存に失敗した場合も同じく実行しないので、表示は消さない。
- 実行中の「終了」では、その時点までの行が残る（機能 009 のまま。消さない）。行は次の「開始」まで残る。
- 行が 1 行も無い実行（ECU 数 0 など）でも、「開始」で前回の行は消える。
- 「開始」は編集ウィンドウが開いている間は選べない（機能 010）ので、編集ウィンドウとの関係は変わらない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 「開始」で実行することが決まった時点（保存先の確定後）に、シミュレーションの計測に関わる初期化（実行用ネットワークの
  生成・計算・再生の時計・強調の準備）より前に、ログ表示エリアの行をすべて消し、画面上でも空の状態にしなければならない。計算が
  終わるまで前回の行が見えていてはならない。
- **FR-002**: 同じ時点で、構成図の強調（送信・受信・バスの強調、グレー表示）をすべて消し、画面上でも通常の表示にしなければならない。
- **FR-003**: 消した後のログ表示エリアは、スクロール位置が先頭で、スクロールバーは行の無い状態でなければならない。前回の実行で
  ユーザーが遡っていた位置を引き継いではならない。
- **FR-004**: 新しい実行の行は、ログ表示エリアの一番上の行から時刻の順に表示しなければならない。エリアの行数を超えた後の追従と、
  遡っている間に動かさない動作は機能 009 と同じとする。
- **FR-005**: FR-001〜FR-003 の初期化（イベント表示とログ表示）は、「開始」の処理の中で計測関連の初期化より先に行い、画面への
  反映（描き直し）まで済ませてから計測関連の初期化に進まなければならない。
- **FR-006**: 「開始」をキャンセルした場合・保存に失敗した場合は、表示を消してはならない。
- **FR-007**: シミュレーションの結果（CSV）、ログの行の内容と順序、時間の進み方（機能 005）は変えてはならない。

### Key Entities

- **ログ表示の状態**: 表示する行の一覧、表示済みの行数、表示の先頭行（スクロール位置）。「開始」で空・先頭に戻る。
- **構成図の強調**: 送信・受信・バスの強調と、グレー表示の ECU。「開始」で無しに戻る。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 「開始」を選んでから 0.2 秒以内に、ログ表示エリアが空になり、構成図に強調が無くなる（シミュレーション時間 600 秒の
  構成でも、計算の完了を待たない）。
- **SC-002**: 前回の実行でどの位置までスクロールしていても、新しい実行の最初の行はログ表示エリアの一番上に表示される（10 回中 10 回）。
- **SC-003**: 「開始」の処理で、イベント表示とログ表示の初期化（画面の描き直しを含む）が、計測関連の初期化より常に先に行われる。
- **SC-004**: 「開始」のキャンセル・保存失敗では、表示が 1 行も変わらない。
- **SC-005**: 既存の検証（機能 001〜011）がすべて通り、シミュレーション結果（CSV）は変わらない。

## Assumptions

- 「イベント表示」は構成図の領域（フレームの送受信の強調を表示する所）、「ログ表示画面」は機能 009 のログ表示エリアを指す
  （機能 011 と同じ解釈）。
- 計算そのものの時間は変えない（計算中の待機カーソルも今のまま）。本機能は、計算の前に画面を描き直すことだけを加える。
- 完了後・「終了」後の表示（追従・行を残す。スピード +10 の即時完了で全行を出した後の表示位置を含む）は機能 009 のまま変えない
  （ユーザー回答: 完了後の位置ではなく、開始時の初期化の順序を定める）。

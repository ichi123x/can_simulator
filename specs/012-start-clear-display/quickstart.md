## 1. コアの検証（自動、checks.exe）

- 既存の 001〜011 の項目がすべて PASS し、サンプルの CSV が基準と一致する（コアは変更しない）。

## 2. GUI の確認（Debug|x64、サンプルは一時フォルダにコピー）

計算に時間のかかる構成として、`sample_16ecu` をコピーし、`DurationSec=600`・`Speed=10` にしたもの（`long600.canprj`）を使う。
ログ表示エリアが空であることは、文字の領域の数点の画面の色が背景色（`E6E6E6`）であることで判定する。

1. `long600.canprj` を読み込み「開始」→ 完了させてログを表示する（全行、一番下）。
2. ログをスクロールで先頭近くまで遡る。
3. もう一度「開始」→ 0.2 秒以内（計算中、待機カーソル表示中）にログ表示エリアの文字の領域が背景色だけになる。スクロールバーは無効。
4. 計算が終わって完了したら、ログには新しい実行の行が表示されている（機能 009 のとおり）。
5. スピード 0 の構成（`sample_appendix_a`）で、前回のログを途中まで遡った状態から「開始」する。
   - 最初の行がログ表示エリアの一番上に表示される。
   - 行がエリアに収まる間は、先頭行が動かない。
6. ECU をダブルクリックし、グレー表示中（0.5 秒以内）に編集ウィンドウを閉じて「開始」する → 計算前に構成図のグレーが消える。
7. キャンセルの確認: 起動直後（プロジェクト未保存）に「開始」→ 保存先のダイアログでキャンセル → 何も実行されず、表示は変わらない。
   - 保存先を尋ねられるのはまだ一度も実行していないとき（ログが空のとき）だけなので、「ログがある状態でキャンセル」は起こらない。
   - そのため FR-006 は、初期化の呼び出しが保存の確定より後にあることをコードで確認して代える。

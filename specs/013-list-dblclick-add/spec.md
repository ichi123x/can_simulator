# Feature Specification: 送信フレーム一覧のダブルクリックでフレーム追加を開く

**Feature Branch**: `ver.0.3`（spec ディレクトリ: `013-list-dblclick-add`）

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "データフレーム編集ウィンドウのリスト表示エリア内をダブルクリックすると追加ボタンを押したと同じようにフレーム追加へ遷移する。"

**前提となる機能**: 機能 006（データフレーム編集ウィンドウ・追加／編集の入力画面）、機能 010（編集ウィンドウのモードレス化・入力画面の間のオーナー無効化）。

## 現状（背景）

- データフレーム編集ウィンドウの送信フレーム一覧では、行をダブルクリックすると「編集」と同じ動作になる（機能 006）。
- 行の無い所（一覧の空白部分、フレームが 0 件のときの一覧全体）や列見出しをダブルクリックしても、フレームの追加は開かない。
  フレームを追加するには「追加」ボタンまでマウスを動かす必要がある。

## 用語

- **リスト表示エリア**: データフレーム編集ウィンドウの送信フレーム一覧の全体（ユーザー提示の画面写しの赤枠）。列見出し
  （No. / フレーム名 / ID / DLC / 初回オフセット(ms) / 送信周期(ms)）、フレームの行、行の無い空白をすべて含む。ECU の選択欄・
  ボタンは含まない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一覧のどこをダブルクリックしてもフレームを追加できる (Priority: P1)

ユーザーがデータフレーム編集ウィンドウで ECU を選び、リスト表示エリアの中（列見出し・行・空白のどこでも）をダブルクリックすると、
「追加」ボタンを押したときと同じ追加用の入力画面が開く。入力して OK すると、そのフレームが一覧の末尾に加わり選ばれた状態になる。
キャンセルすると何も変わらない。

**Why this priority**: 要望の中心。マウスを「追加」ボタンまで動かさずに、一覧の上で続けてフレームを追加できる。

**Independent Test**: フレームが 0 件の ECU を選び、一覧の中央をダブルクリックして追加の入力画面が開くことを確認し、OK で 1 行
追加されることを確認する。続けて、追加された行の上・列見出しをダブルクリックしても追加の入力画面が開くことを確認する。

**Acceptance Scenarios**:

1. **Given** 選んだ ECU のフレームが 0 件、**When** 一覧の中（空白）をダブルクリックする、**Then** 「追加」ボタンを押したときと同じ
   追加用の入力画面（空欄・既定値、タイトルも追加と同じ）が開く。
2. **Given** フレームが数件ある、**When** いずれかの行の上をダブルクリックする、**Then** その行の編集ではなく、追加用の入力画面が開く。
3. **Given** フレームが数件あり、最後の行より下に空白がある、**When** その空白をダブルクリックする、**Then** 追加用の入力画面が開く。
4. **Given** 一覧が表示されている、**When** 列見出しをダブルクリックする、**Then** 追加用の入力画面が開く。
5. **Given** 追加用の入力画面が開いている、**When** 正しい値を入れて OK する、**Then** 「追加」ボタンからの追加と同じく、フレームが
   一覧の末尾に加わり、その行が選ばれた状態になる。
6. **Given** 追加用の入力画面が開いている、**When** キャンセルする、**Then** 一覧・プロジェクトの定義は変わらない。

---

### User Story 2 - 追加できないときはダブルクリックしても何も起きない (Priority: P2)

「追加」ボタンが無効のとき（ECU が無い、その ECU のフレームが上限の 100 件）は、一覧をダブルクリックしても入力画面は開かない。

**Why this priority**: ボタンとダブルクリックで追加できる条件を揃え、上限を超える追加や ECU の無い追加を防ぐ。

**Independent Test**: フレームが 100 件の ECU を選び、一覧の行・空白・列見出しをダブルクリックしても何も開かないことを確認する。

**Acceptance Scenarios**:

1. **Given** 選んだ ECU のフレームが 100 件（「追加」ボタンが無効）、**When** 一覧の中をダブルクリックする、**Then** 何も起きない
   （メッセージも出さない。編集の入力画面も開かない）。
2. **Given** ECU 数が 0（ECU を選べない）、**When** 一覧をダブルクリックする、**Then** 何も起きない。

---

### Edge Cases

- 行の上のダブルクリックは「追加」になり、機能 006 の「行のダブルクリック = 編集」は無くなる。フレームの編集は、行を選んで
  「編集」ボタンで行う（ボタンの動作は変わらない）。
- 行の上をダブルクリックすると、1 回目のクリックでその行が選ばれる（一覧の通常の動作）。追加の入力画面を OK すると、選択は
  追加した行に移る。キャンセルすると、ダブルクリックで選ばれた行が選ばれたまま残る。
- 列見出しの境目のダブルクリックも「追加」とする（列幅の自動調整は行わない）。列見出しのドラッグによる列幅の変更は今までどおり。
- スクロールバー（行が多いときに一覧の中に出る）の上のダブルクリックは、スクロールの操作として扱い、追加を開かない。
- 追加用の入力画面が開いている間は、機能 010 のとおりメインダイアログは無効（編集ウィンドウを閉じたり差し替えたりできない）。
  入力画面が開いている間に一覧へダブルクリックが届くことはない（入力画面はモーダル）。
- 実行中はデータフレーム編集ウィンドウを開けない（機能 006/007/010）ので、実行との関係は変わらない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: リスト表示エリア（列見出し・フレームの行・行の無い空白）のどこをダブルクリックしても、「追加」ボタンを押したときと
  同じ動作（追加用の入力画面を開き、OK で末尾に追加して選び、キャンセルで定義を変えない）をしなければならない。
- **FR-002**: FR-001 の動作は、「追加」ボタンが有効なとき（ECU が選ばれていて、その ECU のフレームが 100 件未満）に限らなければ
  ならない。無効なときのダブルクリックでは何もしてはならず、メッセージも出してはならない。
- **FR-003**: 行の上のダブルクリックで「編集」の入力画面を開いてはならない（機能 006 の「一覧のダブルクリック = 編集」を置き換える）。
  「編集」ボタンの動作は変えない。
- **FR-004**: 一覧の中のスクロールバーのダブルクリックでは追加を開いてはならない。
- **FR-005**: ダブルクリックから開く追加の入力画面・入力検査・追加後の一覧の表示・オーナー（メインダイアログ）の無効化は、
  「追加」ボタンからの追加とまったく同じでなければならない（別の動作・別の画面を設けない）。
- **FR-006**: 追加したフレームのプロジェクトへの反映（その場で定義に反映、保存はプロジェクト保存）、シミュレーションの結果は
  変えてはならない。

### Key Entities

- **送信フレーム一覧（リスト表示エリア）**: 列見出し、選んだ ECU の送信フレームの行（No. / フレーム名 / ID / DLC / 初回オフセット /
  送信周期）、行の無い空白。どこをダブルクリックしても追加になる（スクロールバーを除く）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 「追加」ボタンが有効なとき、リスト表示エリアの列見出し・行・空白のいずれのダブルクリックでも、追加用の入力画面が
  10 回中 10 回開く。
- **SC-002**: ダブルクリックから追加したフレームと、「追加」ボタンから同じ値で追加したフレームは、一覧の表示・保存したプロジェクト
  ファイルの内容が同じになる。
- **SC-003**: 「追加」ボタンが無効なとき（100 件・ECU なし）、ダブルクリックで入力画面（追加・編集とも）が開くことは 1 回もない。
- **SC-004**: 一覧のダブルクリックで編集の入力画面が開くことは 1 回もない。
- **SC-005**: 既存の検証（機能 001〜012）がすべて通り、シミュレーション結果（CSV）は変わらない。

## Assumptions

- 「リスト表示エリア」はユーザー提示の画面写しの赤枠（送信フレーム一覧の全体。列見出しを含む）を指す（ユーザー回答）。
- 「追加ボタンを押したと同じように」は、追加ボタンの有効／無効の条件も含めて同じ、と解釈する（ボタンが押せないときは追加しない）。
- スクロールバーは一覧の中に出るが、スクロール操作のための部品なので対象外とする（矢印の連続クリックで追加が開くのを防ぐ）。
- ダブルクリックの判定（間隔・距離）は OS の設定に従う。
- ドメインロジック（入力検査・追加）は既存のものをそのまま使い、新しい規則は加えない。

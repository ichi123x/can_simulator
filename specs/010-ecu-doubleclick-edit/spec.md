# Feature Specification: ECU ブロックのダブルクリックでデータフレーム編集を開く

**Feature Branch**: `010-ecu-doubleclick-edit`

**Created**: 2026-09-30

**Status**: Draft

**Input**: User description: "ＣＡＮ接続図のＥＣＵブロックをダブルクリックすると当該のＥＣＵのデータフレーム編集フレームウィンドウを起動して編集できる仕様を追加してください。"

**前提となる機能**: 機能 003（CAN バス構成図）、機能 006（データフレーム編集ウィンドウ）、機能 007（実行中のメニュー制限）。本機能は新しい編集画面を作らず、機能 006 の編集ウィンドウを構成図から開く入口を増やす。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 構成図の ECU をダブルクリックして、その ECU のフレームを編集する (Priority: P1)

ユーザーは CAN バス構成図を見ながら、ある ECU の送信フレームを確認・変更したいと考える。メニューから編集ウィンドウを開いて ECU を選び直す代わりに、構成図上のその ECU のブロックをダブルクリックすると、その ECU が選ばれた状態でデータフレーム編集ウィンドウが開き、そのまま追加・編集・削除ができる。

**Why this priority**: 本機能の目的そのもの。構成図と編集対象が直接結び付き、ECU の取り違えと操作の手間が減る。

**Independent Test**: `sample_appendix_a` を読み込み、構成図の「ECU 03」をダブルクリックして、編集ウィンドウがECU 3 を選んだ状態で開き、ECU 3 の送信フレーム一覧が表示されることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** シミュレーションを実行していない状態で構成図に ECU 01〜N が表示されている、**When** ECU 0k のブロックをダブルクリックする、**Then** データフレーム編集ウィンドウが開き、ECU の選択欄で ECU k が選ばれ、ECU k の送信フレーム一覧が表示される。
2. **Given** ダブルクリックで開いた編集ウィンドウ、**When** フレームを追加・編集・削除して閉じる、**Then** 結果はメニューから開いた場合と同じく現在のプロジェクトに反映される（プロジェクト保存で保存され、次の「開始」で使われる）。
3. **Given** 送信フレームを 1 つも持たない ECU（プロジェクトに定義がない ECU を含む）、**When** そのブロックをダブルクリックする、**Then** その ECU を選んだ状態で空の一覧の編集ウィンドウが開き、「追加」でフレームを登録できる。
4. **Given** ダブルクリックで開いた編集ウィンドウ、**When** ECU の選択欄で別の ECU を選ぶ、**Then** メニューから開いた場合と同じく、その ECU の一覧に切り替わる。

---

### User Story 2 - ECU ブロック以外や実行中のダブルクリックでは何も起きない (Priority: P2)

ユーザーが構成図のバス線・接続線・余白やログ表示エリアをダブルクリックしたり、シミュレーションの実行中に ECU をダブルクリックしたりしても、編集ウィンドウは開かず、表示も実行も変わらない。

**Why this priority**: 誤操作で意図しない画面が開いたり、実行中にフレーム定義を変えられたりしないようにするため。機能 007 の「実行中は編集できない」の約束を、新しい入口でも守る。

**Independent Test**: 構成図の余白・バス線をダブルクリックして何も開かないこと、`sample_startup` の実行中に ECU をダブルクリックして何も開かず実行が続くことを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 実行していない状態、**When** バス線・「CAN BUS」の文字・ECU とバスの接続線・構成図の余白・ログ表示エリアのいずれかをダブルクリックする、**Then** 何も開かず、画面は変わらない。
2. **Given** シミュレーションの実行中、**When** ECU のブロックをダブルクリックする、**Then** 編集ウィンドウは開かず、実行（時計・フレーム表示・ログ表示）はそのまま続く。
3. **Given** 実行していない状態、**When** ECU のブロックを 1 回だけクリックする、**Then** 何も開かない。
4. **Given** ECU 数が 0 の構成図（バスのみ）、**When** 構成図のどこをダブルクリックしても、**Then** 何も開かない。

---

### User Story 3 - 編集ウィンドウを開いたまま、別の ECU をダブルクリックして切り替える (Priority: P2)

ユーザーはある ECU の編集ウィンドウを開いたまま、構成図の別の ECU をダブルクリックする。今開いている編集ウィンドウがいったん閉じ、約 0.5 秒おいてから、ダブルクリックした ECU の編集ウィンドウが開く。間をおくことで、ユーザーは編集対象の ECU が切り替わったことに気づける。今開いているのと同じ ECU をダブルクリックした場合は、閉じ直さない。

**Why this priority**: 複数の ECU のフレームを続けて確認・編集するときに、毎回ウィンドウを閉じてから開き直す手間を省く。US1 の上に成り立つ追加の操作。

**Independent Test**: `sample_appendix_a` で ECU 03 の編集ウィンドウを開いたまま ECU 05 をダブルクリックし、ECU 03 のウィンドウが閉じてから約 0.5 秒後に、ECU 05 を選んだ編集ウィンドウが開くことを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** ECU 3 を表示中の編集ウィンドウが開いている、**When** 構成図の ECU 05 をダブルクリックする、**Then** 今の編集ウィンドウが閉じ、約 0.5 秒後に ECU 5 を選んだ編集ウィンドウが開く。
2. **Given** ECU 3 を表示中の編集ウィンドウが開いている、**When** 構成図の ECU 03 をダブルクリックする、**Then** ウィンドウは閉じず、開いている編集ウィンドウが前面に出る。
3. **Given** 編集ウィンドウの選択欄で ECU 5 に切り替えた状態、**When** 構成図の ECU 05 をダブルクリックする、**Then** 表示中のECU と同じなので、閉じ直さずに前面に出る。ECU 03 をダブルクリックした場合は、閉じて約 0.5 秒後に ECU 3 で開く。
4. **Given** ECU 3 の編集ウィンドウでフレームを追加した、**When** ECU 05 をダブルクリックして切り替える、**Then** ECU 3 に追加したフレームは現在のプロジェクトに残っている（切り替えで編集内容は失われない）。
5. **Given** 切り替えの待ち（閉じてから開くまでの約 0.5 秒）の間、**When** さらに別の ECU 07 をダブルクリックする、**Then**開くのは最後にダブルクリックした ECU 7 の編集ウィンドウ 1 つだけである。
6. **Given** 編集ウィンドウが開いている（切り替えの待ちの間を含む）、**When** メニューを見る、**Then**「シミュレーション →開始」は選べない。編集ウィンドウを閉じると選べるようになる。
7. **Given** 編集ウィンドウが開いている、**When** メニューから「プロジェクト読込み」または「セッティング」を選ぶ、**Then**編集ウィンドウが閉じてから、その操作が行われる。
8. **Given** 編集ウィンドウで「追加／編集」の入力画面、または「削除」の確認が開いている、**When** 構成図の別の ECU をダブルクリックする、**Then** 何も起きない（入力中の内容は失われない）。

---

### Edge Cases

- ECU のブロックの境界上（縁）をダブルクリックした場合は、そのブロックのダブルクリックとして扱う。ブロック同士は重ならないので、どの ECU かが曖昧になることはない。
- 画面の拡大率（DPI）が 100% 以外でも、見えている ECU のブロックの範囲と、ダブルクリックが効く範囲が一致する。
- ECU 数を減らした後は、表示されていない ECU（ECU 数を超える番号）はダブルクリックの対象にならない。定義が残っていても構成図に出ていない ECU は開けない（機能 006 の選択欄も ECU 1〜N だけ）。
- 編集ウィンドウを開いている間も、メインウィンドウ（構成図のダブルクリック、メニュー、ログ表示エリアのスクロール）は操作できる。編集ウィンドウは同時に 1 つしか開かない。
- 編集ウィンドウが開いているときにメニュー「編集 → データフレーム編集」を選んだ場合は、新しく開かず、開いている編集ウィンドウを前面に出す（表示中の ECU は変えない）。切り替えの待ちの間に選んだ場合は何もしない（まもなく編集ウィンドウが開くため）。
- 編集ウィンドウを開いている間も「プロジェクト保存」「フレーム表示」は使える（編集内容はその時点でプロジェクトに反映済み）。
- 切り替えの待ちの間にメインウィンドウを ✖ で閉じた場合は、新しい編集ウィンドウは開かずに終了する。
- 切り替えの待ちの間に「プロジェクト読込み」「セッティング」を選んだ場合は、待ちを取り消して（新しい編集ウィンドウは開かず）、その操作を行う。
- 編集ウィンドウを閉じた後、構成図の ECU 数・表示は変わらない（編集ウィンドウでは ECU 数を変えない）。
- 実行が終わった（完了・「終了」で止めた）後は、再びダブルクリックで開ける。
- 「開始」の計算中（待機カーソル表示中）に行ったダブルクリックは、計算の後に届く。その時点で実行中なら無視し、スピード +10 などで実行がすでに終わっていれば、その ECU の編集ウィンドウが開く（完了後に開けるのと同じ扱い）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、シミュレーションを実行していないとき、CAN バス構成図に表示されている ECU のブロックがダブルクリックされたら、データフレーム編集ウィンドウ（機能 006）を開かなければならない。
- **FR-002**: ダブルクリックで開いた編集ウィンドウは、ダブルクリックされた ECU を選んだ状態で開き、その ECU の送信フレーム一覧を表示しなければならない。
- **FR-003**: ダブルクリックで開いた編集ウィンドウの内容・操作・検査・プロジェクトへの反映（ウィンドウそのものの振る舞い）は、メニューから開いた場合と同じでなければならない（ECU の選択欄で別の ECU に切り替えることもできる）。
- **FR-004**: ダブルクリックが効く範囲は、画面に描かれた ECU のブロックの矩形（縁を含む）と一致しなければならない。画面の拡大率にかかわらず一致すること。
- **FR-005**: ECU のブロック以外（バス線、「CAN BUS」の文字、接続線、構成図の余白、ログ表示エリア）のダブルクリックでは、何もしてはならない。
- **FR-006**: シミュレーションの実行中は、ECU のブロックをダブルクリックしても編集ウィンドウを開いてはならず、実行に影響を与えてはならない（機能 007 と同じ制限）。
- **FR-007**: 1 回のクリック（シングルクリック）では何もしてはならない。
- **FR-008**: 編集ウィンドウが開いていないときのメニュー「編集 → データフレーム編集」の動作（開いたときに最初に選ばれているECU を含む）は変えてはならない。
- **FR-009**: 編集ウィンドウを開いている間も、メインウィンドウの構成図のダブルクリックとメニューを操作できなければならない。編集ウィンドウは同時に 1 つだけとする。
- **FR-010**: 編集ウィンドウが開いているとき、そのウィンドウで表示中の ECU と異なる ECU のブロックがダブルクリックされたら、今の編集ウィンドウを閉じ、約 0.5 秒おいてから、ダブルクリックされた ECU を選んだ編集ウィンドウを開かなければならない。待ちの間もメインウィンドウは操作できなければならない（画面が固まらない）。
- **FR-011**: 表示中の ECU と同じ ECU のブロックがダブルクリックされたら、閉じ直さずに、開いている編集ウィンドウを前面に出さなければならない。
- **FR-012**: 切り替えの待ちの間にさらに ECU がダブルクリックされたら、最後にダブルクリックされた ECU の編集ウィンドウを1 つだけ開かなければならない。
- **FR-013**: 編集ウィンドウが開いている間（切り替えの待ちの間を含む）は、シミュレーションを開始できてはならない（「開始」を選べない）。
- **FR-014**: 編集ウィンドウが開いている間（切り替えの待ちの間を含む）に「プロジェクト読込み」「セッティング」が選ばれたら、編集ウィンドウを閉じ（待ちは取り消し）、その後にその操作を行わなければならない。その操作がキャンセルされても、編集ウィンドウを再び開いてはならない。
- **FR-015**: 編集ウィンドウの「追加／編集」の入力画面、または「削除」の確認が開いている間は、構成図の ECU のダブルクリックで切り替えてはならない。
- **FR-016**: 切り替え・自動で閉じる場合でも、それまでの編集内容は現在のプロジェクトに残らなければならない（機能 006 と同じく、編集はその場でプロジェクトに反映される）。
- **FR-017**: 編集ウィンドウは、構成図の ECU のブロックに重ならない位置（構成図の下、ログ表示エリアの上に重ねる位置）に開かなければならない。画面の下端からはみ出す場合は、画面内に収まるように上へずらす。開いた後にユーザーが動かすことはできる。

### Key Entities

- **ECU ブロック**: 構成図に描かれた ECU 01〜N の箱。ECU 番号と、画面上の矩形（機能 003 の配置計算で決まる）を持つ。本機能では、この矩形がダブルクリックの当たり判定の範囲になる。
- **データフレーム編集ウィンドウ**: 機能 006 のウィンドウ。本機能では、最初に選ぶ ECU を指定して開けるようにし、開いたままメインウィンドウを操作できるようにする。同時に 1 つだけ。「表示中の ECU」（選択欄で選ばれている ECU）を持つ。
- **切り替えの待ち**: 編集ウィンドウを閉じてから次の編集ウィンドウを開くまでの約 0.5 秒の状態。開く予定の ECU（最後にダブルクリックされた ECU）を持つ。「編集ウィンドウが開いている」ものとして扱う（FR-013、FR-014）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ECU のブロックをダブルクリック 1 回で、ECU の選び直しをせずに、その ECU の送信フレーム一覧が表示される。
- **SC-002**: ECU 数 1〜16 のそれぞれで、表示されているすべての ECU ブロックについて、ダブルクリックするとその番号の ECU が選ばれた編集ウィンドウが開く（取り違え 0 件）。
- **SC-003**: ECU ブロック以外の場所へのダブルクリックと、実行中のダブルクリックで、編集ウィンドウが開く回数が 0 回。
- **SC-004**: ダブルクリックで開いて行った追加・編集・削除の結果が、メニューから開いて同じ操作をした場合と同じプロジェクトファイル・同じシミュレーション結果になる。
- **SC-005**: 画面の拡大率 100%・125%・150% のいずれでも、ECU ブロックの縁の内側 1 px をダブルクリックすると開き、外側 1 px では開かない。
- **SC-006**: 編集ウィンドウを開いたまま別の ECU をダブルクリックすると、今のウィンドウが閉じてから 0.4〜0.7 秒後に、ダブルクリックした ECU の編集ウィンドウが開く。同じ ECU のダブルクリックでは閉じ直さない。
- **SC-007**: 編集ウィンドウが開いている間（切り替えの待ちを含む）に、シミュレーションが開始される回数が 0 回。
- **SC-008**: 切り替え・自動で閉じる操作の前後で、プロジェクトのフレーム定義が失われる件数が 0 件。

## Assumptions

- 開く編集ウィンドウは機能 006 のものをそのまま使い、新しい画面や項目は追加しない。ただし、開いたままメインウィンドウを操作できる作りに変える（機能 006 では開いている間メインウィンドウを操作できなかった）。
- 切り替えの待ちは約 0.5 秒の固定値とし、設定項目にはしない。待ちの間は何も表示しない。
- 入力画面・削除の確認が開いている間のダブルクリックは無視する（入力中の内容を守るため。要望に明示がなく、既定として置いた）。
- ダブルクリックの判定（2 回のクリックの間隔・位置のずれの許容）は OS の標準設定に従う。
- ダブルクリックが効く範囲は ECU の箱の外接矩形とし、角の丸みの外側の数 px も含む。ECU 同士・バス線とは離れているため、誤って別の ECU やバスと判定されることはない。
- ECU ブロックの上でマウスカーソルの形を変える、ブロックを強調するといった「ダブルクリックできる」ことを示す表示は本機能の範囲外とする（必要なら別機能で追加する）。
- 右クリックメニューやドラッグなど、ダブルクリック以外のマウス操作は本機能の範囲外とする。
- 構成図の配置・色・大きさ（機能 003）とログ表示エリア（機能 009）は変えない。

# Research: 解析・ログ表示メニューの追加とシミュレーションログの表示

## 決定1: 大きなログを全行読めるようにする方法（行の索引）

- **Decision**: 開くときにファイルを先頭から 1 回だけ読み（1 MB ずつ、`\n` を数える）、256 行ごとの行頭のバイト位置を `std::vector<long long>` に記録する（`LogFileIndex`）。行 i を読むときは、`i / 256` 番目の位置へ移動して `i % 256` 行を読み飛ばす。同時に行数と最も長い行の文字数（横スクロールの幅）を記録する。
- **Rationale**: 700 万行でも索引は約 2.7 万個（約 220 KB）。画面の書き換えでは見えている数十行 + 最大 255 行の読み飛ばしだけで、ディスクのキャッシュに乗るので速い。行頭をすべて記録すると 700 万行で 56 MB になり、32bit 版でも持てるが無駄が大きい。
- **Alternatives considered**: ファイルをメモリに写像する（32bit 版では数百 MB の写像が確保できないことがある）、全文を読み込む（メモリと時間）、別スレッドで索引を作る（開くのが速くなるが、作り途中の表示と排他が要る。sample_16ecu 600 秒で 2 秒以内の目標は同期で満たせる見込みなので、待機カーソルで同期に作る）。

## 決定2: 表示の部品（自前描画）

- **Decision**: `CLogTextView`（`CWnd` 派生の子ウィンドウ）で、見えている行だけを `LogFileIndex::ReadLines` で読み、等幅フォント（MS Gothic、ログ表示エリアと同じ 13 px）で描く。縦スクロールの単位は行、横は文字。文字単位の選択（アンカーとキャレットの (行, 列)）を持ち、選択範囲を反転色で描く。CSV は ASCII なので、列 = バイト位置で、文字の幅は一定。
- **Rationale**: spec の「全行を読める」（Q2 = A）と「文字を選んでコピー」を両立できる。読み取り専用は、編集の操作を一切持たないことで満たす。
- **Alternatives considered**:
  - 読み取り専用のエディット: 全文を入れる必要があり、標準のエディットは大きな文字列で非常に遅い。
  - リッチエディット: 同じく全文が要る。数百 MB では開くのに数十秒かかる。
  - 仮想リストビュー（`LVS_OWNERDATA`）: 全行を扱えるが、選択は行単位で、文字単位の選択ができない。

## 決定3: 操作

- **Decision**:
  - スクロール: スクロールバー（ドラッグ中は `SIF_TRACKPOS`）、ホイール（3 行）、↑↓・PgUp/PgDn・Home/End（行頭・行末）・Ctrl+Home/Ctrl+End。←→ はキャレットを動かす。
  - 選択: 左ボタンのドラッグ（端に出たら自動でスクロール）、Shift + 移動のキー、Ctrl+A（全体）、ダブルクリックは扱わない。
  - コピー: Ctrl+C と右クリックのメニュー「コピー」「すべて選択」。行の区切りは CRLF。選択が 16 MB を超えるときはコピーせず、`IDS_LOG_COPY_TOO_LARGE` で知らせる（数百 MB をクリップボードに入れない）。
  - 閉じる: Esc・✖。Enter では閉じない。
- **Rationale**: 一般的なテキスト表示の操作に合わせる。コピーの上限は、Ctrl+A → Ctrl+C で数百 MB を確保して固まるのを防ぐため。

## 決定4: ログ表示を閉じる時機（spec FR-009）

- **Decision**: 次の操作の前にログ表示を閉じる（`CloseLogViewer`）: 「開始」（新しい実行のとき。再開では閉じない）、「プロジェクト読込み」（ファイル選択の前）、「セッティング」、`SetProjectPath` でパスが変わるとき（別名で保存、起動時の引数の読込みも含む）。ほかの操作（データフレーム編集・ツールバーのスピード・フレーム表示）では閉じない。
- **Rationale**: 機能 010 の編集ウィンドウが読込み・セッティングの前に閉じるのと同じ考え方。表示中のファイルが、実行の終わりの書き込み・別のプロジェクトへの切り替えで、現在のプロジェクトと食い違うのを防ぐ。実行の終わりに同じファイルへ書くため、「開始」で閉じておくと、ファイルを開いたままの書き込みも起きない（`LogFileIndex` は読むたびに開いて閉じるので、そもそも書き込みを妨げない）。
- **Alternatives considered**: 開いている間は「開始」などをグレーにする（操作が増え、どの操作が止まっているのかわかりにくい）、終了後に読み直す（「開始」直後の未完了の内容の扱いが複雑）。

## 決定5: 実行中・中断中のメニュー

- **Decision**: `UpdateTopMenus` で、位置 0（ファイル）・1（編集）に加えて 3（解析）・4（ログ表示）もグレーにする。`OnInitMenuPopup` では、念のため `ID_LOG_VIEW_SIMLOG` も実行中はグレーにする。
- **Rationale**: spec FR-008、機能 007 と同じ方法（トップレベルごとグレーにしてキーボードでも開けない）。

## 決定6: ログの有無の判定とメッセージ

- **Decision**: パスは `m_projectPath + L".log.csv"`（`WriteResults` と同じ組み立て）。`m_projectPath` が空 → `IDS_LOG_NONE_NOPROJECT`、`GetFileAttributes` が無い／フォルダー → `IDS_LOG_NONE`（プロジェクトファイル名）、`LogFileIndex::Build` が開けない／読めない → `IDS_LOG_READ_ERROR`（ログのフルパス）。
- **Rationale**: spec FR-005・FR-006。「無い」と「読めない」を区別する。ログのパスの組み立ては今の `WriteResults` と同じ式を使い、ずれないようにする（共通の小さな関数 `LogPathFor` にまとめる）。

## 決定7: 「解析」の中身

- **Decision**: `POPUP "解析(&A)"` に `MENUITEM "準備中", ID_ANALYSIS_PLACEHOLDER, GRAYED` を 1 つ置く。ハンドラは持たない。
- **Rationale**: spec FR-002。空のポップアップは Windows で開いたときに何も出ず、操作できないのか壊れているのかがわからないため、準備中の項目を見せる。

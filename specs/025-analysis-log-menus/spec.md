# Feature Specification: 解析・ログ表示メニューの追加とシミュレーションログの表示

**Feature Branch**: `ver.0.5`（spec ディレクトリ: `025-analysis-log-menus`）

**Created**: 2026-10-02

**Status**: Draft

**Input**: User description: "新規のメニューをシミュレーション(S)の次に、解析(A)、ログ表示(L)の２つを追加。解析メニューのサブメニューは検討中です。ログ表示メニューは、当該プロジェクトでシミュレーションをおこなってシミュレーションログがある場合は、読み込み専用でログをテキスト表示してください。ログがない場合はログがないこを通知してください。"（確認の回答: Q1 = A（フレームログだけ）、Q2 = A（すべての行をスクロールで読める））

**前提となる機能**: 機能 001（ログの CSV 形式）、004（メニュー、プロジェクトファイルの隣への CSV の出力）、007（実行中のメニューのロック）、024（現在のプロジェクトファイル）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 現在のプロジェクトのシミュレーションログを画面で読む (Priority: P1)

ユーザーはシミュレーションを実行した後、メニューの「ログ表示」から、現在のプロジェクトのシミュレーションログを、アプリの中のテキスト表示のウィンドウで読む。表示は読み取り専用で、内容を書き換えることはできない。表計算ソフトやエディターを別に開かなくても結果を確かめられる。

**Why this priority**: 要望の中心。実行結果の CSV は今はファイルとして出力されるだけで、アプリから見る手段が無い。

**Independent Test**: プロジェクトを保存して「開始」で実行し終えた後、「ログ表示」を選び、表示された内容が出力されたログファイルの内容と一致すること、編集できないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 現在のプロジェクトで実行を終え、そのログファイルがある、**When** 「ログ表示」から表示を選ぶ、**Then** ログの内容がテキストで表示される。内容はファイルと同じ（行の順・区切りのカンマを含む）で、スクロールで最後の行まで読める。
2. **Given** ログを表示している、**When** 表示の中で文字を入力・削除・貼り付けしようとする、**Then** 内容は変わらない。文字を選んでコピーすることはできる。
3. **Given** ログを表示している、**When** ウィンドウを閉じる、**Then** ログファイルは変更されていない。
4. **Given** 別のプロジェクトを読み込んだ、**When** 「ログ表示」を選ぶ、**Then** 新しく読み込んだプロジェクトのログが表示される（前のプロジェクトのログではない）。

---

### User Story 2 - ログが無いことがわかる (Priority: P1)

現在のプロジェクトにシミュレーションログが無いとき、「ログ表示」を選ぶと、ログが無いことを知らせるメッセージが出る。空のウィンドウは開かない。

**Why this priority**: 要望に明記されている。何も起きない・空の画面が開くと、操作が失敗したのか、ログが空なのかがわからない。

**Independent Test**: 単体起動の直後（プロジェクトファイルなし）と、実行したことのないプロジェクトを読み込んだ直後に「ログ表示」を選び、メッセージが出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 単体起動の直後でプロジェクトファイルが無い、**When** 「ログ表示」から表示を選ぶ、**Then** 「シミュレーションログがありません」という趣旨のメッセージが出て、表示のウィンドウは開かない。
2. **Given** 一度も実行していないプロジェクトを読み込んだ、**When** 表示を選ぶ、**Then** 同じメッセージが出る。メッセージには、どのプロジェクトのログを探したか（プロジェクトファイル名）と、「開始」で実行するとログができることを示す。
3. **Given** ログファイルはあるが読めない（他のアプリが書き込み中で開けない等）、**When** 表示を選ぶ、**Then** 読めなかったことを示すメッセージが出る（「ログが無い」とは区別する）。

---

### User Story 3 - メニューの並びに「解析」「ログ表示」が加わる (Priority: P2)

メニューバーは「ファイル(F)・編集(E)・シミュレーション(S)・解析(A)・ログ表示(L)」の順になる。「解析」はサブメニューが検討中のため、今回は中身の無い状態（準備中であることがわかる状態）で置く。

**Why this priority**: メニューの枠は要望に明記されているが、「解析」の中身は今回の範囲外。

**Independent Test**: 起動直後のメニューバーの並びと、Alt+A・Alt+L でそれぞれのメニューが開くことを確かめる。

**Acceptance Scenarios**:

1. **Given** 起動直後、**When** メニューバーを見る、**Then** 「シミュレーション(S)」の右に「解析(A)」、その右に「ログ表示(L)」がある。
2. **Given** 起動直後、**When** 「解析」を開く、**Then** 選べない（グレーの）「準備中」の項目だけが表示され、選んでも何も起きない。
3. **Given** 起動直後、**When** Alt+L を押す、**Then** 「ログ表示」のメニューが開く。

---

### Edge Cases

- **実行中・中断中**: 「ログ表示」は「ファイル」「編集」と同じく使えない（グレー）。実行の終わりにログが書き換わるため、古いログを今の実行の結果と取り違えないようにする（機能 007 と同じ扱い）。「解析」も同じくグレーにする。
- **実行後にプロジェクトを別名で保存した場合**: ログはプロジェクトファイルの名前に結び付くので、新しい名前のログは無い（メッセージが出る）。
- **プロジェクトファイルの外でログが消された・書き換えられた場合**: 表示を選んだ時点のファイルの内容を表示する。
- **ログ表示のウィンドウを開いたまま次の操作をする場合**: 「開始」・読込み・セッティングなどを行う前に、ログ表示のウィンドウは閉じる（または閉じるまでそれらの操作をさせない）。表示中のログと現在のプロジェクト・実行結果が食い違わないようにする。
- **ログが非常に大きい場合**（16 ECU・600 秒の実行では数百万行になり得る）: すべての行をスクロールで最後まで読めるようにする（確認の回答 Q2 = A）。ログ全体を一度に画面の部品へ読み込むのではなく、見えている部分を必要に応じてファイルから読むなどして、行数に関係なくすぐに開き、スクロールが引っかからないようにする。
- **ログが空（見出しの行だけ）の場合**: 見出しの行を表示する（「ログが無い」とは扱わない）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: メニューバーの「シミュレーション(S)」の右に「解析(A)」、その右に「ログ表示(L)」を追加しなければならない。アクセスキーは A・L とする。
- **FR-002**: 「解析」には、選べない（グレーの）「準備中」の項目を 1 つだけ置き、選んでも何もしてはならない。サブメニューは後の機能で決める。
- **FR-003**: 「ログ表示」には、シミュレーションログを表示する項目を置かなければならない。表示するログは フレームログ（`<プロジェクトファイル名>.log.csv`）だけとする（確認の回答 Q1 = A）。性能指標の集計（`.summary.csv`）・起動記録（`.startup.csv`）は表示しない。「ログ表示」のメニューの項目は 1 つ（「シミュレーションログ(&L)...」）。
- **FR-004**: 表示の項目を選んだとき、現在のプロジェクトのログファイルがあれば、その内容を読み取り専用のテキストで、ファイルと同じ内容・同じ行の順で表示しなければならない。表示の中で内容を変えることはできず、選択とコピーはできる。
- **FR-005**: 現在のプロジェクトファイルが無い、またはそのログファイルが無いときは、ログが無いことを知らせるメッセージを出し、表示のウィンドウは開いてはならない。メッセージには探したプロジェクトのファイル名（プロジェクトファイルが無いときはその旨）と、「開始」で実行するとログができることを含める。
- **FR-006**: ログファイルがあるのに読めないときは、読めなかったことを示すメッセージ（ファイル名を含む）を出し、FR-005 のメッセージとは区別しなければならない。
- **FR-007**: 表示はログファイルを変更してはならない（開くのは読み取りのためだけ）。
- **FR-008**: 実行中・中断中は「解析」「ログ表示」をメニューバーごとグレーにして開けないようにしなければならない（機能 007 の「ファイル」「編集」と同じ）。
- **FR-009**: ログ表示のウィンドウが開いている間に、表示中の内容と現在のプロジェクト・実行結果が食い違う操作（「開始」、読込み、セッティングの変更、保存先の変更）が行われることがあってはならない。
- **FR-010**: 既存のメニュー（ファイル・編集・シミュレーション）・ツールバー・シミュレーション結果（CSV）の動作は変えてはならない。

### Key Entities

- **シミュレーションログ**: 実行が終わったとき（自然終了・即時完了・「終了」）に、現在のプロジェクトファイルの隣に出力されるファイル。フレームログ `<プロジェクトファイル名>.log.csv`、性能指標の集計 `.summary.csv`、起動記録 `.startup.csv` の 3 つ（機能 004）。
- **現在のプロジェクトファイル**: 機能 024 のタイトルバーに表示しているファイル。ログはこのファイル名から探す。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 実行後に「ログ表示」から表示を選ぶと、ログファイルと 1 文字も違わない内容が、編集できない状態で表示される（行数・先頭と最後の行が一致）。
- **SC-002**: ログが無いときの選択の 100% で、ログが無いことを示すメッセージが出て、空のウィンドウは開かない。
- **SC-003**: サンプルプロジェクトを 10 秒実行したログ（数万行）も、16 ECU・600 秒の実行のログ（数百万行）も、選んでから 2 秒以内に表示され、先頭から最後の行までスクロールで引っかからずに読める。
- **SC-004**: 実行中・中断中の 100% で、「解析」「ログ表示」が開けない。
- **SC-005**: 既存の検証（機能 001〜011・014・015・017〜020・022〜024）がすべて通り、シミュレーション結果（CSV）は変わらない。

## Assumptions

- 「当該プロジェクト」は、機能 024 でタイトルバーに表示している現在のプロジェクトファイルを指す。ログはその隣の、同じ名前に拡張子を足したファイル（機能 004 の出力先）から探す。別のフォルダー・別の名前のログを選んで開く機能は含めない。
- 「シミュレーションログがある」は、そのログファイルが存在することとする。今回のアプリの実行で作られたかどうかは問わない（前回の起動時に実行したログも表示する）。
- 表示は、メインウィンドウとは別のウィンドウに出す。文字は等幅で、CSV の内容をそのまま（表の形に整えずに）表示する。
- 「解析」の項目「準備中」の文言・「ログ表示」の項目名・メッセージの文言は `.rc` の文字列テーブルに置く。
- 表示の中の検索・絞り込み・並べ替え・保存（別名でのエクスポート）は今回の範囲に含めない。
- ログ表示のウィンドウは 1 つだけ開く。開いているときにもう一度選んだら、そのウィンドウを前面に出す（最新の内容に読み直すかは plan で決める）。

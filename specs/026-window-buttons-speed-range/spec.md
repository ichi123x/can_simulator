# Feature Specification: ウィンドウの最小化・最大化ボタンとスピードの範囲の変更

**Feature Branch**: `ver.0.5`（spec ディレクトリ: `026-window-buttons-speed-range`）

**Created**: 2026-10-02

**Status**: Draft

**Input**: User description: "ウィンドウの右上の✖（ウィンドウを閉じる）から少し左にスペースを空けて、ウィンドウの最小化”_”、最大化”□”のアイコンを表示して、機能はウィンドウを最小化、最大化をおこなう。最小化、最大化のアイコン配置は、左が最小化、右が最大化とする。あと、スライドボタンの最小値が-13ですが、最大の時が+10のため、見た目のバランス等を考慮して、-13→-10とします。-13, -12, -11 は使用しない仕様に修正します。"（確認の回答: Q1 = A（最大化しても中身は今の大きさで左上、余りは白）、Q2 = A（Windows 標準のタイトルバーのボタン））

**前提となる機能**: 機能 004（メインウィンドウ、✖ でだけ閉じる）、005（スピード 2^スピード 倍）、009（ログ表示エリア）、010（編集ウィンドウ）、015・019・023（スピードスライダーの位置と目盛り）、025（ログ表示のウィンドウ）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - メインウィンドウを最小化・最大化する (Priority: P1)

ユーザーはメインウィンドウの右上で、✖ の左に並ぶ「_」（最小化）と「□」（最大化）を押して、ウィンドウをタスクバーにしまったり、画面いっぱいに広げたりする。最大化中の「□」は元に戻すボタンになり、押すと最大化前の大きさに戻る。

**Why this priority**: 要望の中心。今はウィンドウを一時的にしまう手段が無い。

**Independent Test**: 起動直後に右上のボタンの並びを見て、最小化 → タスクバーから戻す、最大化 → 元に戻す、を行う。

**Acceptance Scenarios**:

1. **Given** 起動直後、**When** ウィンドウの右上を見る、**Then** 左から「_」（最小化）・「□」（最大化）・「✖」（閉じる）の順に並んでいる。
2. **Given** 起動直後、**When** 「_」を押す、**Then** ウィンドウが最小化されてタスクバーにしまわれ、タスクバーのボタンを押すと元の大きさ・位置・表示内容で戻る。
3. **Given** 起動直後、**When** 「□」を押す、**Then** ウィンドウが画面（作業領域）いっぱいになり、ボタンは「元に戻す」の形に変わる。もう一度押すと最大化前の大きさ・位置に戻る。
4. **Given** 最大化している、**When** 画面を見る、**Then** 構成図・ツールバー・ログ表示エリアは今の大きさ・位置のまま左上に置かれ、右と下の余りは白い余白になる（確認の回答 Q1 = A。端を引っ張って大きさを変えたときと同じ）。ツールバーの暗い帯は今と同じくウィンドウの幅いっぱいに伸び、帯の中の部品は左寄せのまま。
5. **Given** タイトルバーをダブルクリックする、**When** ウィンドウが通常の大きさ、**Then** 最大化する（Windows の標準の動作。もう一度で元に戻る）。

---

### User Story 2 - 実行中・編集中でも最小化・最大化できる (Priority: P2)

シミュレーションの実行中・中断中、データフレーム編集・ログ表示のウィンドウを開いている間でも、最小化・最大化ができ、戻したときに表示・状態は続いている。

**Why this priority**: 実行中に別の作業をするために最小化したいことが多い。状態が壊れないことが前提。

**Independent Test**: 実行中に最小化して数秒後に戻し、シミュレーション時間が進んでいる（または終わっている）ことを確かめる。編集ウィンドウを開いたまま最小化して戻す。

**Acceptance Scenarios**:

1. **Given** 実行中、**When** 最小化して 5 秒後に戻す、**Then** シミュレーションは止まらずに進んでいて（実時間 × 2^スピード）、戻した時点の時刻の表示・ログ表示エリアの行になっている。時間が終端に達していれば、最小化中に完了して CSV が書かれている。
2. **Given** 中断中、**When** 最小化して戻す、**Then** 中断の状態のまま（時刻は進まない）。
3. **Given** データフレーム編集またはログ表示のウィンドウを開いている、**When** メインを最小化する、**Then** それらのウィンドウも一緒に隠れ、戻すと一緒に現れる。

### User Story 3 - スピードの範囲を -10〜+10 にする (Priority: P1)

スピードスライダーの範囲を -13〜+10 から **-10〜+10** に変える。目盛りは -10 から +10 の 21 個になり、左右の端の数字が -10 と +10 で揃う。-13・-12・-11 は選べない。

**Why this priority**: 要望に明記されている。左右の見た目の釣り合いをとる。

**Independent Test**: スライダーの左端・右端までドラッグして、値が -10・+10 で止まることと、目盛りの数・数字の表示を確かめる。

**Acceptance Scenarios**:

1. **Given** 起動直後、**When** スライダーを見る、**Then** 目盛りは -10〜+10 の 21 個で、左端の数字は -10、右端は +10。数字は 5 刻み（-10・-5・0・+5・+10）と今の値を表示する（今の値から 2 目盛り以内の 5 刻みは隠す、機能 019 と同じ）。
2. **Given** スライダーの左端より左を押す・左へドラッグする、**When** 値を見る、**Then** -10 で止まる（-11 以下にならない）。
3. **Given** スピード -10 で開始する、**When** 時間の進み方を見る、**Then** 実時間の 1/1024 で進む（-10 の意味は今と同じ）。
4. **Given** 以前の版で保存したスピード -11〜-13 のプロジェクトファイル、**When** 読み込む、**Then** エラーにせず、スピード -10 として読み込む。保存すると `-10` で書かれる。
5. **Given** スピード -14 以下・+11 以上が書かれたプロジェクトファイル、**When** 読み込む、**Then** 今と同じく範囲外のエラーになる（エラーの文言の範囲は -10〜+10 にする）。

---

### Edge Cases

- **最小化中の書き換え**: 最小化中は画面の書き換えが見えないので、描画を止めてもよい。ただし時刻は実時間で進め、戻したときにその時点の表示にする（中断と同じではない）。
- **最大化中の大きさの変更**: 最大化中はウィンドウの端を引っ張って大きさを変えられない（Windows の標準）。元に戻してから変える。
- **ログ表示・編集ウィンドウの位置**: メインを最大化・元に戻しても、開いているそれらのウィンドウの位置は変えない。
- **編集ウィンドウを開く位置**（機能 010: ログ表示エリアの左端・構成図の下端の 8 px 下）: 最大化中でも同じ規則（メインのクライアント領域を基準）で開く。
- **スライダーの位置**: -10 の目盛りの位置を今の -13 の位置（96 dpi で x 604）にして右へ詰めるか、+10 の位置を保つかは plan で決める（帯の中に収まり、他の部品と重ならないこと）。
- **ドラッグ中のスピード**: -10 より左へ動かしても -10 のまま（-11 以下を経由しない）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: メインウィンドウのタイトルバーの右上に、左から最小化・最大化・閉じるのボタンを表示しなければならない。最小化ボタンはウィンドウを最小化し、最大化ボタンは最大化・元に戻すを切り替えなければならない。ボタンは Windows 標準のタイトルバーのボタンとし、見た目・✖ との間隔・スナップ機能は Windows のテーマどおりとする（確認の回答 Q2 = A。✖ との間に独自の隙間は設けない）。
- **FR-002**: 最小化・元に戻す・最大化の操作は、待機中・実行中・中断中・編集中のどの状態でも行え、実行の状態・シミュレーション時間・ログ表示エリア・ツールバーの状態を変えてはならない。
- **FR-003**: 最大化・元に戻すのとき、構成図・ツールバー・ログ表示エリアの表示と、ECU のダブルクリックなどの当たり判定は、見えている位置と一致しなければならない（US1-4 の配置に従う）。
- **FR-004**: スピードの範囲を -10〜+10 にしなければならない。スライダーの目盛り・数字・当たり判定・ドラッグはこの範囲で行い、-11 以下の値を作ってはならない。
- **FR-005**: プロジェクトファイルの読込みでは、スピード -13〜-11 を -10 として受け入れ、-14 以下・+11 以上は範囲外のエラーにしなければならない。エラーの文言の範囲は -10〜+10 とする。
- **FR-006**: スピードの意味（2^スピード 倍、+10 は待たずに即時完了）、ほかのツールバーの部品・メニュー・シミュレーション結果（CSV）は変えてはならない。

### Key Entities

- **スピード**: -10〜+10 の整数。プロジェクトファイルの `Speed=` に保存する（機能 015）。以前の版の -13〜-11 は読み込み時に -10 になる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 最小化・最大化・元に戻すの操作の 100% で、ウィンドウが期待どおりの状態になり、戻したときに実行の状態・時刻・表示が操作前から続いている。
- **SC-002**: 実行中に最小化して戻したとき、シミュレーション時間は最小化していた実時間 × 2^スピードだけ進んでいる（中断していない）。
- **SC-003**: スライダーで選べる値が -10〜+10 の 21 個ちょうどで、目盛りと数字・つまみが帯の中に重ならずに収まる（DPI 96/120/144）。
- **SC-004**: 以前の版のスピード -13〜-11 のプロジェクトファイルが、エラーなしにスピード -10 として読み込める。
- **SC-005**: 既存の検証（機能 001〜011・014・015・017〜020・022〜025）がすべて通り（スピードの範囲に関わる項目は新しい範囲に合わせる）、シミュレーション結果（CSV）は変わらない。

## Assumptions

- 「スライドボタン」は、ツールバーのスピードスライダー（機能 015）を指す。
- スピード -10 の意味（実時間の 1/1024）は変えない。-13〜-11（1/8192〜1/2048）が選べなくなるだけ。
- メインウィンドウは今も端を引っ張って大きさを変えられる（大きさを変えても中身の配置は変わらない）。最大化もこれと同じ扱いを基本とする。
- データフレーム編集・ログ表示のウィンドウ（ログ表示は既に最小化・最大化のボタンを持つ）は今回変えない。
- 最小化・最大化の状態・大きさはプロジェクトファイルに保存しない。次の起動は今までどおりの大きさで始まる。

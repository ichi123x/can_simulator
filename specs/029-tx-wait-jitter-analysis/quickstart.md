# Quickstart: 送信待ち時間・送信ジッターの確認

## 前提

- 4 構成（Debug/Release × x86/x64）でビルドが通っていること（CLAUDE.md のビルド節）。
- checks をビルドして全項目が通ること。029 の項目は、送信のまとめ方・送信待ち時間・ジッター・周期・間引きと、車両サンプルでの集計 CSV との一致を確かめる（[contracts/ui-analysis-wait-jitter.md](./contracts/ui-analysis-wait-jitter.md)）。
- サンプルは自分のフォルダーにコピーして使う（`sample_vehicle_16ecu.canprj` など）。

## 手動確認（GUI）

1. **メニューの並び**: 起動直後に「解析」を開くと、「送信待ち時間・受信完了時間・送信ジッター・区切り線・CAN バス負荷」の順で、W・R・J・B のキーでそれぞれ選べること（US3-1・2）。
2. **通知**: 起動直後（プロジェクトなし）、一度も実行していないプロジェクト、ログクリアの後、のそれぞれで 2 つの新しい項目を選ぶと、028 と同じ通知が出てウィンドウは開かないこと（US3-3）。
3. **送信待ち時間**: コピーした 16 ECU の車両サンプルを実行してから「送信待ち時間」を選ぶと、表とヒストグラムのウィンドウが 1 秒以内に開くこと（US1-1、SC-004）。
   - 先頭が全体、続いて CAN ID の小さい順の行で、CAN ID・送信 ECU・件数・最小・平均・最大・95% が出ること（US1-2）。
   - CAN ID の大きい行ほど、平均・最大が大きくなる傾向があること（優先度の低いフレームほど待たされる）。
   - 行を選ぶとヒストグラムが切り替わること（US1-3）。説明の行に破棄の件数が出ること。
4. **送信ジッター**: 同じログで「送信ジッター」を選ぶと、表とグラフのウィンドウが開くこと（US2-1）。
   - CAN ID の小さい順の行で、周期・件数・最小・最大・標準偏差が出ること（US2-2）。
   - 値が `.summary.csv` の同じ CAN ID の `Jitter_Max_us`・`Jitter_Min_us`・`Jitter_StdDev_us` と一致すること（SC-003）。
   - 行を選ぶと、時刻に沿ったずれのグラフ（0 の線、点と折れ線、軸の目盛りと値）に切り替わること（US2-4）。
5. **大きなログ**: 16 ECU の車両サンプルをシミュレーション時間 600 秒で実行し、2 つの項目が数秒以内に開くこと。ジッターのグラフで、点が多いときも山と谷が見えること（列ごとの最小〜最大）。
6. **前面に出す・閉じる**: 開いたまま同じ項目を選ぶと前面に出るだけであること。開いたまま「開始」・読込み・セッティング・ログクリアで閉じること（FR-008）。
7. **実行中**: 実行中・中断中は「解析」がグレーで開けないこと。
8. **既存の項目**: 「受信完了時間」「CAN バス負荷」が今までどおり開き、値が変わっていないこと（FR-010）。

## 改訂 1 の手動確認（Release x64 で行う）

9. **解析中のウィンドウ**: 大きなログ（例: `sample_16ecu` を 600 秒実行したログ、約 717 MB）で 4 項目をそれぞれ選ぶと、0.5 秒を過ぎたところで「解析中」（文字・進み具合のバー・「中断」）が出て、その間メインウィンドウを操作できないこと。終わると自動で閉じて解析のウィンドウが開くこと。600 秒・16 ECU の車両サンプルのログ（約 197 MB）では読み込みが約 0.7 秒なので、一瞬出るか出ないこともある。
10. **中断**: 「解析中」が出ている間に「中断」（Esc・✖ でも同じ）を押すと、すぐ閉じて、解析のウィンドウもメッセージも出ないこと。メインウィンドウはまた操作できること。
11. **小さなログ**: `sample_appendix_a` を 10 秒実行したログでは、「解析中」が出ずにすぐ解析のウィンドウが開くこと。

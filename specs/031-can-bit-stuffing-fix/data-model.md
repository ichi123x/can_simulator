# Data Model: ビットスタッフィングを CAN 2.0A の規格どおりに数える

新しい型は増やさない。既存の値型の意味を、規格どおりの数え方に合わせて明確にする。

## FrameTimingResult（`FrameTiming.h`、既存）

| 項目 | 内容（本機能の後） |
|---|---|
| `TotalBits` | SOF〜EOF のビット数。= スタッフビットを差し込んだ後の SOF〜CRC シーケンスのビット数 + 10（CRC デリミタ 1・ACK スロット 1・ACK デリミタ 1・EOF 7） |
| `StuffBitCount` | 差し込んだスタッフビットの数。= 差し込んだ後の SOF〜CRC シーケンスのビット数 − 差し込む前のビット数（19 + 8 × DLC + 15） |
| `BitTimeNs` | 1 ビット時間（1e9 / 通信速度）。変えない |
| `TxDurationNs` | 伝送時間 = `TotalBits` × `BitTimeNs`。インターミッションを含まない。変えない |
| `IntermissionNs` | 3 × `BitTimeNs`。変えない |

決まり:

- 差し込む前の SOF〜CRC シーケンスのビット数は 34 + 8 × DLC（SOF 1・ID 11・RTR 1・IDE 1・r0 1・DLC 4・データ 8 × DLC・CRC 15）。
- `TotalBits` = 34 + 8 × DLC + `StuffBitCount` + 10（機能 030 の `feature_001_tests.cpp` が確かめる関係。変えない）。
- `StuffBitCount` は 0 以上、⌊(34 + 8 × DLC − 1) / 4⌋ 以下（ドメイン仕様書の最悪値。SC-004）。

## フレームのビット列（関数の中の作業用。公開しない）

| 名前 | 内容 |
|---|---|
| 元のビット列 | SOF・ID（MSB から）・RTR=0・IDE=0・r0=0・DLC（MSB から）・データ（各バイト MSB から）・CRC-15（MSB から）。ドミナント 0、レセシブ 1 |
| 差し込んだビット列 | 元のビット列を先頭から順に書き足し、書き足した列の末尾で同じ値が 5 個続くたびに反対の値を 1 つ書き足したもの |

差し込みの決まり（Bosch CAN 2.0A §5、ドメイン仕様書 FR-021）:

- 連続の数は、差し込んだビット列の上で数える。差し込んだスタッフビットは、その値の連続の 1 個目になる。
- CRC シーケンスの最後のビットで 5 連続になったときも、スタッフビットを 1 つ差し込む（CRC デリミタの前）。
- CRC デリミタ・ACK・EOF には差し込まない。

## 伝送時間の表（`SimulationEngine` の中、FR-006）

| 項目 | 内容 |
|---|---|
| キー | ノードの位置（`Network::Nodes` の添字）とフレームの定義の位置（`Node::Frames` の添字） |
| 値 | そのフレームの `FrameTimingResult` |
| 作る時 | エンジンのコンストラクタ（実行の開始時）。全ノードの全フレームを 1 回ずつ計算する |
| 使う時 | 調停に勝ったフレームの送信を始めるとき（今 `ComputeFrameTiming` を呼んでいる所） |

決まり: 表の値は、送信のたびに `ComputeFrameTiming(CanId, Dlc, 定義の Data, 通信速度)` を呼んだ結果と同じ。実行中に定義・通信速度は変わらない。

# Feature Specification: ツールバーのスピードスライダー

**Feature Branch**: `ver.0.3`（spec ディレクトリ: `015-speed-slider`）

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "セッティングからスピード設定を削除する。スピードは、メニュー下のアイコン配置エリアのシミュレーションアイコンの右側にスライドコントールボタンを配置する。スライドコントールボタンのつまみは、長方形（棒状）で、左端が-13で右端が+10とする。スライドコントールの下に、-13,-12,....0,+1,+2.....+10の目盛りを表示し、スライドはその目盛り位置に移動する。また、このスライドはシミュレーション停止中、動作中の両方で操作可能で、動作中の場合はリアルタイムでフレーム表示のスピードを変化させる。"

**前提となる機能**: 機能 004（セッティング・プロジェクトファイル）、機能 005（スピード: 実経過時間 × 2^スピード、+10 = 待たずに即時完了、-13 = 1/8192）、機能 009（ログ表示エリア）、機能 014（ツールバー・中断・再開）。

## 現状（背景）

- スピード（+10〜-13）は「編集 → セッティング」のドロップダウンで選び、「開始」のときの値で実行全体の時間の進み方が決まる。
- 実行中は「編集」メニューがグレー（機能 007）なので、実行中にスピードを変えられない。速すぎる・遅すぎると気づいても、終了してやり直すしかない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ツールバーのスライダーでスピードを選ぶ (Priority: P1)

ユーザーはメニュー下のツールバーで、シミュレーションのボタン（開始・中断・終了）の右にあるスライダーを左右に動かしてスピードを選ぶ。スライダーの下には -13 から +10 までの目盛りが並び、つまみ（長方形の棒）は目盛りの位置にだけ止まる。セッティングにはスピードの項目は無い。

**Why this priority**: スピードの設定場所の移動そのもの（要望の中心）。US2 の前提。

**Independent Test**: 待機中につまみを 0 の目盛りから -3 の目盛りへドラッグして離し、「開始」した実行の時間の進み方が 1/8 になることを確認する。セッティングを開いてスピードの項目が無いことを確認する。

**Acceptance Scenarios**:

1. **Given** 起動直後、**When** ツールバーを見る、**Then** 開始・中断・終了のボタンの右にスライダーがあり、つまみは 0 の目盛りの位置にある。スライダーの下に「-13」「-12」…「0」「+1」…「+10」の 24 個の目盛りの数字が並ぶ（左端 -13、右端 +10）。
2. **Given** 待機中、**When** つまみをドラッグして目盛りの間で離す、**Then** つまみは一番近い目盛りの位置に止まり、スピードはその目盛りの値になる。
3. **Given** 待機中、**When** スライダーの溝（つまみ以外の所）をクリックする、**Then** つまみはクリックした位置に一番近い目盛りへ移る。
4. **Given** スピードを -3 にした、**When** 「開始」する、**Then** シミュレーション時刻は実経過時間の 1/8 で進む（機能 005 と同じ規則）。
5. **Given** 待機中、**When** 「編集 → セッティング」を開く、**Then** スピードの項目は無い（ECU 数・通信速度・シミュレーション時間だけ）。
6. **Given** スピードを +5 にしてプロジェクトを保存し、別のスピードにしてから読み込み直す、**When** 読み込みが終わる、**Then** つまみは +5 の目盛りに戻る（スピードはプロジェクトに保存される）。

---

### User Story 2 - 実行中・中断中にスピードを変える (Priority: P1)

ユーザーは実行中にスライダーを動かし、その場で再生の速さを変える。中断中に動かしておけば、再開からその速さになる。

**Why this priority**: 要望の中心（リアルタイムでの変更）。実行をやり直さずに見たい所をゆっくり・速く見られる。

**Independent Test**: スピード 0 で実行し、3 秒後にスライダーを +2 にして、それ以降のシミュレーション時刻の進みが実時間の 4 倍になり、変更の瞬間に時刻が飛ばない（戻らない）ことを確認する。

**Acceptance Scenarios**:

1. **Given** 実行中（スピード 0）、**When** つまみを +2 に動かす、**Then** その瞬間からシミュレーション時刻が実時間の 4 倍で進む。変更の前後で時刻は連続し（飛ばない・戻らない）、ログの行は欠けも重複もなく続く。
2. **Given** 実行中、**When** つまみをドラッグしている途中で目盛りを通過する、**Then** つまみが止まった目盛りの値が、その時点からスピードとして使われる（ドラッグ中も目盛りごとに反映される）。
3. **Given** 中断中、**When** つまみを -5 に動かして「開始」（再開）する、**Then** 再開後は 1/32 で進む。中断中は時刻は止まったまま。
4. **Given** 実行中または中断中、**When** つまみを +10 に動かす、**Then** その場で最後まで進めて完了とする（「開始」時の +10 と同じ: 全行を表示し、全結果の CSV を出力して完了メッセージを出し、待機に戻る。ユーザー回答 Q1: A）。
5. **Given** 実行中にスピードを何度変えても、**When** 最後まで実行する、**Then** CSV は変えなかった場合と同じ（スピードは表示の進み方だけに効く）。

---

### Edge Cases

- スライダーは、待機・実行中・中断中・データフレーム編集中のいつでも操作できる（グレーにならない）。
- 実行中に「編集」メニューはグレーのまま（機能 007）。スピードはスライダーで変えるので、セッティングを開く必要はない。
- スピード +10 で「開始」した場合は、今までどおり待たずに即時完了する（機能 005）。実行中・中断中に +10 にした場合も同じく即時完了する（FR-009）。
- ドラッグの途中で +10 の目盛りを通過しただけでも、つまみがそこに止まった時点で即時完了になる（ドラッグ中も目盛りごとに反映するため。US2 シナリオ 2）。
- 古いプロジェクトファイルの `Speed=` はそのまま読み込み、つまみの位置に反映する。`Speed=` の無いファイルは 0（機能 005 と同じ）。
- 実行中にスピードを変えても、プロジェクトの保存内容は変わる（次に保存したときに、そのときのスライダーの値が保存される）。実行中は保存できない（機能 007）ので、保存されるのは実行後。
- キーボードでの操作（矢印キー）は行わない（このダイアログは Enter・Esc を握りつぶしており、フォーカスを持つコントロールを置かない方針のため）。
- ツールバーのボタンの押下（機能 014）とスライダーのドラッグは同時に起きない（どちらもマウスの左ボタンを押している間だけ）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 「編集 → セッティング」からスピードの項目を削除しなければならない。セッティングの他の項目（ECU 数・通信速度・シミュレーション時間）の動作は変えてはならない。
- **FR-002**: ツールバーの、開始・中断・終了のボタンの右に、スピードのスライダーを置かなければならない。左端が -13、右端が +10 で、-13 から +10 までの 24 個の整数の位置（目盛り）を等間隔に持つ。
- **FR-003**: スライダーのつまみは長方形（縦長の棒）で、常にいずれかの目盛りの位置に表示しなければならない。
- **FR-004**: スライダーの下に、各目盛りの値（「-13」〜「-1」「0」「+1」〜「+10」）を表示しなければならない。
- **FR-005**: つまみのドラッグ・溝のクリックで、つまみはポインタの位置に一番近い目盛りへ移り、スピードはその目盛りの値にならなければならない。
- **FR-006**: スライダーは、待機・実行中・中断中・編集中のいずれでも操作できなければならない。
- **FR-007**: 実行中にスピードが変わったら、その時点のシミュレーション時刻から新しいスピード（実経過時間 × 2^スピード）で進めなければならない。時刻は連続（飛ばない・戻らない）でなければならず、ログの行・強調は欠けも重複もなく続かなければならない。
- **FR-008**: 中断中にスピードが変わったら、時刻は止めたまま、再開後に新しいスピードで進めなければならない。
- **FR-009**: 実行中・中断中に +10 を選んだら、その場で最後まで進めて完了としなければならない（機能 005 の「開始」時の +10 と同じ処理: 全行の表示、全結果の CSV、完了メッセージ、待機へ）。
- **FR-010**: スピードは今までどおりプロジェクトに含め、保存・読込みで保たなければならない（プロジェクトファイルの形式は変えない）。読込み・起動直後のつまみの位置は、プロジェクトのスピードと一致しなければならない。
- **FR-011**: シミュレーションの計算・CSV の内容・ログの行の内容は、スピードやその変更によって変わってはならない。
- **FR-012**: スライダーを加えても、構成図・ログ表示エリアの大きさと位置（機能 014 のまま）を変えてはならない。

### Key Entities

- **スピード**: -13〜+10 の整数。プロジェクトの一部（保存される）。スライダーのつまみの位置と常に一致する。
- **再生の時計**: シミュレーション時刻。実行中は「最後にスピードが変わった（または再開した）時刻 + その後の実経過時間 × 2^スピード」で進む。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: つまみは 24 個の目盛り以外の位置で止まらない（どこで離しても、一番近い目盛りに止まる）。
- **SC-002**: 実行中にスピードを変えてから 0.1 秒以内に、時刻の進み方が新しいスピードになる。変更の前後で、表示されるシミュレーション時刻が戻ることは 1 回もない。
- **SC-003**: 実行中にスピードを 5 回変えて最後まで実行した CSV は、スピードを変えずに実行した CSV と完全に一致する。
- **SC-004**: セッティングにスピードの項目が無く、スピードはツールバーだけで変えられる。保存・読込みでスピードが保たれる（10 回中 10 回）。
- **SC-005**: 既存の検証（機能 001〜014）がすべて通り、シミュレーション結果（CSV）は変わらない。

## Assumptions

- 「フレーム表示のスピード」は、機能 005 のスピード（再生の時計の進み方。フレーム表示の ON/OFF に関係なくログ表示も同じ時計で進む）を指す。
- スピードはプロジェクトの設定として残す（プロジェクトファイルの `Speed=` を今までどおり読み書きする）。設定の場所がセッティングからツールバーに移るだけ。
- 目盛りの数字は 24 個すべて表示する（間引かない）。今の値の目盛りの数字は強調（太字など）してよい。
- 実行中に +10 を選んで完了した後もスピードは +10 のまま（次の「開始」も即時完了）。
- スライダーの横幅は、ツールバーの中で 24 個の数字が読める幅とする（ウィンドウの幅に収める）。
- マウスホイールでの操作・キーボードでの操作は行わない。

# Quickstart: 015 の検証

## 1. コアの検証（自動、checks.exe）

- 015 の新しい項目（DPI 96/120/144）:
  - 目盛り:
    - 24 個の `SpeedTickX` が左から増え、間隔が `ScaleToDpi(26)` ± 1 px。
    - -13 の目盛りの当たり判定の左端は、終了ボタンの右端より右にある。
    - +10 の目盛りの数字の右端は、ウィンドウの幅（`ScaleToDpi(1140)`）より左にある。
    - 全体が帯の中（高さ `ScaleToDpi(64)` 未満）にある。
  - 隣どうしの数字の範囲が重ならない。各つまみは、その目盛りの x を中心に含む。
  - `SpeedAtX`:
    - 各目盛りの x でその値になる。目盛りの間の点は近い方になる。
    - 左端より左は -13、右端より右は +10 になる。
  - `IsOnSpeedSlider`: つまみ・溝・数字の上で真になる。ボタンの上・帯の外・端の目盛りから pitch/2 を超えた所では偽になる。
  - `GetSpeedChangeAction`: [data-model.md](./data-model.md) の表どおりになる（3 状態 × {-13, 0, +9, +10}）。
- 既存の 001〜014 の項目がすべて PASS し、サンプルの CSV が基準と一致する。

## 2. GUI の確認（Debug|x64、サンプルは一時フォルダにコピー）

詳しい動作は [contracts/ui-speed-slider.md](./contracts/ui-speed-slider.md) を参照。

1. 起動直後: ボタンの右にスライダーがあり、つまみが 0 の目盛りにある（画面の色でつまみの位置を確かめる）。数字が 24 個並ぶ。
2. セッティングを開く → スピードの項目が無い（コンボボックスが無い）。OK で閉じても、スピード（つまみの位置）は変わらない。
3. 待機中、つまみを -3 と -2 の目盛りの中間より少し -3 寄りへドラッグして離す → つまみは -3 の目盛りに止まる。溝の +4 の目盛りの位置をクリック → +4 に移る。
4. スピード -3 で `sample_appendix_a`（10 秒）を「開始」し、2 秒後に「終了」→ 終了メッセージの時刻が約 250,000 µs（2 秒 × 1/8）。
5. スピード 0 で開始し、2 秒後にスライダーを +2 にし、さらに 1 秒後に「終了」→ 時刻が約 2,000,000 + 4,000,000 µs になり、変更の瞬間に戻らない
   （変更の直前と直後に中断して比べた時刻が、直後 ≥ 直前）。
6. 実行中にスピードを 5 回変えて最後まで実行する（+10 は使わない）→ CSV 3 種が、変えなかった実行と一致する（SC-003）。
7. 中断中にスピードを -5 にして再開 → 再開後の時刻の進みが 1/32。
8. 実行中に +10 へドラッグ → その場で完了メッセージが出て、待機に戻る。CSV は最後まで実行したものと一致する。中断中に +10 にしても同じ。
9. スピードを +5 にして保存し、0 にしてから読み込み直す → つまみが +5 に戻る。保存したファイルに `Speed=5` がある。
10. データフレーム編集を開いたままでもスライダーを動かせる。

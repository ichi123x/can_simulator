# Feature Specification: シミュレーションの中断とツールバー（開始・中断・終了）

**Feature Branch**: `ver.0.3`（spec ディレクトリ: `014-sim-pause-toolbar`）

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "シミュレーションメニューに中断を追加し、開始、中断、終了とする。メニューの下の段にシミュレーショングループのアイコンとして、開始、中断、終了を添付画像のイメージで追加する。開始は、シミュレーション開始、中断はシミュレーションを中断状態する。それぞれのボタンのアクティブ、非アクティブ（グレイアウト）は、初期状態：開始ボタン（有効）、停止ボタン（無効）、停止ボタン（無効）。処理中：開始ボタン（無効）、停止ボタン（有効）、停止ボタン（有効）。停止：開始ボタン（有効で開始状態に戻る）、停止ボタン（無効）、停止ボタン（無効）。"（添付画像: 暗い背景の帯に、緑の右向き三角「開始」、青の縦 2 本線「一時停止」、赤の四角「終了」の 3 つの角丸ボタンが並ぶ）

**前提となる機能**: 機能 004（メニュー・開始／終了）、機能 005（スピード・再生の時計・「終了」での途中結果の出力）、機能 007（実行中のメニュー制限）、機能 009（ログ表示エリア）、機能 010（編集中は開始不可）、機能 012（開始時の表示の初期化）。

## 現状（背景）

- 「シミュレーション」メニューには「開始」「終了」の 2 項目しかない。実行中に再生を一時的に止めて、構成図の強調やログをじっくり見ることができない。
- 開始・終了はメニューからしか操作できず、操作のたびにメニューを開く必要がある。

## 用語

- **ボタン**: メニューの下の段（ツールバー）に並ぶ「開始」「中断」「終了」の 3 つのアイコンボタン。ユーザー入力の「停止ボタン（2 つ）」は、それぞれ「中断」ボタンと「終了」ボタンを指すものとする。
- **待機**: シミュレーションを実行していない状態（起動直後、自然終了の後、「終了」の後）。
- **実行中**: 「開始」の後、再生の時計が進んでいる状態（機能 005）。
- **中断中**: 実行中に「中断」した状態。再生の時計が止まり、表示はその時点のまま止まる。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ツールバーのボタンで開始・終了する (Priority: P1)

ユーザーはメニューを開かずに、メニューの下の段のボタンでシミュレーションを開始・終了できる。ボタンは添付画像のイメージ（開始 = 緑の右向き三角、中断 = 青の縦 2 本線、終了 = 赤の四角、それぞれ下に名前）で、状態に応じて有効／無効（グレー）が切り替わる。

**Why this priority**: 開始・終了はもっとも頻繁な操作で、ボタンにするだけで操作の手間が大きく減る。中断が無くても単独で価値がある。

**Independent Test**: 起動直後に「開始」ボタンだけが有効であることを確認し、「開始」ボタンで実行が始まり、「終了」ボタンでメニューの「終了」と同じ結果（その時点までの CSV と完了メッセージ）になることを確認する。

**Acceptance Scenarios**:

1. **Given** 起動直後（待機）、**When** 画面を見る、**Then** メニューの下の段に「開始」「中断」「終了」のボタンが並び、「開始」だけが有効で、「中断」「終了」はグレー。
2. **Given** 待機、**When** 「開始」ボタンを押す、**Then** メニューの「開始」と同じ動作で実行が始まり、「開始」はグレー、「中断」「終了」は有効になる。
3. **Given** 実行中、**When** 「終了」ボタンを押す、**Then** メニューの「終了」と同じ動作（その時点までの結果を出力し完了メッセージ）になり、待機に戻って「開始」だけが有効になる。
4. **Given** 実行中、**When** シミュレーション時間の終わりに達する（自然終了）、**Then** 待機に戻り、「開始」だけが有効になる。
5. **Given** 待機、**When** 「シミュレーション」メニューを開く、**Then** 「開始」「中断」「終了」の 3 項目がこの順に並び、有効／無効はボタンと同じ。

---

### User Story 2 - 実行を中断し、再開する (Priority: P1)

ユーザーは実行中に「中断」（メニューまたはボタン）で再生を止め、構成図の強調・ログ表示をその時点のまま確認できる。中断中は「開始」が有効になり、「開始」を押すと中断した時点から続きを再生する（新しい実行は始めない）。中断中の「中断」はグレー、「終了」は有効（ユーザー回答 Q1: A）。

**Why this priority**: 要望の中心（新しい操作「中断」）。

**Independent Test**: スピード 0 の実行を開始し、数秒後に「中断」して、ログの行・構成図の強調・時刻が止まったままになることを確認し、「開始」で再開すると中断した時点から続きが表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 実行中、**When** 「中断」を選ぶ、**Then** 再生の時計が止まり、ログ表示エリアに新しい行が増えず、構成図の強調はその時点のまま変わらない。「開始」「終了」が有効、「中断」がグレーになる。
2. **Given** 中断中、**When** 時間がたつ（例: 10 秒待つ）、**Then** 表示は変わらない（中断していた時間はシミュレーション時刻に数えない）。
3. **Given** 中断中、**When** 「開始」を選ぶ（メニューまたはボタン）、**Then** 新しい実行は始めず（計算のやり直し・表示の初期化・保存先の確認をしない）、中断した時点のシミュレーション時刻から続きが進み、ログの行は欠けも重複もなく続く。「開始」がグレー、「中断」「終了」が有効に戻る。
4. **Given** 中断中、**When** 「終了」を選ぶ、**Then** 中断した時点のシミュレーション時刻までの結果を出力し（機能 005 の「終了」と同じ）、待機に戻る。
5. **Given** 中断中、**When** ログ表示エリアをスクロール・ホイールで遡る、**Then** 遡って読める（機能 009 のまま）。

---

### Edge Cases

- スピード +10（即時完了）では「開始」の直後に完了して待機に戻るため、「中断」を押す機会はない（実行中の状態にならない）。
- 編集ウィンドウが開いている間・開く待ちの間（機能 010 の「編集中」）は、「開始」ボタンもメニューと同じくグレー。
- 「開始」で保存先を尋ねてキャンセルした場合・保存に失敗した場合は待機のまま（ボタンの状態も変わらない）。
- 実行中・中断中は「ファイル」「編集」メニューをグレーのままにする（機能 007 と同じ。中断中も実行は終わっていないため）。
- 実行中・中断中は、構成図の ECU のダブルクリックで編集ウィンドウを開かない（機能 010 と同じ）。
- 中断中に ✖ でアプリを閉じた場合は、実行中に閉じた場合と同じ扱い（今の動作のまま）。
- グレーのボタンをクリックしても何も起きない。
- 中断中は編集ウィンドウを開けない（「編集」メニューがグレー）ので、中断中に「編集中」になることはない。中断中の「開始」は常に有効。
- 新しい実行を最初からやり直したいときは、「終了」で待機に戻してから「開始」する。
- 中断から再開した後の時間の進み方は、中断前と同じスピード（実経過時間 × 2^スピード）とする。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 「シミュレーション」メニューを「開始」「中断」「終了」の 3 項目とし、この順に並べなければならない。
- **FR-002**: メニューの下の段にツールバーを設け、「開始」「中断」「終了」の 3 つのボタンを添付画像のイメージ（開始 = 緑の右向き三角、中断 = 青の縦 2 本線、終了 = 赤の四角。角丸のボタンで、記号の下に名前）で並べなければならない。無効のボタンはグレーで表示しなければならない。
- **FR-003**: 各ボタンの動作は、対応するメニュー項目とまったく同じでなければならない（別の動作を設けない）。
- **FR-004**: ボタンとメニュー項目の有効／無効は、状態ごとに次のとおりで、常に互いに一致しなければならない。

  | 状態 | 開始 | 中断 | 終了 |
  |---|---|---|---|
  | 待機（起動直後・自然終了後・「終了」後） | 有効（編集中は無効） | 無効 | 無効 |
  | 実行中 | 無効 | 有効 | 有効 |
  | 中断中 | 有効（押すと再開） | 無効 | 有効 |

- **FR-005**: 「中断」は、再生の時計を止め、その時点のシミュレーション時刻・ログ表示・構成図の強調を保たなければならない。中断している間の実経過時間はシミュレーション時刻に数えてはならない。
- **FR-006**: 中断中の「開始」は再開とし、新しい実行は始めてはならない（計算のやり直し、表示の初期化（機能 012）、保存先の確認をしない）。再開では、中断した時点のシミュレーション時刻から、中断前と同じスピードで再生を続けなければならない。ログの行は欠けも重複もなく続かなければならない。
- **FR-007**: 中断中の「終了」は、中断した時点のシミュレーション時刻で機能 005 の「終了」と同じ処理（その時点までの結果の出力と完了メッセージ）をしなければならない。
- **FR-008**: 中断中も、機能 007 のメニュー制限（「ファイル」「編集」をグレー）と機能 010 の制限（ECU のダブルクリックで開かない）を保たなければならない。
- **FR-009**: ツールバーを加えても、構成図・ログ表示エリアの大きさと見た目（位置関係・枠・判定範囲）は変えてはならない。
- **FR-010**: シミュレーションの計算・CSV の内容・ログの行の内容は変えてはならない（中断はいつ・何回しても、最後まで実行した結果と同じ CSV になる。「終了」した場合は、その時点までの結果が機能 005 と同じ）。

### Key Entities

- **実行の状態**: 待機・実行中・中断中。ボタンとメニュー項目の有効／無効を決める。
- **再生の時計**: シミュレーション時刻。実行中だけ進み、中断中は止まる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 3 つの状態（待機・実行中・中断中）と編集中のそれぞれで、3 つのボタンとメニュー項目の有効／無効が FR-004 の表と 100% 一致する。
- **SC-002**: 「中断」を選んでから 0.1 秒以内に、ログ表示エリアの行と構成図の強調が止まる。中断を 10 秒続けても表示は 1 行も変わらない。
- **SC-003**: 実行中に中断・再開を 5 回くり返して最後まで実行した場合、CSV は中断しなかった場合と完全に一致し、ログ表示エリアの行も欠け・重複が無い。
- **SC-004**: 中断中に「終了」した場合、出力された CSV の最後の時刻が中断した時刻を超えない。
- **SC-005**: メニューを開かずに、ボタンだけで開始・中断・再開（中断中の「開始」）・終了の一連の操作ができる。
- **SC-006**: 既存の検証（機能 001〜013）がすべて通り、シミュレーション結果（CSV）は変わらない。

## Assumptions

- 中断からの再開は「開始」で行い、中断した時点から続ける（ユーザー回答 Q1: A。一般的な再生ボタン ▶ ‖ ■ と同じ考え方）。
- 「停止ボタン（2 つ）」はそれぞれ「中断」ボタン・「終了」ボタンを指す（ユーザー入力の状態表の順序から）。「停止」状態は、「終了」した後・自然終了した後の待機を指す。
- ボタンの名前は、メニューと合わせて「開始」「中断」「終了」とする（添付画像の「一時停止」は見た目のイメージとして扱い、名前はメニューに揃える）。
- ツールバーの分だけウィンドウを縦に広げ、構成図・ログ表示エリアはその下に今と同じ大きさで置く（FR-009）。ツールバーの背景は添付画像のような暗い帯とする。
- ツールバーのボタンにはマウスを重ねたときの説明（ツールチップ）を付けてよい（付ける場合は名前と同じ文言）。
- キーボードのショートカット（メニューのアクセスキー以外）は追加しない。
- 中断中はアプリケーション全体の他の操作（ログのスクロールなど表示を見る操作）はできる。

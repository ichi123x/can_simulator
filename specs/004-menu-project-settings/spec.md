# Feature Specification: メニューバー・プロジェクト保存/読込み・設定・フレーム表示・シミュレーション操作

**Feature Branch**: `004-menu-project-settings`

**Created**: 2026-09-29

**Status**: Draft

**Input**: User description: "ダイアログボックスの上部にメニュー ファイル(F)・編集(E)・シミュレーション(S) を配置。ファイル(F)→プロジェクト読込み／プロジェクト保存（拡張子 .canprj）。編集(E)→セッティング／フレーム表示。シミュレーション(S)→開始／終了（シミュレーションの停止）。セッティングでは ECU 数（0〜16）と通信速度（125 k / 250 k / 500 k / 1 Mbps）をリスト選択し、シミュレーション時間（秒）も指定する。フレーム表示は ON/OFF を選択し、ON のときはフレームが送受信している様子をビジュアルで確認できる。初期値は ECU 数=2、通信速度=500 k。現在ダイアログにあるコントロール（設定ファイル欄・参照・シミュレーション時間・実行・結果欄・OK・キャンセル）は、✖ ボタンを除きすべて不要とする。設定ファイルの読込みはプロジェクト読込みと同じとする。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - セッティングで ECU 数・通信速度・シミュレーション時間を選ぶ (Priority: P1)

利用者は、メニュー「編集(E) → セッティング」を開き、ECU 数（0〜16）と通信速度（125 kbps / 250 kbps / 500 kbps / 1 Mbps）をリストから選び、シミュレーション時間（秒）を指定して決定できる。決定した ECU 数は、ダイアログ上の CAN バス構成図（機能 003）の ECU の個数に反映される。

**Why this priority**: ネットワークの規模・通信速度・実行時間は、すべての操作の前提となる基本設定であり、プロジェクトの保存内容（US2）とシミュレーション（US3）もこの設定を土台とする。

**Independent Test**: アプリケーションを起動し、初期値が ECU 数=2・500 kbps であることを確認したのち、セッティングで各値を変更して決定し、構成図の ECU 数が変わること、セッティングを開き直すと選んだ値が表示されることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 起動直後、**When** 構成図とセッティングを確認する、**Then** 構成図には ECU 01・ECU 02の2個が表示され、セッティングの ECU 数は 2、通信速度は 500 kbps、シミュレーション時間は 10 秒が選択されている。
2. **Given** セッティングを開いた状態、**When** ECU 数のリストを開く、**Then** 0〜16 の17通りが選択肢として並び、それ以外の値は入力できない。通信速度のリストには 125 kbps・250 kbps・500 kbps・1 Mbps の4通りだけが並ぶ。
3. **Given** セッティングで ECU 数を 16 に変更して決定、**When** 構成図を見る、**Then** ECU 01〜16 が表示される。ECU 数を 0 にして決定した場合は、CAN バスの線と見出しだけが表示される。
4. **Given** セッティングを開いて値を変更したあとキャンセルした、**When** 構成図とセッティングを確認する、**Then** 変更は反映されず、元の値のままである。
5. **Given** シミュレーション時間に 1〜600 の整数以外（0、負数、小数、空欄、文字、601 以上）を入力、**When** 決定しようとする、**Then** 決定できず理由が表示される。

### User Story 2 - プロジェクトを保存・読込みする (Priority: P1)

利用者は、メニュー「ファイル(F) → プロジェクト保存」で現在の内容をファイルに保存し、「ファイル(F) → プロジェクト読込み」で保存したファイルを読み込んで同じ状態を復元できる。ファイルの拡張子は `.canprj` とする。プロジェクトファイルは、従来の設定ファイル（.cfg）の後継であり、ECU の送信フレーム定義など、シミュレーションに必要な内容をすべて含む。

**Why this priority**: 設定を毎回入力し直さずに済むこと、および ECU が送信するフレームを取り込む唯一の入口であることから、US1 と同等に必須。

**Independent Test**: ECU 数と通信速度を変更して保存し、アプリを再起動して読み込み、構成図とセッティングの値が保存時と一致することを確認する。フレーム定義を含むプロジェクトを読み込み、US3 でそのフレームが送信されることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** ECU 数=5・通信速度=250 kbps・シミュレーション時間=20 秒・フレーム表示=ON の状態、**When** プロジェクトを保存してアプリを再起動し、そのファイルを読み込む、**Then** 4つの設定とフレーム定義が復元され、構成図には ECU 01〜05 が表示される。
2. **Given** 保存ダイアログ、**When** ファイル名を入力する、**Then** 既定の拡張子は `.canprj` で、ファイルの種類は `.canprj` として表示される。
3. **Given** 拡張子が `.canprj` でない、または内容が壊れているファイルを読み込もうとした、**When** 読み込む、**Then** 読み込めなかった理由が表示され、現在の内容は変更されない。
4. **Given** 範囲外の値（ECU 数=17、選択肢にない通信速度、重複した CAN ID など、機能 001 の検証規則に違反する内容）を含む `.canprj` を読み込んだ、**When** 読み込む、**Then** その旨が表示され、現在の内容は変更されない。
5. **Given** フレーム定義がセッティングの ECU 数より大きな番号のノードを含む `.canprj`、**When** 読み込んで実行する、**Then** セッティングの ECU 数が優先され、範囲を超える番号のノードのフレームは送信されない。ECU 数が定義より多い場合、フレーム定義のない ECU は何も送信しない。

### User Story 3 - シミュレーションを開始・終了する (Priority: P1)

利用者は、メニュー「シミュレーション(S) → 開始」でシミュレーションを開始し、「シミュレーション(S) → 終了」で途中で終了できる。開始後は、セッティングで指定した時間まで進み、結果（ログ・集計・起動記録）が保存される。

**Why this priority**: 現在のダイアログの「実行」ボタンに代わる、シミュレーション実行の唯一の入口である。

**Independent Test**: フレーム定義を含むプロジェクトを読み込み、「開始」で実行し、指定時間の経過後に結果ファイルが出力されることを確認する。実行中に「終了」を選び、その時点までの結果が出力されることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** プロジェクトを読み込んだ状態、**When** 「開始」を選ぶ、**Then** シミュレーションが始まり、指定時間に達すると自動的に終了して、3種の結果ファイル（フレームログ・集計・起動記録）がプロジェクトファイルと同じ場所に出力され、完了したことが利用者に通知される。
2. **Given** シミュレーションの実行中、**When** 「終了」を選ぶ、**Then** その時点でシミュレーションが止まり、それまでに送信を完了したフレームだけを含む結果ファイルが出力される。
3. **Given** シミュレーションの実行中、**When** メニューを確認する、**Then** 「開始」は選べず、「終了」は選べる。実行中でないときは逆に、「開始」は選べ、「終了」は選べない。
4. **Given** プロジェクトを一度も保存も読込みもしていない起動直後、**When** 「開始」を選ぶ、**Then** 結果の出力先を決めるために保存先の指定が求められ、指定後にシミュレーションが始まる。指定をキャンセルした場合はシミュレーションを開始しない。
5. **Given** ECU 数=0、または送信フレームが1つもない状態、**When** 「開始」を選ぶ、**Then** エラーにならず、フレームのない（ヘッダのみの）結果が出力されて終了する。

### User Story 4 - フレームの送受信の様子をビジュアルで確認する (Priority: P2)

利用者は、メニュー「編集(E) → フレーム表示」で ON / OFF を切り替えられる。ON のときは、シミュレーション中に各フレームがどの ECU から送信され、どの ECU が受信しているかを、構成図上でビジュアルに確認できる。OFF のときは、フレームの送受信の様子を表示しない。

**Why this priority**: 送受信の流れを目で追えることは大きな価値だが、これがなくてもシミュレーションの実行と結果出力（US3）は成立するため、優先度は2番目とする。

**Independent Test**: フレーム表示を ON にして複数ノードの構成でシミュレーションを開始し、送信元のECU と受信側の ECU、およびバスが、フレームごとに視覚的に区別できることを確認する。OFF にして同じ構成を実行し、何も表示されないことを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** フレーム表示=ON、**When** シミュレーションを開始する、**Then** 時刻に沿ってフレームが1つずつ表示され、送信中は送信元 ECU とバス上のフレームが強調表示され、受信した ECU も強調表示される。フレームの送信が終わると強調表示は消える。
2. **Given** フレーム表示=ON で、2つのノードが同時に送信要求した構成、**When** 実行する、**Then** 調停に勝った ECU のフレームが先に表示され、負けた ECU は次の機会に表示される。
3. **Given** フレーム表示=OFF、**When** 同じ構成を実行する、**Then** 送受信の強調表示は一切行われず、実行結果（ログ・集計の CSV）は ON のときと完全に同一である。
4. **Given** メニューを開いた状態、**When** 「フレーム表示」の項目を見る、**Then** 現在の ON / OFF がチェックマーク等で判別できる。
5. **Given** フレーム表示=ON でシミュレーションを実行中に「終了」を選んだ、**When** 構成図を見る、**Then** 強調表示は消え、構成図は通常の表示に戻る。

---

### User Story 5 - メニューバーと、白いだけの作業領域 (Priority: P2)

利用者は、ダイアログのタイトルバーの直下にメニューバー「ファイル(F)」「編集(E)」「シミュレーション(S)」を見ることができ、メニュー1行分の下側のダイアログ全体が白で表示される。ダイアログには、閉じるための✖ ボタン以外の操作用コントロール（ボタン・入力欄・結果欄）は表示されない。

**Why this priority**: 上記のストーリーの操作入口であり、見た目の基盤だが、機能そのものは US1〜4 が担うため P2 とする。

**Independent Test**: 起動直後にタイトルバー直下のメニュー3項目と、その下が白の構成図だけであることを確認すれば、単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 起動直後、**When** ダイアログを見る、**Then** タイトルバーの直下にメニュー「ファイル(F)」「編集(E)」「シミュレーション(S)」がこの順で表示される。
2. **Given** 起動直後、**When** ダイアログを見る、**Then** メニュー1行分の下から、ダイアログのクライアント領域全体の背景が白で、CAN バス構成図以外に表示されるものがない。
3. **Given** 起動直後、**When** ダイアログを見る、**Then** 従来の「設定ファイル」欄・「参照...」・「シミュレーション時間(秒)」欄・「実行」・「結果」欄・「OK」・「キャンセル」は表示されない。ダイアログは右上の ✖ で閉じられる。
4. **Given** Alt+F / Alt+E / Alt+S、**When** 押す、**Then** それぞれのメニューが開く。

---

### Edge Cases

- ECU 数を現在より減らして決定した場合、構成図は減った数の ECU を表示する。
- プロジェクトを保存せずにアプリを閉じた場合、内容は保存されない（保存の確認や自動保存は行わない）。
- 保存先に同名のファイルがあるとき、上書きしてよいか確認する。
- 読み込み中にファイルが開けない場合（他のプログラムが使用中など）は、理由を表示して現在の内容を保つ。
- シミュレーションの実行中に「プロジェクト読込み」を選んだ場合は、読み込みを拒否する（実行中に内容を変えない）。実行中の「セッティング」も同様に、変更を受け付けない。
- シミュレーション実行中に ✖ でダイアログを閉じた場合は、シミュレーションを中断して閉じる。結果ファイルは出力しない。
- Enter キー・Esc キーを押しても、ダイアログは閉じない（誤操作防止。閉じるのは ✖ のみ）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、ダイアログのタイトルバー直下に、左から「ファイル(F)」「編集(E)」「シミュレーション(S)」のメニューを表示しなければならない。
- **FR-002**: 「ファイル(F)」には「プロジェクト読込み」「プロジェクト保存」の2項目を含めなければならない。
- **FR-003**: 「編集(E)」には「セッティング」「フレーム表示」の2項目を含めなければならない。
- **FR-004**: システムは、メニュー1行分の下側のダイアログ全体を白で表示しなければならない。
- **FR-005**: 「セッティング」は、ECU 数と通信速度を、いずれもリストからの選択で指定できる画面を開かなければならない。ECU 数の選択肢は 0〜16 の整数、通信速度の選択肢は 125 kbps・250 kbps・500 kbps・1 Mbps の4つとする。選択肢以外の値は入力できない。同じ画面で、シミュレーション時間（秒）を 1〜600 の整数で指定できなければならない。
- **FR-006**: システムは、初期値を ECU 数=2、通信速度=500 kbps、シミュレーション時間=10 秒、フレーム表示=OFF としなければならない。
- **FR-007**: システムは、セッティングで決定された ECU 数を、CAN バス構成図（機能 003）の ECU の個数に反映しなければならない。キャンセルした場合は現在の値を変更してはならない。
- **FR-008**: 「プロジェクト保存」は、現在の ECU 数・通信速度・シミュレーション時間・フレーム表示の設定と、ECU の送信フレーム定義を、拡張子 `.canprj` のファイルに保存しなければならない。保存先とファイル名は利用者が指定する。
- **FR-009**: 「プロジェクト読込み」は、`.canprj` ファイルを選んで読み込み、保存されていた設定とフレーム定義を復元しなければならない。復元後、構成図とセッティングの表示は読込んだ値と一致しなければならない。
- **FR-010**: システムは、`.canprj` ファイルが読み込めない場合（形式不正、値が範囲外・選択肢外、機能001 の検証規則に違反、ファイルを開けない）、その理由を利用者に示し、現在の内容を変更してはならない。
- **FR-011**: システムは、シミュレーションの ECU 数・通信速度として、常にセッティング（およびプロジェクトに保存された値）を用いなければならない。フレーム定義のうち、ECU 数を超える番号のノードのものは送信に使わず、フレーム定義のない ECU は何も送信しない。
- **FR-012**: 「フレーム表示」は ON / OFF を選択でき、現在の状態をメニュー上で判別できなければならない。
- **FR-013**: フレーム表示が ON のとき、システムは、シミュレーションで各フレームが送信されている間、送信元 ECU とバスを、また受信した ECU を、他と区別できる形で表示しなければならない。フレームの送信が終わったときはその表示を消さなければならない。
- **FR-014**: フレーム表示が OFF のとき、システムはフレーム送受信の様子を一切表示してはならない。
- **FR-015**: フレーム表示の ON / OFF は、シミュレーションの実行結果（ログ CSV・集計 CSV・起動記録CSV）に影響してはならない。同一構成からは、ON と OFF のどちらでも同一の結果を得ること。
- **FR-016**: 「シミュレーション(S)」には「開始」「終了」の2項目を含めなければならない。
- **FR-017**: 「開始」は、現在のプロジェクト内容でシミュレーションを開始し、セッティングのシミュレーション時間に達した時点で自動的に終了して、3種の結果ファイルをプロジェクトファイルと同じ場所に出力し、完了を利用者に通知しなければならない。プロジェクトファイルの場所が未定のときは、保存先の指定を求めなければならない。
- **FR-018**: 「終了」は、実行中のシミュレーションを、その時点で終了しなければならない。それまでに送信を完了したフレームだけを含む結果ファイルを出力すること。
- **FR-019**: システムは、シミュレーションの実行中は「開始」「プロジェクト読込み」「セッティング」を受け付けてはならず、実行中でないときは「終了」を受け付けてはならない。
- **FR-020**: システムは、ダイアログに ✖（閉じる）ボタン以外の操作用コントロール（ボタン・入力欄・結果欄）を表示してはならない。Enter・Esc でダイアログを閉じてはならない。

### Key Entities *(include if feature involves data)*

- **プロジェクト**: ECU 数（0〜16）、通信速度（125 k / 250 k / 500 k / 1 M bps のいずれか）、シミュレーション時間（1〜600 秒）、フレーム表示（ON / OFF）、ECU の送信フレーム定義。`.canprj` ファイルとして保存・読込みされる単位。従来の設定ファイル（.cfg）の後継。
- **シミュレーションの実行状態**: 停止中／実行中のいずれか。メニューの選択可否を決める。
- **フレーム表示状態**: シミュレーション実行中の、現在送信中のフレームの送信元 ECU と、受信している ECU の集合。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 起動直後の設定は、ECU 数=2・500 kbps・10 秒・フレーム表示=OFF であり、構成図には ECU がちょうど2個表示される。
- **SC-002**: ECU 数の選択肢は 0〜16 の17個、通信速度の選択肢は4個で、これ以外の値はいずれの操作でも設定できない。
- **SC-003**: 保存したプロジェクトを読み込むと、設定4項目とフレーム定義のすべてが保存時と完全に一致する（100%）。ただし、ノード定義が 1 つも無い状態で保存した場合は、読み直せるようにフレームの無いノード（ECU 1〜ECU 数、ECU 数 0 なら ECU 1）が加わる。フレーム定義は無いまま、実行結果も保存前と同じである。
- **SC-004**: 不正な `.canprj`（拡張子違い・壊れた内容・範囲外の値・検証規則違反）を読み込んだ場合、全ケースで理由が表示され、現在の内容は変化しない。
- **SC-005**: フレーム表示 ON のとき、実行中の任意の瞬間に、送信中のフレームの送信元 ECU を利用者が目視で特定できる。OFF のときは強調表示が0件である。
- **SC-006**: 同一構成でフレーム表示を ON と OFF で実行したとき、出力される3種の CSV が完全に一致する。
- **SC-007**: 起動直後、メニュー3項目がこの順で表示され、メニュー1行分の下側のダイアログ全体が白で、構成図以外に表示されるものがない。
- **SC-008**: 「開始」から指定時間の経過までに、結果ファイル3種が出力される。「終了」を選んだ場合は、選択した時点までに送信を完了したフレームの行数と一致する結果が出力される。
- **SC-009**: フレーム表示 OFF のとき、機能 001・002 と同じ構成（同じフレーム定義・通信速度・時間）で得られる結果ファイルの内容が、機能 001・002 の結果と一致する。

## Assumptions

- プロジェクトファイル（`.canprj`）は、従来の設定ファイル（.cfg）の後継であり、本機能以降、ECU の送信フレーム定義を取り込む唯一の入口となる（メニューに .cfg の読込みは設けない）。フレーム定義を編集する画面は本機能のスコープ外で、利用者がテキストエディタ等で `.canprj` に記述する。既存のサンプル構成（`sample_*.cfg`）は `.canprj` 形式へ移行する。
- 「シミュレーション時間」の範囲は 1〜600 秒の整数（実測で、3600 秒はログ約 600 万行・CSV 約 670 MB・Release でも約 30 秒を要し、実用的でないため 600 秒を上限とする）、既定値は 10 秒とする（従来の入力欄の既定値を踏襲）。
- フレーム表示の初期値は OFF とする（指定がなかったため）。
- 「白」は機能 003 と同様に、システムのテーマに依存せず常に白とする。003 では表示部を構成図の領域としていたが、本機能で「メニュー1行分の下側のダイアログ全体」に拡張する。
- 従来のコントロール（設定ファイル欄・参照・シミュレーション時間・実行・結果欄・OK・キャンセル）は削除する。結果のテキスト表示は行わず、完了・エラーは通知（メッセージ）で示す。
- 結果ファイルの出力先は「プロジェクトファイルと同じ場所」とし、名前は `<プロジェクトファイル名>.log.csv`など、従来の命名規則（`.log.csv`・`.summary.csv`・`.startup.csv`）に従う。
- フレーム表示 ON のときの動きは、シミュレーションの時刻に沿って1フレームずつ表示しながら進む形とし、進む速さは視認できる固定の速度とする（実時間との対応は求めない）。フレーム表示 OFF のときは表示を伴わず、できるだけ速く終了する。速度の調整、一時停止、コマ送りは本機能のスコープ外。
- 「終了」は、「終了時点までに送信を完了したフレーム」を結果とし、送信途中のフレームは含めない。
- セッティングの ECU 数・通信速度はネットワークの規模と速度を決める設定であり、各 ECU の送信フレームの編集は本機能のスコープ外（別機能で扱う）。
- 機能 003 の「起動直後は ECU 0 個」という前提（003 の US3・FR-007・SC-003 の初期状態）は、本機能の初期値 ECU 数=2 により置き換わる。003 の ECU 数=0 の表示は、セッティングで ECU 数を 0 にした場合の挙動として残る。また 003 で「既存のコントロールを新サイズでも操作可能な位置に残す」としていた前提は、本機能で既存コントロールを削除することにより不要になる。
- メニューの項目名は日本語表示とし、リソース側で管理する。
- 「プロジェクト保存」の上書き確認とエラー表示は標準的なダイアログ操作に従う。

# Research: メニューバー・プロジェクト保存/読込み・設定・フレーム表示・シミュレーション操作

## 決定1: `.canprj` は `.cfg` 形式の拡張とし、`ConfigLoader` を再利用する
- **Decision**: 形式は機能 001 の `[Network]`／`[NodeN]`／`[NodeN.FrameM]` 構文を踏襲し、新しく`[Project]` セクション（`EcuCount`、`DurationSec`、`FrameDisplay`）を任意で追加する。既定値はspec FR-006（2、10、OFF）。通信速度は既存の `[Network] BitRateBps` を使う（単一の情報源）。`ConfigLoader` は `[Project]` の読込みを追加し、検証規則（CAN ID 重複、Dlc=Data、NodeId 1〜16 等）はそのまま再利用する。ノード 0 個（`[NodeN]` なし）は、機能 001 FR-001 のとおり読込みで拒否する（当初は許容としたが、のちに拒否へ戻した）。
- **Rationale**: 001 の検証を作り直さずに済む。サンプルと利用者の記述負担が最小。
- **Alternatives**: JSON 形式 — 新規パーサが必要。`.cfg` と `.canprj` の併用 — メニューに `.cfg` の読込みは設けない（spec Assumptions）ため不要。

## 決定2: 実行用ネットワークの生成 (`BuildRunNetwork`)
- **Decision**: プロジェクト（`ProjectSettings` ＋ 読込んだ `Network` 定義）から、ECU 番号 1〜EcuCount のノードを持つ `Network` を作る。定義に同番号のノードがあればその内容を使い、なければ名前`ECU<n>`・フレームなしの空ノードを補う。EcuCount を超える番号のノード定義は捨てる。通信速度は`Network.BitRateBps`。ノードは NodeId 昇順（既存エンジンの前提）。
- **Rationale**: spec FR-011 と受け入れシナリオ US2#5。定義のない ECU も起動制御・受信の対象になる。
- **注意**: CAN ID の重複検証は「定義全体」で読込み時に行う（範囲外ノードも対象。実行時に一部が捨てられても重複はない状態を保つ）。

## 決定3: 保存 (`SaveProject`)
- **Decision**: `ProjectSettings` と、読込み済みの `Network` 定義（全ノード定義を保持）から同形式のテキストを書き出す。読込んだ定義は、セッティングで ECU 数を減らしても保存時に消さない（定義は保持し、ECU 数だけを更新する）。コメントと項目順の再現はしない（再保存でコメントは失われる）。再読込みで設定と定義が完全一致することを検証項目に含める（SC-003）。
- **Alternatives**: 元ファイルへの差分書き込み — 複雑でコメント維持の要求もない。

## 決定4: 実行とフレーム再生
- **Decision**: 「開始」で、その場で `SimulationEngine(BuildRunNetwork(...), DurationSec*1e6)` をUI スレッドで同期実行して `Logger` を得る（現在の実行ボタンと同じ）。フレーム表示 OFF のときはそのまま 3 種の CSV を書いて完了通知。ON のときは、結果から `FrameEvents` を作り、タイマー再生に移り、再生が終端に達したところで CSV を書いて完了通知する。
- **再生方式**: **フレーム単位のステップ再生**。1 フレームを固定時間（既定 250 ms）表示して次へ進む。フレーム間の空き時間は飛ばす。表示中は送信元 ECU・バス・受信 ECU を強調表示し、直後に消す。実時間との対応は求めない（spec Assumptions）。
- **「終了」**: 再生中に選ばれたら、現在表示中のフレームの送信開始時刻 `t` を終了時刻とし、`SimulationEngine(同じネットワーク, t)` を再実行して、`t` までの結果で 3 種の CSV を書く。（エンジンの既存仕様「シミュレーション終了時点で送信を完了していないフレームは含めない」をそのまま使う。決定的な再実行のため、ON/OFF で結果が変わらず SC-006/008 を満たす。）
- **Rationale**: エンジンに手を入れず、決定性（再現性）を保つ。スレッド化しないため YAGNI と整合。10 秒程度のシミュレーションは同期実行で 1 秒未満（機能 001 の目標）。
- **Alternatives**: エンジンのステップ実行化 — DES ループの大改修。別スレッド実行 — 同期・キャンセルの複雑化。
- **同期実行中の UI**: 計算中は UI が反応しない。実測（Release、6 ECU）で 3600 秒は約 30 秒・CSV 約 670 MB を要したため、シミュレーション時間の上限を 600 秒（約 5 秒・約 110 MB）に下げ、実行中は待機カーソルを表示する。スレッド化はしない（YAGNI）。
- **既知の制約**: 再生時間が長い場合（数千フレーム）、全部見るには時間がかかる。速度調整はスコープ外。「終了」で途中停止できる。
- **要確認（実装時）**: 既存エンジンが「終了時刻をまたぐ送信中フレーム」をログに含めるかは、実装時にコードで確認し、SC-008 の「送信を完了したフレームのみ」と一致することを検証項目にする。

## 決定5: メニューの実装 (`CDialogEx` 上のメニュー)
- **Decision**: `.rc` に `MENU` リソースを追加し、ダイアログ定義に `MENU IDR_MAINMENU` を指定する。コマンドは `ON_COMMAND` で処理する。ダイアログは `ON_UPDATE_COMMAND_UI` を自動配送しないため、`WM_INITMENUPOPUP` で実行状態に応じて項目の有効/無効・「フレーム表示」のチェックを設定する。メニューは非クライアント領域のため、機能 003 の「図はクライアント左上」がそのままメニューの下に入る。ニーモニックは `ファイル(&F)`／`編集(&E)`／`シミュレーション(&S)`。
- **Rationale**: 標準機能で完結する。

## 決定6: 既存コントロール削除と Enter/Esc の抑止
- **Decision**: 既存のコントロール（設定ファイル欄・参照・時間欄・実行・結果欄・ラベル・OK・キャンセル）と対応する ID（`IDC_EDIT_CONFIG_PATH` 等）、ハンドラ（`OnBnClickedButtonBrowse/Run`、`SetResultText`）を削除する。`OnOK` は何もしない。`PreTranslateMessage` で `VK_ESCAPE`／`VK_RETURN` のキー押下を握りつぶす（`OnCancel` は削除しない: ✖ の `WM_CLOSE` が `OnCancel` を経由するため）。✖ で閉じるとき、実行中ならタイマーを止めて結果を出力せずに閉じる。
- **Rationale**: spec FR-020 と Edge Cases。

## 決定7: ダイアログ全体の白
- **Decision**: `OnEraseBkgnd` でクライアント領域全体を白で塗り、003 の図の描画はその上に行う。コントロールが残らないため `WM_CTLCOLOR` の処理は不要。ダークテーマでも白のまま（明示塗り）。セッティング画面（別ダイアログ）は既定の見た目でよい（spec FR-004 の対象はメインダイアログ）。

## 決定8: セッティング画面
- **Decision**: 新規ダイアログ `IDD_SETTINGS`（`CSettingsDlg`）。ECU 数 `CComboBox`（`CBS_DROPDOWNLIST`、0〜16）、通信速度 `CComboBox`（`CBS_DROPDOWNLIST`、4 項目）、シミュレーション時間`CEdit`（`ES_NUMBER`、1〜600 を OK で検証。範囲外はメッセージを表示して閉じない）、OK／キャンセル。OK で `ProjectSettings` と通信速度を返す。キャンセルは何も変えない。
- **Rationale**: 標準コントロールで足りる。

## 決定9: 出力先と通知
- **Decision**: 出力パスは `<プロジェクトのファイルパス>.log.csv` / `.summary.csv` / `.startup.csv`（従来の `<設定ファイル名>.…` と同じ規則）。プロジェクトの場所が未定なら、「開始」時に保存ダイアログ（`CFileDialog` 保存）で場所を求め、`SaveProject` を実行してから続ける（キャンセルなら開始しない）。完了・エラーは `AfxMessageBox`（文字列は `.rc` の文字列テーブル）で通知する。

## 決定10: 003 との接続
- `SetEcuCount` は、セッティング決定時とプロジェクト読込み成功時のみ呼ぶ。キャンセル・失敗では呼ばない（003 の FR-010）。003 の `m_ecuCount` の初期値 2 は本機能の FR-006 と同じ。

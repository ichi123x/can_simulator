# Research: データフレーム編集ウィンドウ

## 決定1: 検査と一覧操作を CanSim/FrameEditor に置く
- **Decision**: `ValidateFrame(definitions, nodeId, editIndex, input)` が問題の一覧（項目と理由のコード）を返す。`AddFrame` / `ReplaceFrame` / `DeleteFrame` はノードの一覧を更新し、`MakeFrameData(dlc)` は 0xFF の並びを返す。ノード定義がまだない ECU（フレームなしで補われていたもの）に追加する場合は、`NodeId = n`・名前 `ECU<n>`・既定値のノード定義を作る（`BuildRunNetwork` の補完と同じ）。
- **Rationale**: 憲章 III。検査規則は `ConfigLoader` と同じ条件（ID 範囲、DLC 範囲、全ノードでの ID 重複、100 上限）にそろえ、checks.exe で検証する。
- **検査の範囲**: ID 重複は、ECU 数の範囲外のノードも含む全定義で調べる（spec Edge Cases）。

## 決定2: 入力値の型
- ID: 16 進文字列（`0x` 省略可、大文字小文字を問わない）→ 0x000〜0x7FF。
- DLC: 0〜8 の整数。
- 送信周期: ms の整数、1 以上。上限は 3,600,000 ms（1 時間）とする（int のあふれ防止。シミュレーション時間の上限600 秒を超える周期は実質 1 回だけ送信される）。
- 初回オフセット: ms の整数、0 以上かつ送信周期未満。空欄は 0。
- フレーム名: 0〜32 文字（UTF-16 の文字数で数える）。
- ファイル上は µs（`PeriodUs`、`InitialOffsetUs`）のまま。ms × 1000 で保存する。

## 決定3: データを常に DLC 分の 0xFF にする
- **Decision**: `ConfigLoader` は `Data=` を読み飛ばし（書かれていても誤りにしない＝後方互換）、`Data` を `0xFF × Dlc`で作る。`SaveProject` は `Data=` を書かない。サンプルの `Data=` 行は削除する。
- **影響**: スタッフビット数が変わり、既存サンプルの伝送時間・バス負荷・送信待ち遅延などが変わる。
- **Alternatives**: 読込み時に変換せず残す — 利用者の決定（spec FR-014）により採らない。

## 決定4: 最初の送信要求の起点を通常動作開始に変える
- **Decision**: `SimulationEngine::Run` の開始時に TxRequest を積むのをやめ、`HandleSyncComplete`（ノードが通常動作に入った時点）で各フレームの最初の TxRequest を `NormalEntry + InitialOffset` に積む。2 回目以降は現在どおり「直前の要求 + 周期」。ノードが通常動作に到達しなければ送信要求は発生しない。
- **同時刻の順序**: `SyncComplete`（種別 5）は `TxRequest`（種別 6）より先に処理されるので、オフセット 0 の要求は同じ時刻に積んでも同じ時刻のうちに処理される（002 の同時刻規則を維持）。
- **影響**: 起動前に要求が出ることがなくなり、002 の「起動前の要求の保留」（002 FR-010）と上書き回数の累積（起動待ち中の上書き）は起きなくなる。該当する checks.exe の項目は、新しい起点での期待値に置き換える。
- **Rationale**: Doc FR-020a（送信要求の時刻 = 起点 + 初回オフセット + n × 周期、起点 = 通常動作開始）。

## 決定5: 100 フレームの上限
- `kMaxFramesPerNode = 100`。編集ウィンドウでは「追加」を無効化し、`ConfigLoader` は 101 以上のノードを拒否する（Doc FR-091）。

## 決定6: 編集ウィンドウの UI
- モーダルダイアログ `IDD_FRAME_EDIT`: ノード選択（`CBS_DROPDOWNLIST`、ECU 1〜EcuCount の「ECU NN」）、一覧（`CListCtrl` レポート、1 行選択、列: No. / フレーム名 / ID / DLC / 初回オフセット(ms) / 送信周期(ms)）、「追加」「編集」「削除」「閉じる」。一覧のダブルクリックは「編集」と同じ。
- 入力画面 `IDD_FRAME_ENTRY`: フレーム名・ID・DLC・送信周期・初回オフセットの入力欄、ビット長と伝送時間の表示欄、OK・キャンセル。ID/DLC の入力変更のたびにビット長を再計算して表示（範囲外なら「-」）。OK で検査し、NG なら項目名と理由を並べたメッセージを表示し、最初の NG 項目にフォーカスを移して閉じない。
- メニュー: 「編集(E)」に「データフレーム編集(&F)...」（`ID_EDIT_FRAMES`）を「セッティング」の下に追加。実行中は無効。
- ECU 数 0 のときは、ノードを選べないので一覧は空・ボタンは無効（開くことはできる）。

## 決定7: 既存検証の扱い
- 004 SC-009（004 以前の基準 CSV との一致）は、データ 0xFF と起点の変更で成り立たなくなる。基準の比較はchecks.exe の任意引数なので、README と CLAUDE.md に「006 以降は基準が変わった」と明記する。ON/OFF・スピード間のCSV 一致（004 SC-006、005 SC-005）は引き続き検証する。
- 001・002 の期待値（例: 0x080 の最初の Tx_Start = 162 µs、起動待ち中の上書き 5 回）は新しい値に更新する。値は手計算か、新しい実装の出力を確認したうえで設定し、変更理由をコメントに残す。

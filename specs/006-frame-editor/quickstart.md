# Quickstart: 006 の検証

## 1. コアの検証（自動）
CLAUDE.md の手順で `checks.exe` をビルド・実行する。追加・更新項目:
- `ValidateFrame`: 正常値、ID 0x800・`xyz`、DLC 9、他ノードとの ID 重複（範囲外 ECU を含む）と編集中の自身は除外、周期 0、オフセット = 周期、名前 33 文字、101 件目の追加
- `AddFrame` / `ReplaceFrame` / `DeleteFrame` と通し番号（添字）の振り直し、定義のない ECU への追加でノードが作られる
- 読込み: `Data` が 00 でも 0xFF になる、`Name` の読込み、101 フレームのノードを拒否、オフセット ≥ 周期を拒否
- 保存→再読込み: 名前・ID・DLC・周期・オフセット・順序が一致し、`Data=` 行が出力されない
- 送信要求の起点: 電源投入 50 ms のノードでオフセット 0 のフレームの最初の Tx_Request = 通常動作開始時刻、オフセット 5 ms なら + 5 ms
- 001・002・004・005 の既存項目が、更新した期待値で PASS

## 2. GUI の確認（Debug|x64、サンプルは一時フォルダにコピー）
1. 編集メニューに「データフレーム編集」があり、実行中はグレー。
2. `sample_appendix_a` を読み込み、編集ウィンドウで ECU1 → 2 行（0x100 / 0x101、10 / 100 ms）、列の並びが仕様どおり。
3. ECU の選択を変えると一覧が切り替わる。フレームのない ECU では「編集」「削除」が無効。
4. 追加: 入力画面にビット長・伝送時間が出る。NG 入力（ID 重複など）で理由が出て閉じない。正しい値で登録され No. が振られる。
5. 編集・削除（確認あり）と No. の振り直し。
6. 保存→再起動→読込みで一覧が同じ。開始して追加したフレームがログに出る（SC-005）。
